# 界面组件与开发预览

DooKnow 的页面使用 Ant Design Vue 4.2.6 与现有编辑器组件。保留目录侧栏加编辑区的两栏结构；普通笔记通过 NoteEditorHost 连接文档编辑与 CodeMirror 源码编辑，大文件片段继续使用 CodeMirror。原有 Naive UI 模态框保留焦点管理与关闭行为。

## 统一组件与主题

- `apps/web/main.ts` 调用 `installAntDesign` 全局注册常用 Ant 组件，新页面可直接使用 `a-button`、`a-input`、`a-alert` 等。页面也可显式导入组件，避免扩大公共注册集合。
- `apps/web/ant-design.ts` 集中维护主题：品牌色 `#4566c6`、中文字体、6px 圆角、36px 常规控件高度。
- `App.vue` 的 Ant ConfigProvider 为所有页面与弹层提供中文 locale、主题，并关闭中文双字按钮自动插入空格。现有 Naive 组件使用相同品牌色。
- 不导入全局 `reset.css`，防止覆盖 Markdown 正文、原生目录表格与编辑器的排版。跨页面的适配样式放在 `apps/web/ant-design.css`，页面专属样式留在组件内。
- Ant 与 Naive 按钮属性不同：使用 `html-type="submit"`、`danger`、`type="text"`；不要直接复制 Naive 的 `attr-type`、`type="error"`、`quaternary`。
- 输入框的 `v-model:value` 与显式 `@update:value` 不要重复绑定同一事件。需要额外状态更新时，使用 `:value` 与一个更新处理函数。

## 交互约定

搜索区分别呈现请求中、等待索引、失败可重试与最终无结果；搜索忙态不占用笔记保存状态。异步结果需核对查询代次与当前笔记，避免覆盖后来的操作。

新建、分享和恢复使用独立提交状态，忙碌期间防止重复操作；失败提示呈现在所属弹窗中，保留用户输入和草稿。分享阅读区分明确失效与暂时读取失败，读取下一片段失败时保留当前内容和游标。

账户菜单默认折叠，搜索与新建同行；内容搜索状态固定在右下角，详情支持点击外部或 Esc 收起。适配弹层时检查手机抽屉、模态框层级以及短窗口内的滚动。

## 开发与检查

正常源码开发使用 `npm run dev`；服务器的知识库、数据目录和端口应通过项目原有配置指定。不要让开发修改作用于正在运行的正式数据。

本次界面验收另外启动了隔离的源码预览：Web `127.0.0.1:4410`，API `127.0.0.1:4411`；首次配置预览 Web `4412`、API `4413`。这些是本次本机临时预览，不是默认部署端口或常驻服务。启动脚本、合成资料配置和截图脚本位于忽略的 `.local/antdv-refinement/` 与 `.local/antdv-*-server.ts`；预览凭据不进入仓库。

基础检查：`npm run typecheck`、`npm run build`。浏览器覆盖目录/编辑/冲突/分享/恢复、插件、授权、大文件、首次配置及移动小窗口。新增反馈用例在 `tests/e2e/ui-feedback.spec.ts` 与 `tests/e2e/reader-feedback.spec.ts`。

## 文档编辑开发预览

`VITE_DOCUMENT_EDITOR_ENABLED` 只在值为 `1` 时开启；正式构建由 `apps/web/.env.production` 启用，开发模式缺省关闭。显式设置环境变量为 `0` 可构建关闭功能的回退版本。开发时可在忽略的 `apps/web/.env.development.local` 中设置为 `1`，然后使用现有开发启动方式。此文件不影响 production 模式构建；不要把开发预览开关当作生产发布授权。

开启后，普通笔记顶部提供“文档编辑 / Markdown 源码 / 阅读”。源码可开启“同时预览”；新用户默认文档编辑，已有浏览器偏好继续保留。文档模式支持基础排版、列表/任务、表格、图片附件和有限颜色/对齐；未知语法显示原文保留块，跨段引用或超限内容回退到源码。文档编辑与源码共用 Markdown 草稿、保存和撤销；切换本身不写入服务器。

引擎按需加载，阅读入口不加载文档编辑器。原文保全实现位于 `apps/web/editor/`，界面位于 `DocumentEditor.vue`、`NoteEditorHost.vue` 和 `DocumentTableTools.vue`；Workspace 仍是保存、冲突及导航的权威入口。附件显示使用授权地址，保存仍使用相对 Markdown 路径。

异常组合输入不能安全转换时保持当前输入和未保存状态，提供恢复副本下载；恢复副本包含原 Markdown、当前编辑器模型及保留块，供异常恢复使用，不是新的存储格式。不能在这种情况下把“已保存”显示给用户。

隔离浏览器用例使用独立临时知识库、账号和 4179/4180 端口，双模式套件需显式开启开关；原有源码回归需显式关闭。真实中文输入法、性能和资源证据见[验收记录](验收记录/2026-10-20-document-editor.md)。正式服务保持独立，启用和回退只切换前端开关及构建，不批量改写笔记。

### 保持 Markdown 的约束

- 普通编辑已支持粗体、斜体、删除线、行内代码、列表与任务、引用、分隔线、基础表格、链接、常见位图、撤销重做和模式切换；不重复列为未实现。

## 2026-10-23 普通 Markdown 阅读器兼容性（用户明确要求）

此约束覆盖前述控件选型、SVG 预览及编辑器增强：笔记离开 DooKnow 后，普通 Markdown 阅读器仍应能阅读正文、代码及图形。不能将“本应用能渲染”视为跨阅读器兼容；以下是待落实的设计及验收规则，不代表当前扩展已经完成兼容改造。

### 存储与表现分离

- 通用正文语法以 [CommonMark](https://spec.commonmark.org/0.31.2/) 为基础；表格、任务列表、删除线按常见 [GFM 扩展](https://github.github.com/gfm/) 处理，明确它们不是所有基础阅读器都提供的能力。
- CodeMirror 6 只增强编辑体验，代码继续存为普通围栏代码块和语言标记；行号、折叠、复制按钮、编辑器主题等不写成正文的私有组件结构。
- 原始 `.md` 和相对路径附件可独立携带，通用阅读不依赖登录态、`/api/` 地址、笔记 UUID 查询或 DooKnow 前端脚本；需要认证的站内显示地址只在运行时解析。
- 新增图形功能必须同时设计普通阅读器的可读表现，不能仅依靠事后导出；已有文档不因此批量改写，迁移或兼容导出需要显式操作。

### 兼容规则

| 内容 | 普通阅读器应有的表现 | DooKnow 可附加的能力 |
| --- | --- | --- |
| 常规代码块 | 显示完整源码；高亮主题可以不同 | CodeMirror 编辑、复制、行号、折叠 |
| SVG 附件 / SVG 源码块 | 标准图片相对路径引用；对不显示 SVG 的目标提供 PNG 预览图，并保留 SVG 原文件链接或围栏源码 | 代码与图形切换、矢量查看 |
| Mermaid | 保留标准 `mermaid` 围栏源码；为不带 Mermaid 插件的阅读器提供标准图片引用。图形渲染是阅读器扩展能力，不能承诺仅靠围栏在所有阅读器显示为图 | 在线预览、主题切换、转白板 |
| Excalidraw 白板引用 | 提供 PNG/SVG 预览图的标准 Markdown 引用及相对路径 `.excalidraw` 源文件链接，避免只有应用内部白板 ID | 完整设计页、编辑与预览刷新 |
| 数学公式、脚注、提示块等扩展 | 采用常见写法并保留可读源文；图形必须可见时提供图片或文字回退；不能把不同阅读器的插件能力当作共同基线 | 专用编辑、渲染和跳转 |
| 图片大小、表格列宽及颜色对齐 | 正文内容和基础表格在忽略样式时仍可读；不默认新增私有尺寸/布局语法。显示偏好优先留在应用设置，确需随文保存时另行评估兼容表达 | 站内布局与主题增强 |

SVG 围栏在普通阅读器中通常只是代码块，这属于源码可读，不能等同于图形可见。因此 SVG 的兼容方案需要预览图引用。对要求最广阅读器覆盖的文档，优先 PNG 作为可视回退；原始 SVG 和设计源仍单独保留。GitHub 的 Mermaid 支持属于其额外渲染功能，见[官方图表文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)。

### 后续验收要求

1. 使用独立 CommonMark 渲染器检查基础正文，再用 GFM 渲染器检查表格、任务与删除线；另以 VS Code Markdown 预览、GitHub 和一种常用本地 Markdown 阅读器作实际抽查，并记录扩展及设置。
2. 将 `.md` 与附件复制到独立目录，在不运行 DooKnow、没有登录态的条件下打开；正文和回退图片不能依赖站内接口，附件路径在移动、重命名及导出后仍应有效。
3. 检查代码原文、语言标记、链接与图形预览；不要求所有阅读器的字体、配色和像素布局一致，但不能丢失必要内容。
4. 外部修改后重新导入或打开，验证未操作的正文与扩展源码未被静默改写；生成的预览图应与对应源版本一致，生成失败时保留源文并明确提示。
5. 在实现和上述验证前，不宣称已经完整支持所有普通 Markdown 阅读器。
