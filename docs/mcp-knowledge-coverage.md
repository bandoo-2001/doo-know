# Knowledge business capability coverage

Inventory: `apps/server/app.ts`, `apps/server/knowledge/web-routes.ts`, and the business import/export branches of `apps/server/platform/transfers.ts`. The tools reuse the live host principal and ordinary knowledge services. They do not invoke browser recovery wrappers with `webPrincipal`.

Permissions below abbreviate `knowledge:read/write/organize/archive/share/manage/index` as R/W/O/A/S/M/I. M and S are independent, default-off actions. “All” means the live knowledge grant covers the entire library; a path or selected note grant is insufficient. Operation receipts, transfer sessions and bulk jobs are isolated by principal and client. Public link consumers remain constrained by the existing public share permission; MCP management never uses a public token to bypass its own grant.

## Verification references

`tests/mcp-knowledge-full.test.ts` exercises real temporary libraries/databases and the real transfer store:

- K1: “reads a note-bound revision…” — version metadata, snapshot reads, cross-note denial, file-job restore, stale CAS and replay.
- K2: “restores only the selected archived identity…” — inactive identity recovery, path reuse collision and renamed restore without granting the replacement note.
- K3: “isolates shares…” — S isolation, token and source CAS, status/create/rotate/revoke, receipt replay and operation recovery.
- K4: “pages backlinks and favorites…” — reference matching, scoped collection totals/pages, stable favorite receipts and live narrowing.
- K5: “archives and restores whole folders…” — subtree version, whole-directory archive/restore, folder trash and caller-owned receipts.
- K6: “requires full library maintenance rights…” — all-library M requirement, settings CAS/replay, actual conflicted write resolution with preserved evidence and caller receipt.
- K7: “imports bounded source documents…” — opaque document upload/finalization/replay and a source download exceeding 2 MiB, without host paths.
- K8: “binds attachment and diagram uploads…” — attachment upload, independent asset association, no sibling asset reads/registration, and whiteboard target authorization.
- K9: “prepares a replayable diagram group…” — real PNG/SVG pair, hashes, stable group receipt, selected-note access to its prepared source and stale source rejection.
- K10: “rechecks resource revocation…” — grant narrowing during an awaited source lookup cannot disclose a share.
- K11: “previews collision-safe bulk imports…” — full source batch preview/hash, rename collision behavior, reference-preserving attachment import, paged receipts and TAR.GZ export.
- K12: “cancels bulk imports…” — cancellation between committed items and continuation without duplicated notes.
- K13: “includes a whiteboard referenced by a large note…” — source snapshots exceeding the ordinary editor limit retain whiteboard dependencies outside the selected export folder.
- K14: “recovers a selected inactive directory…” — selected directory identity remains recoverable after its path is reused; recovery never authorizes the replacement subtree.

`tests/mcp-knowledge-sdk.test.ts` (SDK) traverses every public catalog page with the real MCP SDK, checks complete-frame limits, discovers all knowledge tool input/output schemas, and calls history, favorite/collection, sharing/recovery and managed attachment upload through the real host/grant boundary.

`tests/mcp-knowledge-review-r1.test.ts` adds thirteen independent-review regressions: actual live source CAS for shares/assets/diagrams across an awaited lookup; all-library conflict authorization across Git lookup; atomic, purpose-bound upload finalization and expiry-safe asset/document receipts; a 73,362,296-byte source export that preserves an ordinary reader snapshot without increasing the 64-MiB snapshot quota; composed long-path completion/recovery and preflight rejection; in-flight collection scope invalidation; complete-frame sizing for quote-heavy collection/trash/bundle preview/job pages; public edit delegation requiring W even when edit permission is preserved implicitly; safe failed-export restart; and ancestor validation before staging writes. These strengthen the corresponding source-CAS, sharing, transfer, maintenance, collection, export-limit, path and frame-budget claims below.

`tests/mcp-knowledge-snapshot-r2.test.ts` adds three same-note 12-MiB concurrent-reader regressions. Export preparation and ready caches have a durable private job namespace; ordinary read/outline/file-job consumers cannot adopt them or their pending preparation. Another actual SQLite connection can release the export cache while an ordinary range read continues safely, including after host cancellation. Normal quotas and active-reader cache behavior retain their existing snapshot regression coverage.

Existing tools retain their existing regression suites: `mcp-agent-workflows.test.ts`, `mcp-agent-protocol.test.ts`, `mcp-organization-integration.test.ts`, `knowledge/move-conflicts.test.ts`, `folders.test.ts`, `restore-folder-trash.test.ts`, `note-collections.test.ts`, `diagram-artifacts.test.ts` and collection service tests. The common transfer store and public chunk tools have their separate transfer/SDK regressions.

Browser-created host transfer jobs and backups are not reattributed to an MCP client. MCP exposes the complete business import/export workflow through its own caller-bound jobs. Host encrypted backups, key export/password checks, platform restore/activation, accounts and deployment APIs remain outside the knowledge business domain. Git/manual or unsupported multi-file conflict resolution was already non-automatic in the source service; the MCP conflict list returns the concrete existing reason and the keep-disk tool handles only eligible file conflicts.
