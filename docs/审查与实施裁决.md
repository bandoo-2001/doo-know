## 全部裁决及代价

以下保留执行 ledger 的全部裁决，包括审查者明确未判断的行为；不是额外生产操作授权。

- Ruling: 已有书面设计和计划按用户明确指令直接执行，不重新申请设计确认；在指定源码目录的干净功能分支实现，不新增 worktree。代价：开发目录会包含本次改动，生产不从开发目录发布。
- Ruling: 中文阶段计划不使用技能脚本的 Task N 标题格式，按原阶段维护手工 ledger 与验证日志，避免更改用户计划结构。代价：阶段命令由执行者核对。
- Ruling: 用户后续授权定期推送，独立 MCP 关联 git@github.com:bandoo-2001/doo-know-bridge.git 并在验证节点提交推送；只提交本任务源码和文档。代价：通过验证的代码进入远程仓库。
- Ruling: 小文件 patch 同样返回后台 operationId，使提交/超时/取消路径一致并保持响应有界；FileReply 契约兼容。代价：小 patch 成功需多一次状态查询。
- Ruling: 阶段八允许稳定机器契约上的提前模拟开发；先交付网关有界 HTTP 客户端、身份签名与契约测试，以便在用户指定 MCP 仓库形成实际可推送阶段代码，完整检索/MCP/OAuth 验收在阶段七之后完成。代价：首个网关 checkpoint 不包含全部工具。
