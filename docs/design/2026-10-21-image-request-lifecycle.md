# 图片请求取消与连接保留设计

本项用于继续用户已授权的全平台故障修复。原文、编辑模型、账户隔离、保存协议和附件访问规则保持；修复图片阻塞导航及正文/保存请求，不以固定延迟掩盖连接问题。正式35暂不修改，新代码须重新验收后使用新版本。

真实HTTP对比已确认：当前实现清空src后立即恢复，响应头尚未返回时仍等待约3秒；不恢复或延迟恢复虽变快，却不能据此保证取消离开和所有网络时序。独立fetch/AbortController原型可在约12ms导航，取消离开后六图显示正常且来源不变。

采用由显示视图拥有的同源附件请求。富文本节点通过当前来源回调加载；Markdown预览、大文件预览和分享页在现有受信任映射处生成延后加载属性，不能先给原生img设置src再补救。保持现有不支持的外部图片行为，普通链接不改。

每个文档最多同时下载三个不同图片资源，为正文、身份检查和保存保留连接。相同URL只合并同时进行的请求，不引入持久或完成后的跨视图缓存。请求保持同源凭据、禁止跳转、无额外缓存，严格接受已有PNG/JPEG/GIF/WebP类型；服务器仍负责账户和分享访问控制。

下载完成后用临时对象URL显示；对象URL不能进入Markdown或模型。节点更新读取当前来源，忽略加载引起的DOM属性变化但保留选区处理。来源变更、节点销毁、区域或祖先移除时取消请求、释放队列位置及对象URL；同步移动保留。异步回调必须确认当前对象和来源，防止旧图片复活。

离开页面只中止图片请求；取消离开时重新读取当前来源并恢复尚未完成的图片，完整图片不重下。不得停止所有窗口请求，以免影响在途保存。HTTP失败保持替代文字与模型，不自动修改或提交原文。

验证包括真实响应头/正文挂起、导航与控制请求响应、取消离开时草稿/模型/光标/原文、并发与同时请求合并、完成图片不重载、错误类型/访问拒绝、来源变更和清理、HTML三种入口、复制及真实授权附件显示。继续运行CSRF与保存恢复检查；完整项目、生产构建、实际安装及公网检查通过后才能发布。有限Chromium检查不冒充物理Safari或所有条件证明。

执行顺序：已有RED → 请求生命周期和受信任渲染集成 → 关联与实际入口检查 → 新增独立循环并验证 → 新增量复核 → 完整源码及制品门禁 → 新版本实际部署与原文核对。已授权审计的必要内部修复继续执行，不重复要求用户确认既有任务。
