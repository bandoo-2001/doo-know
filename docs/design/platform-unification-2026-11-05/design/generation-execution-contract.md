# 全量图稿执行合同

本轮唯一目标为非 ToDoo 全平台 UI 统一，全部设计及逐图/全局审查通过后才进入产品实现。已合并 ToDoo 是风格基准，不是本轮完成条件。

## 功能权威与当前状态

1. 当前实际组件模板、API/权限和覆盖清单决定功能；实际基线截图决定所选运行状态的可见内容。图稿计划中的笼统例子有歧义时，按这两项裁定并写入 sidecar，不能添加功能。
2. `style-contract.md` 及已通过的 `images/PILOT-WS-001.png` 决定配色、密度和共享层级。不要把 ToDoo 的 logo、任务菜单或数据移入其他模块。应用首页中本来存在的 To Doo 卡片必须保留。
3. 同一图只画已声明的连贯状态。不要把全部 `importantStates` 或所有条件字段同时塞入一个页面。状态矩阵按其明确行/分区展示互斥变体，完整逐项映射仍保存在计划和元数据中。
   同一个父`.vue`文件不等于同一个视觉模式。变体若新增字段、按钮、链接、排序/折叠toggle、任务kind/state、progress、取消/重试/预览继续/补资料/下载等结构，须有真实独立可读片段或精确现成等价图引用，不能拿空态、普通错误或loading再配metadata冒充。互斥分开不等于省略独特分支。纯message/value及相同实际控件槽位的label/guard变体才可按逐项绑定共享；7行装不下须向Root提出拆分，不设任意资产数上限。
4. 完整主页面显示自己的真实宿主；局部窗口/浮层/状态图可以只画实际组件，通过 parent/role 绑定回主页面，避免反复重画宿主。公开/认证/打印不能借用私有导航。图外 ID 说明可放在 sidecar。
5. 当前原始截图可能有布局缺陷；保留实际功能，修正图稿布局。尤其画布手机侧栏不能照抄到屏外，主要动作及关闭按钮必须可达。
6. 密集表单独立完整图；同图大型独立分区最多3个，紧凑状态矩阵最多7行。手机按计划展示320/390的真实字段顺序与滚动/页脚关系，不用设备外壳装饰，也不能删字段来缩图。
7. PB-060 当前是服务器状态/错误响应，没有应用自有 HTML 页面；其4项状态仅作非视觉契约映射，不生造访客错误页。PB-016仅现有SetupWizard条件提示，不声称普通公开入口可达，也无浏览器账号创建表单。

## 工具与输出

- 读取 imagegen 技能，使用已通过官方核验的内置 `tools.image_gen__imagegen`（GPT-Image2）；无需 CLI/API Key，不替换模型。该工具不暴露每次型号身份回执，如实记录官方工具合同依据。
- 先用 `view_image` 查看每张实际输入，明确内容/样式/编辑目标职责。真正编辑既有图时先查看目标，保存新的 `-vN`，不覆盖历史文件。
- 生成时提交简洁、具体的选定状态与控件要求；完整实际提交的提示词必须存档。实际绘图prompt尽量只描述要画出的真实UI、精确可见label/value、控件禁用/选中和布局。source-ID、role、parent、source-derived、dirty等审查元信息只存sidecar，避免烧入产品界面。完整原始计划及字段/动作/角色/约束映射另外保留，生成者仍须先读源码核对，不能因prompt简化漏功能，也不能把接口协议字段画成输入框。
- 一项设计资产一个内置调用；编辑修订另记一次。可并行独立调用；所有 Promise 必须 await。初次 exec 使用120000ms yield提示，适时yield；不要输出结果base64/完整对象。用子线程内 `generatedImage(result)` 接收原图，复制工具默认 `$CODEX_HOME/generated_images/...` 原始PNG到项目目标路径，禁止用Python改像素。
- 输出 `design/images/ASSET.png` 及同名JSON。sidecar必须含：assetId、完整actual submittedPrompt、全部inputs及职责、sourceIds/panels/roles/selected state、原始计划引用、source commit933、实际工具与官方型号依据及回执限制、默认输出路径、生成时间、PNG SHA256/字节数/实际宽高、修订关联、self-inspection concerns、`pending-independent-review`。不要将意图尺寸写成实际尺寸。
- 生成图只在子线程查看，根线程只收文件名/计数/阻断项，不内嵌大批图片。用户图集按需展开原图。
- 每个资产都需独立审查实际PNG及当前模板；功能/角色/状态偏移必须重生成。仅栅格轻微纹理或近似像素宽度按已明确CSS合同实现，不能无限迭代，也不能据此声称像素精确。

## 协作与恢复

- 所有产品源文件、真实账号/资料、服务和其他工作树保持。当前阶段只写图稿/文档/忽略的辅助脚本与进度，不修改产品UI。
- 每个批次有明确独占ID清单，先检查目标PNG/JSON防止重复生成；不得领取其他代理已占有的ID。进度写 `.superpowers/sdd/2026-11-05-platform-ui-unification/`。
- 每批结束将完成文件/自检报告交根代理，由根代理集中运行共享索引构建以核对真实文件数、散列和审查状态。生成/审查子代理不写共享catalog/index/queue，避免并发覆盖。旧失败、历史图和未验证项保留，不能把它们改写成成功。
- 设计计划、图稿生成、逐图审查及全局设计审查是不同门槛；生成数量/覆盖映射通过均不自动放行产品开发。
