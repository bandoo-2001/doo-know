## Important

1. **大脑图可能以不可读比例打开，根节点还会被移出画布。** `apps/web/diagrams/mindmap.ts:73–81` 对任意一个出界 topic 都按整棵树缩放，再将整树外接矩形的中心移至视口中央。MindElixir 此版本默认 scaleMin=0.2；默认正文若为 16px，0.2 倍即约 3.2px。对于从根向同一侧增长、0.2 倍后仍比画布宽的深链，居中整棵树会把位于一端的根移出视口。原库初始化时按根居中，可读的初始位置会被这段新代码覆盖。原生缩放限制本身正确，问题在于初始相机选择。既有 500 节点浏览器用例检查只读 PNG，与这种实时首次挂载不同。
   - 最小可检验输入无需 500 节点。例如在 `tests/fixtures/mindmap-adapter/harness.ts` 用真实 parseMindmapOutline + mountMindmap 可编辑入口加载根标题和 24 级单侧子链，每级两空格缩进、各带足够长的不同普通标题使外接矩形大于 320px 的五倍。该输入位于 64 级/500 节点支持范围。等待字体和首次 fit，在 320px 上测量根节点实际可见、根与可见相邻标签的有效字号不低于现有 12px 门槛，再平移查看深层并验证视图未被拉回。两节点长名原例仍应同时完整可读。整树按比例无法达到可读初始视图时，应以根和附近节点为锚点，保留用户平移到其余节点的能力，不强求所有节点入屏。

2. **未完成创建的“取消”可能提交外层新建表单，并与同一创建意图的恢复并发。** `apps/web/components/Workspace.vue:3717–3722` 的两个原生按钮位于 3669 行的表单内，均缺少 type=button。以已有待恢复图形打开新建笔记，在有效目录填写新文件名后点击“取消未完成图形”，按钮会先进入 1630 行的取消处理器，继而触发表单默认提交；submitCreate 于 1654–1683 行可真实创建另一篇普通笔记。恢复处理器会同步设置 createBusy，取消处理器既不检查也不占用该锁。用户还可在恢复请求未完成时取消，或在取消未完成时重新恢复/创建。取消会 DELETE 该 intent 并清除本地 draft（`apps/web/diagrams/primary-creation.ts:45–59`）。这些行为从旧模板继承，此次新样式让这组决策成为视觉主操作。
   - 仅外层“创建”应提交表单。给两项恢复决策显式设置 type=button，使用现有 busy 机制互斥恢复、取消和创建，失败时释放。真实回归可让一次实际图形准备失败形成 pending，打开普通笔记创建表单、输入有效名称，点击取消，验证对应 intent 被取消，但没有 POST /api/notes、没有新笔记且输入仍在。暂停取消或恢复响应时检查对立动作不能开始；恢复仍完成原 intent 一次。

## 通过的范围

- 独立字节比较：Workspace、DraftRecovery、DiagramSaveDialog 的 script 前缀全部与基线一致；从 readMindmapTree 到 PNG 文件末尾、从 sceneSvg 到 canvas 导出文件末尾的两个后缀均完全相同。WS063 只给原决策行加共享类。WS054 的 Ant primary/danger 为显示属性，恢复/舍弃条件照旧。opaque 删除的专属选择器有足够优先级覆盖一般按钮色，复制、编辑和用户正文颜色没有被选中。补丁没有新增角色、权限、接口或画布数据颜色覆盖。
- 白板只在实际画布宿主内寻找当前固定 zh-CN 的背景输入和最近的 Radix wrapper。位置使用独立 translate，实际 input 与焦点保留；停止时取消 RAF、断开 mutation/resize observer、移除 resize/scroll 监听，再卸载 React 根。嵌入式全屏的层级不受普通底栏边界约束。
- 脑图 wrapping 仅限 live class，导出另建的只读宿主不选中。字体就绪后只安排一次双 RAF；pointerdown/wheel/keydown 捕获标记可取消尚未运行的 fit。正常销毁会取消当前 RAF，阻止字体 promise 在销毁后安排布局，并移除监听与类。缩放和平移调用库自己的 API，不提交树数据。现有新测试实际验证了 fit 后的用户平移不被重置；“在字体就绪之前先交互”这一时序本次仅作源码核查。
