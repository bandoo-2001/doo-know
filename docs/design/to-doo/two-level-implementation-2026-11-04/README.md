## 实现范围

覆盖确认稿全部 28 场景：16 个主页面、11 个操作窗口、1 个附加筛选空状态。桌面使用 64px 模块窄栏和 208px 上下文侧栏；任务保留我的待办、目标、我的清单分组。其他模块分别提供日历视图、专注项目/历史、习惯今天/历史、纪念日状态、复盘锚点、通知状态及四类设置入口。

二级入口使用经过模块校验的 `appPage` 路由，刷新、前进/后退可恢复选中状态。日历切换保留日期、视图和所选清单。任务/看板只保留列表与看板的表现方式切换，四象限、时间线使用各自模块入口。手机使用上下文抽屉和已有底部模块导航。

共享布局统一内容宽度、对齐、卡片、工具栏和窗口滚动/底部操作；详情按需显示。任务空状态区分全库、当前范围及附加筛选。通知搜索、日期和状态组合使用真实分页查询；设置中的归档、回收站入口连接已有任务范围。标签、清单及专注项目可编辑契约已有的颜色。复盘窗口显示真实统计快照预览，保存仍由服务端按所选区间捕获。

保留并验证任务草稿、父子完成确认、筛选与分页、时区/跨日、专注历史同步、习惯逐条更正、导入丢响应重试及通知状态。图中的日期、任务和计数来自隔离夹具，不写入产品代码。导入实体数由真实解析结果决定，不能将 CSV 行数直接当成实体数。

开始前已有的 ToDoo 卡片、提示和专注底栏改动被复制到独立工作树后复用并一起验证；原目录的未提交工作没有覆盖或回滚。历史验收截图保持原样，本次回归补充图存入 `regression-screenshots/`，相关测试的输出位置也已调整。

### 失败与重跑

- 开发中的新回归先观察失败再实现。初次相关单元批次为 671 通过 / 5 失败，包含新增断言使用错误的草稿返回结构和组件测试未加载新增导航依赖；修正后完整 52 文件批次 682 通过。
- 首次混合桌面/手机的 118 项端到端命令为 71 通过 / 10 失败 / 37 未运行（达到失败上限）。旧选择器、同一夹具中的固定标题事件重复，以及统计初始滚动问题分别被处理；最终两种设备各自使用新夹具运行，均为 60/60。后者不是把原命令改写成零失败。
- 最初一次截图在并行编辑尚未完成时因样式文件尚未写入而中止，不作为交付证据。后续旧窗口名称/按钮定位也已校准。
- 第一轮 84 图命令为 81 通过 / 3 失败：导入场景把 23 行 CSV 错当成 23 个实体，真实结果为 49 个实体。改为读取真实结果。人工复核另发现习惯记录背景入口、复盘快照、标签颜色和管理按钮对比度问题，均完成修正，并在新源码冻结后重新生成全套最终图。
- 后续 `1339c06` 的截图命令虽然 84/84，但人工复核拒绝了导入页的深滚动截图。实际追踪发现工作区被宿主 flex 压至 776px，而内容滚动高度为 2008px，顶栏因此越过固定范围；修正容器高度及预览列表滚动后，又用专注底栏回归发现短页留白问题，最终通过 `align-content: stretch` 同时保留短页填满和长页增长。最后 12 项真实浏览器集中回归通过，交付截图再次从 `f44d608` 全量生成。
- 对比度回归先实际测得 2.65:1，修正后浅/深色均通过正常字号文本至少 4.5:1 的浏览器检查。

本次验证范围为 ToDoo 及工作区导航，没有重跑与本次 UI 变更无关的全仓库测试。构建中的既有模块指令和静态/动态导入警告不代表测试失败，也没有从日志中删去。
