# ToDoo 全套两级菜单版概念图

本批按已确认的“模块窄栏＋上下文侧栏”方向重新生成全部 28 张图，不沿用旧版原图作为本批最终图。旧图只作为各场景内容、示例数据、表单与状态的参考；[两级菜单参考图](./navigation-reference.png)用于统一导航比例、顶栏、色彩和层级。

图集是本地静态概念文档，未部署为产品 UI。图中的任务、清单、目标、日期、统计及连接状态均为示例，不对应真实账号。图片和表单控件不代表可操作的产品功能。28张最终选稿与3处校准均已完成，完整性检查已通过。

打开 [index.html](./index.html)，可按主页面、空状态、操作窗口筛选，搜索标题、编号、文件名、模块或二级菜单，并点击预览查看原图。无需额外库或网络服务，可直接从本地文件打开。桌面为两到三列，手机为单列；目录默认收起，展开后的导航区域最高 160px，可独立滚动。

## 共同布局原则

- **模块窄栏＋上下文侧栏**：最左侧窄栏切换任务、日历、四象限、专注、习惯、纪念日、复盘、通知和设置；相邻侧栏只呈现当前模块的分组和入口，保持两级结构。
- **对应模块选中**：每张图选中所属一级模块及当前二级菜单。任务列表、看板和新建任务归任务；日历视图和时间安排归日历；设置页和结构管理归设置。操作窗口保留所属模块的背景上下文。
- **弹性内容**：列表、看板、日历和时间线使用剩余宽度；长时间线保留横向滚动空间，避免将日期压成过窄的列。
- **按需详情**：仅在原场景含详情或相关操作时显示详情；其他场景保留完整主区域，操作窗口的表单和底部按钮保持可见。
- **区分空状态**：全库无任务、时间范围为空、附加筛选无结果分别表达。第 17 张为附加筛选无结果，保留范围和筛选上下文，提供清除筛选及查看所有任务入口。

## 提示词与重建

- [generation-plan.json](./generation-plan.json)：本批全部 28 个场景的完整提示词、原内容参考图、两级菜单参考图及应选中的菜单。
- [generation-prompts.json](./generation-prompts.json)：辅助清单，本批 `assets` 为空；全部场景以 `generation-plan.json` 为准。
- 每张已生成 PNG 旁的同名 JSON 记录对应提示词、参考图、来源和尺寸；记录出现后可从图集卡片打开。
- [build-gallery.mjs](./build-gallery.mjs)：仅使用 Node 内置模块读取清单并生成 [index.html](./index.html)，不生成、编辑或删除图片。

在仓库根目录运行：

```bash
node docs/design/to-doo/layout-redesign-two-level-2026-11-04/build-gallery.mjs
```

普通模式允许缺图并显示占位。每批图片到齐后重新运行，即可更新预览、生成记录链接与数量。全部图片生成后运行严格检查：

```bash
node docs/design/to-doo/layout-redesign-two-level-2026-11-04/build-gallery.mjs --require-complete
```

严格模式要求 01—28 每个编号恰有一个场景，且清单中 28 个 PNG 文件均存在并具有 PNG 文件头；缺图时退出并列出文件名，不写出新的图集。该检查不证明视觉或业务正确性，最终内容需逐图复核。

实际产品实现还需验证真实数据、响应式、键盘操作、表单校验、滚动与交互状态。本目录仅保存本批静态概念稿及其生成资料；运行中的产品和账号不受其影响。
