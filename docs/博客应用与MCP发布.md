# 博客应用与 MCP 发布

在侧栏打开「应用 → 博客」，从现有 Markdown 笔记中选择文章。文章标题、摘要、分类、标签、封面和置顶信息由博客单独管理；编辑原稿仍使用现有笔记编辑器。

## 发布与更新

1. 选择笔记，填写文章信息并保存。
2. 预览内容，点击「发布文章」。默认博客站点关闭，可先准备文章。
3. 在「站点设置」开启博客，配置站点信息。公开入口为 `/blog`，文章地址首次发布后固定。
4. 修改笔记后，公开页面保留上次发布的内容。检查新预览，手动点击「发布更新」才会替换公开版本。

如果发布前发现原稿或文章信息已被其他操作修改，工作台会要求先复核新内容。保存文章信息与发布为两个独立操作，修改信息同样不会自动改变线上版本。

「下架文章」停止公开访问；「移除选稿」移除博客关联并保留原笔记。源笔记删除或进入回收站时文章会下架，恢复原笔记后需要重新发布。关闭站点将停止全部公开页面访问。

## 装修自己的主页

打开「应用 → 博客 → 装修主页」。选择文字博客、卡片杂志或个人主页，再设置主题色、字体、内容宽度、卡片样式、姓名、个人介绍、头像和主页横幅。头像和横幅支持本地选择、裁切与上传，保存为独立图片副本；每张上传图片最多 5 MiB，支持 PNG、JPEG 和 WebP。

「首页模块」提供个人介绍、精选文章、最近更新、专题合集、项目和友情链接，可添加、上移下移、隐藏、删除、修改标题及显示数量。精选文章来自已置顶的公开文章；最近更新按发布版本的更新时间排列。「导航与链接」管理站点导航、社交链接和友情链接；「项目作品」添加作品名称、介绍与访问地址。

「专题合集」可以给一组已发布文章设置名称、路径、介绍和阅读顺序。专题公开页与文章页会给出阅读路线，撤下的文章即时退出公开列表；草稿及知识库其他资料不会因为加入模块而公开。

右侧使用公开站同一个渲染器预览当前草稿，可切换电脑与手机宽度。未保存的编辑也能预览。「保存装修草稿」只保存配置；「发布主页」才替换访客看到的外观。历史保留最近十次发布，可恢复到草稿，核对后重新发布。关闭博客时仍可用主人账号预览装修及已发布快照图片。

## 阅读与发布前核对

完整文章列表位于 `/blog/-/articles`，支持标题、摘要、分类和标签搜索、筛选及分页；专题入口为 `/blog/-/collections`。旧分类、标签链接继续可用；历史上地址为 `articles` 或 `collections` 的文章保留原公开链接。

文章页提供目录、预计阅读时间、专题上下篇、相邻文章、相关文章、代码复制和链接分享。「关于」支持安全 Markdown。首次发布前可以修改文章路径；首次公开后路径固定。文章封面可以从原稿附件选择，或直接上传裁切后的图片。

打开「预览文章」可以核对线上版本与待发布正文，查看未发布内链、失效引用、缺失图片，以及可能需要重新发布的关联文章。检查结果会按当前目录和博客授权过滤。发布时仍会重新核对原稿与资源；修复原稿后需要刷新检查、手动发布更新。

## 公开内容与资源

公开站点包含首页、文章、分类与标签筛选、归档、关于、RSS 和 sitemap。正文、图片和附件使用发布时的固定副本，修改原资源不会自动更新公开版本。私有笔记链接不会递归发布目标笔记；YAML 前置信息不属于公开正文。

Mermaid、SVG 和 Excalidraw 图形使用固定图片预览。网页发布会准备所需 PNG；缺少有效图形预览时发布失败并保留现有公开版本。普通 Markdown 原稿上限 1 MiB、单行 32 KiB；每次发布最多 64 项资源，单项 10 MiB、总计 20 MiB。

博客发布与已有分享链接独立，博客公开文章为只读。分享链接原有的有效期与可编辑权限继续生效。

站点设置中的公开地址用于生成绝对链接；留空时使用实例配置的访问地址。数据库备份包含博客文章版本、装修配置与图片。公开内容继续保存在知识库 `_data/apps/blog/state.json`，装修独立保存到 `_data/apps/blog/design.json`，装修图片位于 `_data/apps/blog/design-media/`；换机时随知识库原文、应用数据及资源一起迁移。恢复副本默认关闭站点并下架文章，检查恢复结果后再显式开启、发布。

## MCP

MCP 同步提供文章管理、独立装修配置、发布与版本核对。完整接口与授权对应关系见 [博客 MCP 覆盖表](mcp-blog-coverage.md)。常用工具：

| 工具 | 用途 |
| --- | --- |
| `get_blog_status` | 查询笔记的博客关联、源版本和待发布状态 |
| `publish_blog_post` | 显式发布或更新文章 |
| `unpublish_blog_post` | 按当前文章版本下架 |
| `get_blog_design` | 按 UTF-8 字节分页读取草稿或线上装修 JSON、版本及哈希 |
| `update_blog_design` | 按当前版本保存装修草稿，可提交内联 JSON 或已上传 JSON |
| `publish_blog_design` | 明确发布已保存的装修草稿 |
| `restore_blog_design` | 将指定装修历史恢复到草稿 |
| `begin_blog_design_upload` | 创建受限的装修 JSON／图片分块上传 |
| `commit_blog_design_media` | 将已校验的图片上传提交为装修媒体 |
| `get_blog_publication_review` | 分页读取引用诊断、关联文章及正文对照哈希摘要 |

公开发布需要显式 `blog:publish` 授权，文章读取及引用资源仍需要 `knowledge:read` 与相应目录范围。装修草稿保存、媒体上传和历史恢复需要站点范围的 `blog:manage`；只授权几篇文章不能管理全站。博客发布不隐含知识库写权限，旧授权也不会自动扩权。旧版兼容配置仍受 `readOnly`、`allowPublish` 及原授权限制；提交前会再次验证授权、有效期和插件配置。

先查询状态，使用返回的源修改时间、内容哈希和文章版本发起发布，并为每次新操作设置独立 `requestId`。不确定请求结果时，使用原 `requestId` 调用 `operation_status` 或重试相同请求；更改内容必须使用新的 ID。包含图形的文章还需要与当前原稿绑定的有效 PNG 预览，缺失时返回 `BLOG_PREVIEW_REQUIRED`。

MCP 返回有界的发布收据，保留文章 ID、状态、版本、源哈希、标题和公开地址；`omittedMetadata` 明确列出未返回的摘要、分类、标签、置顶与封面字段。完整元数据仍由网页和 SDK 提供，避免发布成功后因响应过大无法查询结果。

本次同时修复 MCP 在途取消与截止处理、已成功更新的回执重放被大文件挡住，以及列表响应缩小页长后游标无法继续的问题。
