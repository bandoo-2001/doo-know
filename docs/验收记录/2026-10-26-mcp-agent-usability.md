# MCP 具体功能与 agent 易用性验收

本轮测试现有 18 项工具，并把参数、发现与恢复契约修正为 agent 可直接使用的形式。MCP 插件补丁版本 1.1.1，仍要求宿主 API ^1.1.0；未增加同义工具或自动扩权。

## 已修复

- SDK 在回调前产生纯文本参数错误：使用公共 tools/call 入口交由严格 registry 统一校验，返回有界 issues／recovery。
- 客户端发现工具后拒绝结构化业务错误：发现结果保留严格成功分支，并声明精简错误分支；正常 SDK `listTools → callTool` 无需绕开校验。
- 权限、版本及未知结果的恢复信息丢失：只保留白名单 requiredScope／currentModifiedAt 和安全字段问题，未知写入保留原 ID，笔记冲突先读新正文合并；博客冲突先查 get_blog_status 复核发布状态和意图。
- OpenAPI 将 maxBytes／limit／mode／freshness 默认字段误列为必填：改为输入模式转换，与实际调用一致。
- 缺少统一使用说明：initialize 返回流程指南，关键输入字段说明 ID 来源、分页、快照、UTF-8 范围、异步任务和公开发布权限。
- 有效 Markdown 从 H2／H4 开始时产生空标题祖先：修正新切片并兼容旧索引的 null 占位，不重建索引；其他错误类型继续严格拒绝。

错误不会透传正文、未知参数值、私有路径或任意后端 details。原有 CAS、固定收据、分页、预算、撤销与取消语义保留。曾怀疑不支持的 MCP task 请求可绕过新 handler，实际 SDK 探针证明它在调用前已拒绝，写入回调次数为 0，未添加多余修复。

## 功能矩阵

| 工具组 | 实际断言 |
| --- | --- |
| search／fetch／search_notes | 真实临时 FTS 返回已知资料；签名对象解析为完整正文或精确片段；旧索引无需重建可用；向量未配置如实降级 |
| list_notes／get_note_info | 分页完整无重复，元数据不含正文，目录越界拒绝，归档后列表移除 |
| get_note_outline／read_note | 50＋11 章节有序续页，显式快照准备／查询，128 字节页连续，原游标重放稳定 |
| create_note／update_note | 文件内容、版本、固定收据与同 ID 重放；后续改动不改变旧收据；冲突及缺权限被拒绝 |
| patch_note／operation_status／cancel_operation | 真实排队修改／成功、按范围修改提交前取消，取消后正文与版本不变，ID 两种查询路径有效 |
| archive_note | 版本绑定可恢复归档与收据重放，回收文件保留原文 |
| refresh_index／index_status | 范围核对返回 jobId，文本哈希匹配，pending 不解释成向量完成 |
| get_blog_status／publish_blog_post／unpublish_blog_post | 独立发布授权、私有修改不自动公开、显式更新、固定收据、版本撤下；冲突恢复可通过正常 SDK 跟随至状态工具 |

测试使用真实临时核心／宿主 SDK，经 SDK 内存传输 `Client.callTool` 执行业务；正式插件制品还实际构建、安装并通过临时 HTTP／OAuth 验证初始化、18 工具发现、结构化错误、权限、发布、重试、撤下和停用。

## 正式连接边界

当前连接 3 次有间隔只读尝试都在 SSE 探测层返回 429，错误提到 openai.org，未触达业务。缓存包装只有 app ID，没有服务器 URL，无法确认该错误来自网关还是错误端点。

SSH 只读确认 Mini 生产为 rc.49／Host API1.0.0，官方 MCP1.0.3 已安装但 disabled。当前源码为 Host API1.1.0，不能直接把新 MCP1.1.1 装到旧宿主；也不能仅凭缓存 15 工具认定当前连接指向哪个服务。旧独立 bridge 源码未改。

本轮未启用正式插件、重新授权、修改正式知识库、升级／发布程序或恢复 QA timer。所有写入、归档、发布及索引测试只在临时资料中执行。本地通过不等于外部 ChatGPT 连接可用；正式接入需要兼容宿主／插件及单独的入口与授权复测。
