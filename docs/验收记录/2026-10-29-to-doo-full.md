## 主要审阅修复

- 合法分支合并按成员版本依赖重放，不再依赖事务文件枚举顺序；保留原请求回执。
- 批量和级联先固定实例全集，再核对每个任务/实例版本，最后叶到根非扩张执行；两个客户端不会把今天的旧操作推进到未来一期。
- 完成后重复继承子树保留共同周期与父实例；取消重复后恢复普通可执行实例，保留历史。
- 任务、实例、习惯、通知及其它集合独立分页，551 实例/205 习惯的真实服务到工作台路径可完整读取。
- 未知响应重试保留原请求，新建草稿与成果恢复有实际界面入口，跨知识库不会混入旧库内存草稿。
- MCP 在所有异步资料授权之后重新复核权限和对象当前清单；受限计划联动使用可信服务上下文，不从客户端 JSON 接受权限。
- 计划同时校验候选互相重叠、现有安排、finish-to-start/延迟与完整版本基线，客户端不能清空 conflicts 绕过。
- 习惯历史按生效版本和真实周期计算；未来目标变化不会重新提醒今天已经达标的事项。
- 250 任务的真实 MCP 模板提交回执受响应预算保护，返回准确总数并可继续分页核对；已知领域冲突不再误报未知写入。
- 成果预检尚无操作记录时不返回虚构恢复 ID；已经保存的笔记可在后续版本冲突后继续同一操作。

## 继承环境与测试隔离

隔离工作区开始时没有原项目忽略的 Python 环境和模型。验证期间复用了既有项目环境；模型数据使用本地链接复用，未重新下载权重或修改模型内容，也没有为此放宽生产路径检查。

既有 backlinks 测试存在 150ms 目录监视器抢先撤下不可读候选的时序竞争。相关测试和生产实现与精确初始基线相同。本次仅在该测试夹具隔离无关 watcher 回调，保留真实 watcher、数据库、文件、软链接与原 `skipped === 4` 断言；目录生命周期另有真实测试通过。生产 watcher/backlinks 逻辑没有为通过测试而改动。

构建仍有既有 Radix 组件的 `use client` 打包提示，退出码为 0；没有将其误写成新增 To Doo 功能失败。

## 已知限制与未验证条件

- M1：损坏或实际同步冲突可能暂停整个 To Doo，尚无完整的事务闭包局部隔离界面。当前保守保全文件，不自动覆盖；笔记与博客与该故障隔离。
- Web Push 已有真实发送实现和受控协议测试，未向用户真实设备发送通知，生产 HTTPS/浏览器/网络条件下的实机接收需要部署后验证。
- MCP 协议、SDK、权限与打包插件已验证；没有使用用户真实 ChatGPT 连接进行远端授权验收。
- CSV 使用代表性脱敏合成样例和列映射验证，未取得真实用户的滴答导出；未知字段或不能表达的规则明确预览，不承诺恢复原工具没有导出的信息。
- 未实测 To Doo 的 10,000 任务/100,000 实例性能目标；几百实体的真实分页/事务测试不冒称大规模基准。事务历史暂无压缩回收。
- 本次没有创建正式部署、更新现有运行服务或自动提交/推送用户知识库。代码和配套设计保留供发布前审阅。
