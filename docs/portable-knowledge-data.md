# 知识库应用数据与迁移

知识库根目录的 `_data/` 保存需要随原文迁移的用户数据。SQLite 仍用于本机查询、索引和运行状态，但收藏、博客发布内容和插件便携用户数据可从 `_data` 还原。

```text
knowledge/
├── 00-Inbox/
├── 30-Knowledge/
└── _data/
    ├── manifest.json
    ├── library/state.json
    ├── apps/blog/
    │   ├── state.json
    │   └── assets/<sha256>
    └── plugins/<plugin-id>/state.json
```

- `library/state.json` 保存稳定笔记标识、相对路径和按用户名关联的收藏。新机器创建同名账号后恢复对应收藏；不复制账号密码或登录会话。
- `apps/blog/state.json` 保存站点设置、文章元数据、发布状态和版本快照；图片等发布资源按内容哈希独立保存。原始 Markdown 继续放在原有笔记目录。
- `plugins/<plugin-id>/state.json` 保存插件版本要求、声明为便携的配置及 `ctx.userData` 中的长期数据。插件程序、依赖、安装和启用状态留在本机。

## 首次升级与换机器

首次使用更新后的应用时，如果该数据文件尚不存在，会将现有 SQLite 中对应的长期数据写入 `_data`，原数据库保留。已有 `_data` 文件优先作为同步来的数据来源；格式错误、资源缺失或冲突会报告错误，不用旧缓存覆盖文件。

在原机器完成保存与同步，将整个知识库（包括 `_data` 和附件）拉取到新机器，再绑定知识库目录。程序会重建本机记录。Git 仓库不得忽略 `_data/`。没有必要把运行中的 `app.sqlite`、WAL 文件或本机配置加入知识库。

插件管理页显示同步数据所需的插件、版本和配置状态。缺少插件或兼容依赖时，只显示提示；拉取、读取或检查数据都不会触发下载、安装或启用。安装、配置和启用继续通过原有显式操作完成。令牌、密码、私钥、本机端口和路径不会随便携配置导入。

完整备份仍包含知识库与数据库。为保持恢复副本隔离，完整备份恢复后仍关闭博客公开访问并撤回文章；这与单纯同步知识库的迁移流程不同。

## 插件开发

- 将长期用户内容保存到 `ctx.userData`（`get/set/delete/entries` 接口）。
- 现有 `ctx.storage` 和 `ctx.dataRoot` 保留本机语义，适合临时游标、预览、缓存等；不会自动整表迁入知识库。
- 可迁移的配置字段在 JSON Schema 属性上声明 `"x-dooknow-portable": true`。`writeOnly` 秘密字段始终排除；端口、绝对路径和凭据不应声明为便携字段。
- 保留旧插件本机存储可避免将 Git 临时索引路径、操作游标和 MCP 调用观察误同步。插件若已有长期文件，需要明确的数据格式及迁移逻辑，不能依靠复制其整个运行目录。

## 同步与恢复边界

`_data` 不展示为笔记，不进入普通笔记搜索、索引或文档导出；整库 Git 同步和完整备份包含它。它不是可执行插件目录，也不会授予新机器执行代码的权限。

数据文件使用版本标记、原子替换和本机待写记录。文件被外部修改且同时存在本机未保存变化时，应用报告同步冲突。保留冲突双方及完整备份，核对所需版本后再恢复操作；不要通过删除 `_data` 来消除报错，因为该目录包含不能仅从原文重建的数据。

当前同步依赖现有 Git/文件同步流程，不提供跨机器同时编辑同一数据文件的自动合并。外部手动改名的普通 Markdown 文件没有内嵌身份，跨机器迁移前应使用应用内移动/改名并同步产生的身份映射。
