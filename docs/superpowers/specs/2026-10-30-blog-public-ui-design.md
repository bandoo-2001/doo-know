# Public blog redesign

User requests comprehensive homepage, article and mobile improvements, followed by validated production deployment. Existing direct-execution preference authorizes implementation and deployment.

Public rendering remains server-side with no new dependencies, no remote assets, and the existing self-hosted reader script. Same renderer powers management previews. Preserve journal/magazine/profile, custom accents/fonts/card styles/module order, no-JS navigation, canonical/SEO/CSP and immutable article HTML. Never change publication, persistence, site enabled state or plugins in production. Start from production rc.53, exclude unrelated dirty source changes.

Visual direction: refined warm paper and forest ink, generous yet practical rhythm, crisp dividers, clear identity and content hierarchy. Keep existing light/dark base palette for tested accessibility. Journal is an editorial stream, magazine is a visual feature/grid, profile is a personal sidebar with content. Common header/footer provide identity, useful navigation and clear focus/current state. Mobile links wrap with at least 44px touch targets, no hidden essential navigation or page overflow. Empty optional modules should remain compact and intentional; retain enabled module headings and order.

Home: stronger intro, feature and latest article hierarchy, coherent metadata, deliberate cover ratios, connected collections/projects/friends, useful all-articles CTA. Minimal decoration, no stock images or fabricated metrics. Long names/titles, missing covers and zero content must work.

Reader: breadcrumb, clear title/summary/date/category/tags/author, readable ~68ch body, cover, separated sticky desktop TOC and native collapsible mobile TOC. Keep source h1 unchanged but smaller than page title. Code/table overflow inside blocks; copy/share controls remain usable. Add progressive reading progress and active TOC via existing external reader.js; native back-to-top works without JavaScript. Honor reduced motion; JS exceptions/storage/clipboard unavailable never break reading. Short/no-heading articles and very long contents need usable layouts. Adjacent/collection/related recommendations preserve published-only semantics and custom collection order.

Validation: scoped core/render/security unit tests; candidate typecheck/build; compiled-runtime actual anonymous home/article E2E desktop/mobile across three themes, dark, long content, keyboard/TOC, clipboard, no-JS and preview. Independent code review, screenshots, immutable artifact validation, disposable production-data-copy preflight, encrypted backup restored before release; native manager update and local/public health checks. Preserve exact production source/data/profile/plugin/publication state. Site is currently disabled and must stay disabled.
