# 应用主菜单与按需二级导航

用户已确认进入应用后头像位改为返回 DooKnow，窄栏改为应用主功能，底部设置跟随应用；主菜单应可复用和注入。追加要求：参考提供的 TickTick 截图，只为有真实目录的页面保留二级侧栏，四象限和专注等应铺满；每页必须展示应用 Logo 和名称。

## 结构与取舍

采用共享展示组件 + Vue 菜单宿主 + 应用注入定义。菜单不持有业务路由或请求；应用回调负责切换，宿主负责返回与未保存保护。避免在 Workspace 按应用堆积模板，也不引入新的插件协议或依赖。

根据用户后续要求，视觉延续 DooKnow 的蓝紫配色、线性图标和勾选标识，以“知识 · 行动 · 成果”表达产品定位。借鉴主/次导航的职责划分，内容布局与状态标识使用本项目现有组件，不复制参考截图的整套视觉。

- `WorkspaceMainMenu.vue`：展示标识/返回入口、主功能和底部工具。定义提供 id、label、activeId、items、utilities、onSelect；图标和品牌可用 slot 自定义。
- `workspace-main-menu.ts`：提供/注入宿主及可释放注册；嵌套自定义可覆盖上层定义，更新上层不抢占子层，卸载子层恢复父层。无宿主时保持普通应用可用。
- `WorkspaceFooter.vue`：默认 DooKnow 菜单、账户菜单与共享组件的适配。应用活跃时头像位显示明确返回箭头，底部使用应用 utilities。
- `AppsWorkspace.vue`：To Doo/博客菜单定义注入、受保护的应用导航转发。
- `Workspace.vue`：保留原编辑器和原文，返回前确认应用草稿；按应用记住最后路由，取消返回不修改 URL；异步导航保留 intent 检查。

## To Doo 菜单

主功能：任务、日历、四象限、专注、习惯、纪念日、统计与复盘；底部为通知中心与设置。任务覆盖 tasks/board/overview，日历覆盖 calendar/timeline，四象限 matrix 是独立主功能。

有二级侧栏：tasks、board、overview（智能范围、目标、清单），calendar、timeline（真实日期/周月视图与时间线入口）。其余 matrix、focus、habits、anniversaries、stats、notifications、settings 不显示左侧二级目录，主体铺满。原专注统计等内容分栏继续属于内容区。

每页顶部显示勾选标识和 To Doo 名称；二级目录标题显示任务/日历，避免把应用名仅放在可隐藏目录里。手机使用共享应用菜单抽屉与必要的目录抽屉，320px 无横向溢出。应用独立使用时保留完整导航后备。

## 保护与验收

不修改用户真实任务、账号或正式部署，不提交已有工作。应用切换/返回保留未保存笔记编辑器；应用草稿确认取消时 UI 和 URL 不变。不同应用各自记住位置；刷新深链和前进后退仍正确。确认 To Doo 设置为 appSection=settings，博客设置为博客设置，返回后恢复 DooKnow 设置。菜单纯配置、覆盖和释放具有定向测试；桌面/手机验证主次菜单、铺满页、品牌、返回与草稿，类型检查和构建成功。
