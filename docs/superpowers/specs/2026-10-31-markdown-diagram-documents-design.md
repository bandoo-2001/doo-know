## 目标和已确定的方向

白板、脑图、流程图统一以 `.md` 为用户主文件，通过文件内标记选择 DooKnow 编辑器。普通 Markdown 浏览器无需插件、无需连接 DooKnow，即可读取正文和 PNG 预览；保留附件后可重新导入并继续编辑。兼容单位是 Markdown 加相对路径附件，不承诺单个 Markdown 文件内包含完整画布。

用户已经选择 Markdown 主文件加附件的方向，并确认导出时自动携带所有引用资源、处理相对路径，供其他工具直接阅读。单篇且无资源依赖时直接下载 `.md`；存在资源依赖或批量导出时才打包。本轮只形成总体设计，不安装依赖、不迁移知识库、不修改产品代码、不部署服务。现有工作树包含大量 ToDoo 相关未提交变更，执行时应在隔离工作区开展，并保留这些工作。

“本轮只形成总体设计”仅描述制定本文件的会话，不禁止未来经用户明确要求的开发。实施授权可覆盖代码、项目内依赖、测试、测试数据上的数据库迁移及可审查的迁移工具；开发完成不自动等于获准执行真实知识库批量迁移、覆盖生产数据、部署或重启常驻服务。这些操作应分别按当时用户授权推进。

## 方案比较和框架选择

1. Markdown 正文承担可表达的内容，原生画布附件承担白板数据，PNG 承担通用显示。采用此方案，满足用户已选方向，并复用现有图形链路。
2. 三种图形都只保存独立 JSON，再包一层 Markdown。编辑器接入较直接，但脑图离开应用后只剩图片，失去直接编辑大纲的价值，不采用。
3. 所有格式转换为 Excalidraw。可以共用画布，但难以保留脑图父子关系和 Mermaid 的原文编辑能力，不采用。

| 功能 | 选择 | 原因和限制 |
| --- | --- | --- |
| 白板 | 沿用 Excalidraw | 保留已有画布、图片、撤销重做和源文件格式，改持久化入口 |
| 脑图 | 新增 Mind Elixir 核心库和 @zumer/snapdom | 提供节点编辑、布局、拖拽、快捷键和撤销重做；按当前官方指引生成图片，不依赖已弃用的 exportSvg API |
| 流程图 | 沿用 Mermaid 加 CodeMirror 6 | 原文直接保存在 Markdown，复用当前安全渲染和 PNG 生成 |
| 格式识别和转换 | 沿用 markdown-it、Zod | 用现有解析能力和 schema 校验，避免重复引入 Markdown 栈 |

Markmap 适合大纲展示，本任务需要直接编辑脑图节点，首版不同时引入两套脑图引擎。Mind Elixir 的节点内 Markdown 支持不等于整个大纲的双向序列化，由 DooKnow 的受限格式适配器控制 Markdown 大纲与节点树转换，并通过往返测试验证。

此前讨论过的 simple-mind-map 当前 GitHub README 已明确说明库/Web 进入低维护状态，因此本方案调整为 Mind Elixir。此选择是结合当前维护信息、所需功能及适配范围作出的工程判断，不将仓库状态当成稳定性保证。实施前用中文输入、复杂文本转义、500 节点、深层级、离屏节点和大图导出做适配验证，选定经过验证的精确版本并锁定依赖，保留依赖许可证声明。PNG 捕获使用临时渲染实例展开完整树，覆盖整图并去除选中态/工具栏，不改变用户的折叠和视口状态；等待字体就绪，验证离线中文字体与不加载外部资源的导出路径。

流程图首版明确为 Mermaid 源码编辑、模板和实时图形预览，不包含任意拖拽画布与 Mermaid 的双向无损转换。现有 Mermaid 转白板仍是创建新副本的一次性转换。若以后要求拖拽式流程图，另评估 Vue Flow 或 LogicFlow，并另定原生数据规范。

## 主文件和附件规范

### 文档级标记

建议文件头使用标准 HTML 注释，JSON 由共享 schema 解析，例如：

```md
<!-- dooknow:document {"version":1,"type":"whiteboard","engine":"excalidraw"} -->

# 系统架构

![系统架构预览](assets/diagram-<preview-hash>.png)

[图形源文件](assets/diagram-<source-hash>.excalidraw)
```

示例中的哈希为占位符，实际沿用附件服务生成的文件名。首版一篇专用图形文档对应一个主图；正文可以包含另外的说明。文档级标记与现有 `dooknow:diagram-preview` 图块级标记职责不同，分别识别默认编辑器和源码/预览版本。

白板的源链接、预览图片及摘要绑定放在明确的生成区域内；基于 Markdown token 和源码范围读取，不扫描任意同名链接。保存只改写生成区域及必要元数据，保留说明、未知元数据和无关正文。脑图大纲及流程图源码也各有明确受管区域，范围标记使用 HTML 注释，不依赖自定义 Markdown 指令。

文件类型 `markdown | whiteboard | mindmap | flowchart` 与文件后缀分开：后缀是 `.md`，类型来自共享解析器。只识别文件头实际的顶层注释 token，跳过 BOM 和已有 frontmatter，不能将代码块、正文示例或嵌入图块中的文字识别为整篇文档类型。

无标记按普通 Markdown 打开。未知版本、重复冲突标记或受管内容不合法时，保留原文并提供普通 Markdown/源码恢复入口，不进行有损格式化。只有明确标记才决定专用编辑器，不能看到一个 Mermaid 代码块就把整篇普通笔记改成流程图文档。服务器返回解析结果，文件树、前端和插件复用该结果；数据库中的类型仅作为可重建缓存。

### 内容的权威来源

| 类型 | 权威内容 | 派生产物 |
| --- | --- | --- |
| 脑图 | `.md` 内受管的大纲，文档标题对应根节点 | 节点树、布局和 PNG |
| 流程图 | `.md` 内受管的 Mermaid 代码块 | 渲染 SVG、PNG；如输出 `.mmd` 附件，它只是导出副本 |
| 白板 | 由 `.md` 明确引用的 `.excalidraw` 场景附件 | PNG、用于检索的文字摘要 |

脑图首版支持一个根节点、文本节点和父子层级、同级排序；普通无序嵌套列表对应节点树。选定规范化 Markdown 子集，不把任意 Markdown 文档静默重写为脑图。首版不承诺富文本、跨节点关系线、自由坐标、每节点独立样式或 XMind 的无损导入。这些能力无法仅由大纲完整表示，需另定扩展后才能启用。折叠和视口先作为会话状态，布局及整体样式采用预设，不建立第二套权威 JSON。

PNG 是默认通用预览，使用相对路径，无登录令牌、数据库 ID URL 或内网绝对地址。文件名转义沿用 `shared/portable-figure.ts`。附件保存在现有 `assets` 体系内，不再建立另一套顶层存储区。

### 主文档与图形资源接口

文档类型、主图角色和源格式分开建模：`whiteboard`、`mindmap`、`flowchart` 是整篇文档的编辑类型；`primary`、`embedded` 区分专用主图和正文内嵌图；Excalidraw JSON、Markdown 大纲和 Mermaid 是可编辑源格式。不能把三者塞进同一个 fenced 代码语言枚举。

`GET /api/notes/:id` 和原文分段读取始终返回主文件原文，新白板的 `content` 必须是 Markdown，不能为了旧画布继续冒充场景 JSON。新增共享图形资源解析服务，按文档 ID、角色和主体权限返回主文件版本、源格式、源内容或授权读取句柄、源摘要、预览版本及编辑能力。全页画布、嵌入预览、预览准备、旧 UUID/路径解析、公开读取和 MCP 均通过该服务取得资源，各入口仍独立鉴权。旧读取协议需要明确兼容适配，不能直接 `parseWhiteboard(note.content)`。

扩展图形准备及绑定协议，允许脑图/流程图仅有内嵌权威源码和 PNG，不强制创建另一份源附件。整篇受管主图和普通笔记内嵌图由同一解析器识别，替代当前依赖“PNG、源链接、绑定、fence 必须相邻”的单一规则，避免生成区域注释、可选 `.mmd` 和脑图大纲无法被识别。

版本必须区分：主 Markdown 的完整字节摘要用于并发写入；源内容摘要用于编辑数据完整性；渲染指纹覆盖源、根标题、布局/主题等影响图像的配置和渲染器版本。派生 PNG 路径和绑定标记不计入渲染指纹，避免生成预览后又使自身过期。外部修改源附件、标题或配置均需要使对应预览失效。

## 保存、冲突和恢复

流程为：固定编辑快照 → 计算源码摘要 → 生成同一快照 PNG → 准备不可变附件 → 以预期版本提交 Markdown 引用。提交成功后新版本才对读者可见。上传成功、Markdown 提交失败时，旧版本保持可读，待用附件可按后续清理策略处理。

复用写入意图、工作区锁、幂等请求和本地草稿。白板一次提交关联主文件与源附件版本；不能只用主文件修改时间判断原生源附件是否被外部改动，需验证源摘要。脑图和流程图提交时检查 Markdown 基线版本，防止专用编辑器覆盖外部源码编辑。

编辑过程可以轻量保存本地恢复草稿，PNG 做合并和去抖，不能每次键盘事件都导出图片。只有源码与预览一致的版本才标记为完成通用保存。渲染失败保留最后一次完整发布版本和当前草稿，允许下载原文。

当前普通笔记已经有“仅保存源码”功能，应保持兼容。专用图形主图不能通过该入口移除预览后被标成完整发布；其原文编辑、全量更新、分段 patch、历史恢复和 MCP 文档上传统一经过服务端图形提交策略。未准备好预览的源码可保存为明确的待发布草稿，等待浏览器完成预览；原始快照上传及普通笔记内嵌图的源码保存规则与完整图形发布分开，不能仅由新编辑器按钮控制。

浏览器关闭或重试不能留下指向不存在附件的已提交主文件。原生源附件缺失、被篡改或摘要不一致时，显示现有 PNG 并说明编辑数据问题，不用空白场景覆盖原件。新图也必须完成第一张预览后才能成为可交付文档。

首次创建采用可恢复的预留身份与未发布创建意图：先预留 UUID、目标路径、所有者和幂等请求，附件准备允许绑定该意图，但未发布文件不进入普通扫描、分享、检索或导出。源码、首张 PNG 和主文件一起完成提交后才激活文档；取消、崩溃续跑和超时清理均验证同一意图。不能直接沿用当前“先创建活动笔记、再上传附件”的流程。

草稿升级为版本化封装，至少记录文档类型、载荷格式、主文件基线、源摘要和未发布意图 ID（如有）。同一文档会话只有一个写入协调者，画布和源码视图不能分别把 JSON 与 Markdown 写入同一个 IndexedDB 键。识别旧白板 JSON 草稿，保留并按旧格式恢复或显式转换，不能套用新 Markdown 恢复逻辑。跨标签页竞争继续进行版本比较。

### 历史、附件保留及恢复

历史记录增加原始文档类型、逻辑路径和固定的资源清单（相对路径、资源标识和摘要），不能根据历史存储文件统一的 `.md` 后缀解释内容。历史预览按历史类型读取。迁移前白板的 JSON 历史恢复到新规范时，需作为场景输入重新生成源附件、PNG 和 Markdown，不把 JSON 原样写进当前 `.md`。移动后恢复旧版本，按历史逻辑路径映射至当前目录，不能让旧相对链接按新目录误解析。小文件恢复和后台大文件恢复执行相同规则。

资源生命周期区分准备中、已被版本引用、待回收；当前文档、可恢复历史、回收站、有效准备/草稿租约、迁移回滚材料、博客发布版本和进行中的导出都是保留根。首版不增加自动删除历史附件的清理功能。后续清理必须受引用登记、租期和幂等回执有效期约束；过期回执返回明确状态，不能删掉合法重试仍需读取的附件。浏览器离线草稿引用当前不可变源和新载荷，新增资源随准备租约登记，不依赖服务器扫描 IndexedDB。

不可变附件若被外部覆盖，按保存摘要报告完整性冲突；恢复优先使用已固定快照或受控备份，找不到原始字节时明确拒绝冒充恢复成功。备份继续复用现有知识库 `assets` 备份，新建的版本资源清单、迁移日志和引用登记也必须纳入现有状态备份与恢复清单。

## 编辑体验

创建菜单提供笔记、脑图、流程图、白板、模板和文件夹。三种图形都实际创建 `.md`，文件树使用不同图标。提供默认专用视图、Markdown 源码和只读预览切换；切换前处理当前未保存草稿。

脑图支持新增同级/子级节点、编辑、删除、拖动层级、折叠、缩放和撤销重做；快捷键与中文输入法事件需验证。源码模式修改大纲后重新解析，失败时保留原文。说明区不能被节点编辑覆盖。

流程图提供开始/结束、判断、分支等常用 Mermaid 模板、语法错误定位、实时预览及 PNG 导出。白板继续使用现有全页及嵌入画布体验。

三种图形均复用自动保存、冲突提示、草稿恢复、返回保护、明暗主题和按需加载。预览图片使用适合独立阅读的背景和对比度，不能依赖宿主应用 CSS。

新类型标记和受管区域注释须加入 `knowledgeMarkdown` 的安全隐藏 token 及可视化编辑器的受保护原文节点，覆盖正文阅读、分享、博客、HTML 导出和打印。现有原文账本已经能保留未知注释，不应重写这一机制，更不能为隐藏标记而启用任意 HTML。专用类型移除或转换通过明确的文档转换操作完成；外部工具删标记时按普通 Markdown 打开并保留附件，不静默重建或销毁原件。

切换视图先完成同一会话快照交接，再设置新的撤销边界；源码重解析后不得继续回放旧画布的操作历史。自动更新 PNG、摘要和机器标记不单独进入用户撤销栈。普通可视化编辑不允许误删受管边界；不支持的内容原样保留并回退源码编辑。

## 旧白板迁移和引用

先支持同时读取旧 `.excalidraw` 文档与新 Markdown 白板；新建统一采用新规范。旧格式仍可导入，并进入受控转换流程，不能只改后缀。

提供预检和可续跑的迁移任务：

1. 列出旧白板、入站引用、同名 `.md` 冲突、无效场景、正在编辑的基线冲突和缺失附件；提供结果报告，不覆盖冲突目标。
2. 为每份白板固定旧版本，沿用已有浏览器画布生成源附件和 PNG，再准备新的 Markdown。
3. 经服务端迁移日志及写入意图，将原文档身份映射到新的 `.md` 路径。保留原 UUID、收藏、历史归属和引用关系，并同步可移植身份登记及索引状态。跨文件系统和数据库的操作依赖日志恢复，不假定数据库事务能原子提交文件。
4. 主文件可读后处理旧引用。旧 UUID 引用在 DooKnow 内继续可解析；已有路径引用建立迁移映射并受版本保护地改写。普通 Markdown 的嵌入补充标准 PNG 和源文档链接，不只保留私有 fenced 引用。
5. 每条完成后核对源摘要、PNG、主文件和引用，记录迁移前路径、版本、附件及改写范围；原件保留为受控备份，不立即删除。

迁移使用专门的写入意图和身份映射，不通过现有禁止 `.excalidraw → .md` 的普通改名/恢复 API 绕过类型保护。准备阶段保留旧身份可读，切换阶段短暂阻止该文档的新写入并重新校验基线；活动文档、可移植身份登记、历史类型和引用更新失败时由日志恢复。旧浏览器会话须收到版本冲突和重载提示，不能让旧 JSON 自动保存覆盖已迁移的 Markdown。

PNG 渲染由复用现有前端引擎的迁移界面提供，服务器记录进度和提交；不假定普通 Node 进程能直接渲染 Excalidraw。浏览器关闭后可重开续跑。无效场景或外部嵌入资源无法安全渲染时跳过该条并保留原件，不降低校验标准。

回滚对迁移后仍未被编辑的文档恢复旧映射；已经编辑的新文档不能被回滚覆盖，应报告并保留两版。迁移任务重复运行不创建重复文档，也不能让旧副本再次被扫描成第二个独立白板。

图形引用明确区分“源文档身份”和“预览快照”。现有 DooKnow 内的动态 UUID 解析继续指向源图，磁盘上的标准图片是最后一次更新的快照。图形自身保存不悄悄重写所有引用它的笔记；保存引用笔记和导出时刷新其通用预览。导出固定一组源版本，打包相应 PNG 与附件，不对未保存原件做隐式写入。

首版不部署服务端浏览器渲染器。UI 发起通用导出时，先检查依赖并在浏览器生成需要更新的版本化图形产物，再提交固定版本的导出请求。服务器或 MCP 单独发起导出只使用与固定源码版本摘要匹配的已准备预览；预览缺失、外部源码编辑后过期或准备阶段发生版本变化时，返回可识别的 `DIAGRAM_PREVIEW_REQUIRED`/版本冲突及待更新文档列表，不把旧 PNG 静默当作最新内容打包。用户可在 DooKnow 更新预览后重试。完整备份仍应保留磁盘原件及旧预览，不受通用图形导出的准备要求阻挡，恢复时保留其过期状态。

## Markdown 和附件的可移植导出

默认导出自动按依赖收集结果选择交付形式，不要求用户先选择是否打包：

- 单篇笔记且没有需要随行的资源或其他本地文档，直接下载 `.md`，不创建空 `assets` 目录、不添加清单文件、不生成压缩包。正文包含普通排版、表格、代码或外部网页超链接也可属于此情况，不按是否为字面纯文本判断。
- 单篇笔记引用图片、视频、音频、图形原件、预览或其他需要随行的文件时，导出包含 Markdown 和依赖文件的压缩包；按需要创建 `assets` 目录。
- 多篇或文件夹导出统一打包以保留目录结构，即使所有文档均无附件也不触发多次独立下载；无附件时不创建空 `assets` 目录。

携带附件的压缩包解压后保持目录结构，即可在其他支持标准 Markdown 图片和链接的工具中阅读；浏览不需要生成新附件，也不依赖 DooKnow 服务。存在资源依赖时，只下载主 `.md` 不是完整便携导出。缺失或不可访问的资源仍是未解决依赖，不能因为收集失败而降级为无附件的单文件下载。

导出流程为：固定文档版本 → 收集资源依赖 → 按单篇/批量和依赖结果选择交付形式。无依赖的单篇直接下载 Markdown；其余情况先生成包内路径映射并完成影响原生源字节的链接重定位，再按导出副本的最终源内容准备匹配预览，填入派生图片引用和绑定，校验完整性后打包。主文件中的派生预览路径不计入渲染指纹，不能出现改路径、生成图、再改源的循环。只改导出副本，不改知识库原文或原附件。

- 资源收集覆盖普通图片、视频、音频、视频封面、下载附件，以及白板原件、脑图/流程图 PNG 和显式引用的图形源文件，不能只处理新建图形的生成区域。
- 基于实际 Markdown/受支持 HTML 结构识别行内图片、引用式图片和链接、附件链接、`src`、`srcset`、`poster` 与媒体 `source` 等资源位置；代码块和行内代码中的路径示例不作为依赖。DooKnow 内部资源地址和 UUID 引用先按现有权限解析为可导出的文件或标准文档链接。
- 相对路径按各源文档所在目录解析，收集跨文件夹资源。为本地被引用的 Markdown 文档继续收集依赖，使用已访问集合处理循环引用；保留标题锚点。普通外部网页超链接保留原链接，不递归抓取网站；因此外部网页本身不在离线阅读保证范围内。
- 依赖边区分正文导航、图形身份引用和必要附件，分别记录用户选中文档与额外关联文档。默认便携导出仍包含可访问的本地关联文档以保留离线链接，但必须先计算文档数、总大小和范围，并受显式预算约束；不能无限递归或静默越过访问范围。每个关联文档独立鉴权，根笔记权限不授予目标笔记权限；任务续跑、下载和分块读取复核固定依赖闭包，授权变化时终止下载，错误信息不泄露不可访问目标的私有内容。
- 外链嵌入媒体需要在现有访问权限和网络资源校验下取回并本地化，不能把远程图片当作已离线打包。临时 `blob:` 资源须先持久化；`data:` 媒体按类型和大小校验后可转换为普通附件。无法访问、已经失效、资源超限或缺少授权时，列出来源文档和失败资源，完整便携导出不能静默成功。
- 保留导出文档的目录层级，附件统一分配到包内 `assets` 目录，并按每篇导出文档所在位置计算正确相对路径。同内容附件可按摘要去重；不同内容但同名、大小写冲突的附件必须分配不同路径。正确编码中文、空格、括号和 URL 转义，禁止写出绝对主机路径或逃逸到包外的路径。
- 标准链接、图片、受支持 HTML 资源地址，以及 DooKnow 受管元数据中关联的路径同步重写；解析与改写使用源码范围，保留其他正文和代码。包内不依赖 `/api/...`、登录令牌、临时签名地址或私有 UUID 协议显示本地内容。
- 视频和音频原件一并打包，并始终提供标准 Markdown 文件链接；视频已有封面时同时保留封面。支持媒体嵌入的工具可以播放，不支持的工具仍可通过链接交给本地播放器打开，不承诺所有 Markdown 浏览器都能内嵌播放。
- 打包前核对每条包内引用的目标、资源摘要及图形源码/预览版本，不能夹带导出期间的新旧混合版本。缺失资源、越权依赖或过期图形预览以明确失败和诊断列表返回；如以后提供忽略失败的导出，必须另标为不完整包，不能按完整导出报告成功。

压缩包导出附带简洁的文件/资源清单和校验摘要，便于核对包内容；清单不包含凭据或主机绝对路径。资源包以“复制整个解压目录到另一台设备，并停用 DooKnow 后，正文、图形和媒体链接仍可用”为验收基准。附件目录是交付内容的一部分，不能只检查 `.md` 文件本身。单文件导出则以移动下载的 `.md` 后可独立阅读为验收基准，不附带额外文件。

### 导出接口、媒体和回导入

保留现有“下载原文”及 MCP `download_note_document` 的快照原文契约，保留旧 bundle 导出始终返回归档的语义。新增默认便携导出入口，明确请求来自单篇、显式多篇还是目录，自动选择实际交付形式；目录恰好只有一篇仍按目录导出处理。结果包含交付类型、实际文件名、MIME、大小、摘要和版本化清单，UI 使用服务端结果命名，不能将压缩包下载成 `.md`。`DIAGRAM_PREVIEW_REQUIRED` 等错误持久化结构化的待准备文档列表，而非只存错误字符串。

管理端与 MCP 现有两套任务继续各自管理授权和进度，但调用同一个资源依赖、版本固定、路径映射、完整性检查和打包规划核心，不能各自实现一份新规则。所有原文下载、便携导出、HTML 导出及打印的入口和文案明确区分，避免仍有默认导出绕开附件收集。

音视频是需要新增的资产能力，当前资产类型只含图片、PDF 和图形源文件。首版媒体范围定为受校验的 MP4/WebM 视频、MP3/WAV 音频及现有附件类型；应用内至少提供文件链接，不在本任务承诺全套播放器。同步调整上传、MIME/文件结构校验、资产读取、公开授权、导出和导入。媒体配额与 PNG/白板配额分开配置并由前后端共用，不能仍套用当前附件 10 MiB、导入总量 20 MiB 的限制；大文件走有界流式暂存，避免全量 Buffer/Base64 链路。

提供能直接读取本应用导出归档及解压目录的导入流程，识别和校验清单版本、文件列表及摘要，清单是包元数据而非普通 `.json` 资产。当前导出可达 256 MiB/10000 文件、目录导入仅支持 20 MiB/200 文件，必须通过统一的资源预算和流式/分批暂存服务使本实例生成的完整便携包可整体回导；旧小批量 JSON 导入 API 可保留其限制。导入后重写路径、资源绑定和副本身份，不能要求用户手工剔除清单或拆开相互依赖的文件。归档校验沿用安全解包流程，不信任清单中的绝对路径、越界路径、符号链接或重复文件。

远程媒体取回、浏览器渲染及压缩都在全局工作区排他锁之外执行：短锁固定本地快照和权限闭包，锁外执行有时限、字节数、重定向和目标地址约束的资源取回与打包，发布前短锁复核。不得把慢网络请求放进现有贯穿整个导出的排他区，阻塞普通笔记自动保存。远程媒体下载不转发用户会话或任意凭据，不绕过私网地址及资源访问检查；失败、中断和授权失效均回收暂存文件。

## 检索、图谱与外部资源变化

白板主 Markdown 的受管区生成可读文字摘要，绑定当前场景源摘要；检索该区及说明正文，引用定位使用它们在主文件中的真实行和字节范围。脑图使用真实大纲位置，流程图使用真实代码/说明位置。不得沿用旧白板“从 JSON 提取标签、坐标却指向整个源文件”的投影方式，也不把源附件标签伪装成 Markdown 内容。

索引完整扫描证明与可检索块范围分开：所有原文字节都须经过扫描，但元数据、机器标记和重复预览不必成为检索文本。现有 `text.publish` 要求 chunk 连续覆盖全文件，必须同步调整完整性校验及引用读取，避免简单跳过元数据后触发 `INDEX_INCOMPLETE`。检索结果、AI 引用、全文搜索、向量检索、知识图谱和集合投影均使用该规则。

建立源资源到主文档的反向依赖，文件监测及 Git 调和不仅观察 `.md`，还将源附件缺失、外部修改和 Git 冲突传播为主文档的过期/冲突状态；不能因主文件哈希未变化就继续声称图形、索引和图谱是最新。派生 PNG 本身修改也需重新校验预览完整性。首版可沿用主文档字节变化触发正常索引重建，不增加未经验证的语义缓存；以后按投影指纹复用时，仍必须重新绑定真实源版本和范围，不能用语义摘要替代写入校验。图谱人工确认决策和稳定文档身份不因只更新预览而被当作新文档丢弃。

## 全链路兼容

- 重命名和移动：更新受管区域中的相对图片/源链接、文档标记内可能的相对路径和入站文档链接；不依赖数据库解析才能打开导出的文件。当前单文件跨目录移动会拒绝含相对链接的 Markdown，须增加有计划、可恢复的资源引用改写，不能仅换文件类型判断。批量整理、整理撤销及单文件移动使用同一规则；历史旧版本引用的不可变附件仍需保留。
- 原生源内链接：Excalidraw `elements[].link` 等链接也属于依赖图，规定相对链接以源附件所在目录为基准。旧白板迁入 `assets` 时按原逻辑路径重定位；目标文档移动、复制、导入和导出均检查原生链接。需要改写时生成新的不可变源附件，更新主文件摘要及预览绑定，不能把源附件当作不透明二进制而遗漏其链接。
- 链接重定位与预览：影响源字节的改写先进入操作计划，再生成对应的 PNG。首版不假定路径变化一定不影响渲染，不直接把旧 PNG 改绑到新摘要。UI 可在提交前按计划渲染；独立服务器/MCP 执行若缺少最终源的匹配预览，整个文件操作或便携导出在提交前返回结构化 `DIAGRAM_PREVIEW_REQUIRED`，准备完成后按原计划及基线重试。不得先移动/导入后留下不完整图形；批量操作逐条报告未提交状态。
- 文件夹删除及附件共享：删除/回收目录前检查目录外活动文档、历史和有效准备租约对目录内附件的引用。首版阻止会移走这些仍需保留资源的删除并报告影响，不能整目录搬进隐藏回收站后破坏其他白板。复制可以共享有固定摘要和保留登记的不可变附件；修改副本时写新附件，不覆盖原件。恢复到不同目录名称时按登记的路径映射处理。
- 复制和导入：新副本分配新文档身份，内部引用按导入映射重写；附件不被再次识别成主文件，保留现有跨知识库身份规则。
- 导出：按上述规范自动判断，单篇无依赖直接下载 `.md`，有资源依赖或批量导出才打包；自动收集引用资源并改写相对路径，可选另行下载原生源文件。
- 分享和博客：新专用图形默认只读并使用正文及 PNG 的公开投影；原件下载需单独显式授权。公开正文、分段读取、附件两个入口、旧白板资源接口及公开导出均遵循同一投影，不能只在 HTML 隐藏源链接。现有资源证明会将正文中的源链接当作公开授权，须增加资源角色/能力校验，不能把“被引用”等同于“允许公开原件”。权限必须依据语义类型及图形资源能力，避免 `.md` 后缀意外开启白板公开编辑。
- 博客发布：消费同一受管图形及预览绑定解析结果，冻结发布时的主文件、源摘要和 PNG；新白板即使没有 fenced 图块也执行源码版本复核，不能作为普通图片跳过现有 `BLOG_PREVIEW_REQUIRED` 检查。发布包仅固化允许公开的产物；标题、源码或绑定变化后重新准备预览，旧发布版本仍按其固定资源读取。
- 索引和检索：脑图索引标题和节点文字，流程图索引标题和可提取标签，白板索引文字节点及说明。排除 JSON、Base64、机器标记和重复预览文本。
- MCP、Bridge、备份和恢复：返回完整类型信息；读写遵循相同格式和权限，备份包含源附件和预览，不只保存 Markdown。
- 安全和资源限制：沿用当前相对路径、权限、场景和 SVG/Mermaid 校验；防止路径越界、外部资源读取、超大图阻塞和分享越权。上限由现有白板/PNG 限制及脑图验证结果确定。

## 分阶段交付

| 阶段 | 主要交付 | 完成条件 |
| --- | --- | --- |
| 1 格式和适配验证 | 共享 schema、主文档/图形资源契约、主图与嵌入角色、绑定版本、Mind Elixir 和 PNG 小范围适配验证 | 前后端类型一致，脑图受限格式往返不丢内容，摘要不自引用 |
| 2 新版白板及基础链路 | 预留身份、完整提交、版本化草稿、隐藏标记、旧白板双读、权限投影、历史/附件保留和移动 | 创建、重开、公开只读、冲突、历史恢复、移动及外部阅读通过；不能把权限和恢复延后 |
| 3 迁移及引用 | 预检、专用迁移日志、原身份保留、旧引用适配、旧草稿/历史转换、索引投影 | 中断/重复运行/旧会话写入/旧历史恢复用例通过，图形标签可正确检索引用 |
| 4 脑图 | Mind Elixir 编辑器、大纲适配、预览和统一提交服务接入 | 节点编辑与 Markdown 源码往返通过，说明区字节保留，MCP 与源码写入不绕过预览政策 |
| 5 流程图 | Mermaid 专用编辑器、模板、错误反馈、主图/嵌入保存策略 | 源码、图形预览、保存重开及外部显示一致，普通笔记现有源码保存保持兼容 |
| 6 便携导出及回导 | 共享依赖规划、单文件/归档结果协议、媒体能力、清单导入、配额和短锁暂存 | 生成的完整资源包可整体回导，权限闭包有效，大媒体不阻塞笔记保存 |
| 7 全链路验收 | 分享/博客/HTML打印、图谱/Git、MCP、ToDoo笔记关联、备份恢复 | 换设备后正文和图片可见、媒体链接可打开；历史和任务笔记关联可恢复，安全边界无回退 |

每阶段保持可运行并做相应评审；阶段 1 锁定规范后，脑图与流程图才有稳定接入点。实施时再按该设计拆成具体文件、接口和测试步骤，避免同时改动保存协议与多个未验证编辑器。

## 验证标准

- 格式测试：BOM/frontmatter、CRLF、中文及特殊字符、未知字段/版本、代码示例中的伪标记、缺失/重复受管区域、未知类型安全降级。
- 往返测试：脑图同名节点、嵌套和重排、Markdown 特殊字符；Mermaid 原文保留；Excalidraw 图片和文字节点保留；非受管正文不丢失。
- 一致性测试：上传后提交失败、结果不明重试、并发修改、外部编辑源附件、旧 PNG、渲染失败、页面关闭和草稿恢复。
- 迁移测试：同名冲突、稳定 ID、旧 UUID/路径嵌入、原有历史、收藏、分享限制、中断续跑、重复执行和带新编辑的回滚。
- 生命周期测试：跨目录移动、复制、删除恢复、历史恢复、导入导出、源附件丢失、重建数据库、Git 同步和备份恢复。
- 外部兼容验收：导出后停用 DooKnow 接口，以 CommonMark/GFM 渲染图片和正文；浏览器加载导出目录核对相对资源，确保无令牌、内部地址和私有图形协议依赖。不以应用内专用预览代替此项验收。
- 资源包验收：覆盖跨目录、同名不同内容、大小写冲突、中文/空格/括号、引用式图片、HTML 媒体、视频封面、外链媒体本地化、循环文档引用、缺失/失效/越权资源、资源超限及导出期间修改；检查代码示例未被改写。将解压目录换到另一位置或设备，核对图片可见、附件可打开和视频/音频文件链接可用，不能只在原工作区验证。
- 导出形式验收：单篇无依赖时只返回 `.md`，含外部网页链接或表格/代码的无依赖笔记同样直接下载；单篇有资源及批量无资源时返回压缩包；不生成空附件目录；缺失资源不能误判为无依赖，绕过完整性检查。
- 接口与会话验收：`.md` 原文不能被当 JSON；旧 UUID 嵌入、新图预留身份、旧草稿转换、跨视图撤销及多标签页竞争通过；普通嵌入图源码保存不破坏专用主图完整提交，Web/MCP/patch/上传遵循相同策略。
- 恢复与文件操作验收：迁移前 JSON 历史、小/大文件恢复、跨目录历史基准、目录外引用附件的文件夹删除、复制后修改、源内节点链接和整理撤销均覆盖；资源保留和备份清单可重建。
- 发布与导出授权验收：公开主文档、分页原文、源资源直链、旧白板接口和博客不泄露未经授权原件；生成资源包后撤销关联笔记权限须终止后续下载；真实导出归档/目录含清单整体回导，不手工筛文件；慢外链下载不长时间持有工作区排他锁。
- 原生链接重定位验收：跨目录移动、关联目标改名及导入导出改变场景链接后，PNG 必须匹配最终源摘要；没有浏览器准备能力的 MCP 操作在提交前返回待预览状态，不能先提交半完成文件或仅修改摘要冒充预览更新。
- 检索与外部变化验收：主文件文字投影行字节正确，完整扫描与可检索范围分离；只改源附件、源附件 Git 冲突/丢失和只改 PNG 的状态传播通过，旧标签引用不得误指向 Markdown 链接行，人工图谱决策保留。
- 运行项目 `npm run typecheck`、适用的 Vitest/Playwright 集、`npm run build`；发布前按项目既有发布检查补齐。不会为了本轮方案运行产品测试或修改运行服务。

## 执行模型和思考等级建议

默认建议 GPT-6.1 Sol（`gpt-6.1-sol`）配 High（`high`）承担分阶段实现。跨文件持久化、迁移恢复和权限回归是主要难点；可只在这些阶段或遇到复杂失败时提升到 Extra high（`xhigh`）。预算更充足时，可用 GPT-6 Astra（`gpt-6-astra`）配 High 对迁移和保存设计做独立审阅。它们是对此任务的工程判断，不是官方对本仓库的性能保证。

官方资料将 Sol 定位为较低成本的复杂、长时间工作选项，Astra 为更高能力选项；建议提高 effort 时比较质量收益、时间与成本，因此不建议全程默认 Max。
