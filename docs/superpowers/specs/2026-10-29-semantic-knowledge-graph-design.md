# 内容感知知识图谱完整设计

## 目标与授权

用户要求在已有引用图基础上整体实现内容感知图谱，学习成熟产品，并明确要求 UI 不杂乱。用户已选择“本地模型与模型 API 都支持，先做好统一配置入口”。本轮延续独立 `codex/knowledge-graph` worktree，不部署，不接触正式知识库或其他会话工作区。

## 调研与方案

- Obsidian：笔记/引用图、局部深度和孤立项提供可解释的基础关系。
- Microsoft GraphRAG：分块提取实体与关系，关联原文 TextUnit，来源证据是核心数据，不把相似度当作事实。
- InfraNodus：内容中的概念和共现形成网络，点选后查看相关原文；采用其按选择深入探索的方式，避免同时铺开多个分析面板。
- Smart Connections：相似笔记作为辅助探索，不自动把推荐改写成原文链接。
- LightRAG：实体/关系抽取与增量维护分离，支持本地模型接入。

参考入口：https://obsidian.md/help/plugins/graph 、https://microsoft.github.io/graphrag/index/default_dataflow/ 、https://infranodus.com/tutorial/interface 、https://smartconnections.app/docs/connections/ 、https://github.com/HKUDS/LightRAG 。参考设计思路，代码按本项目架构独立实现。

可选路线：仅把引用图改为自动刷新，不能满足内容感知；直接引入完整外部 GraphRAG 服务会增加数据库/运行时和部署负担；采用宿主内置、独立图谱索引与模型适配层，在现有 SQLite/Vue/Fastify 上实现完整业务。本轮选择第三条。模型未配置时仍能运行本地概念/词项及共现分析，明确标注“基础分析”；连接模型后生成带出处的语义候选。模型质量和实际远端连通性取决于用户配置，不伪装已接入真实模型。

## 功能闭环

1. 持续自动感知保存、导入、移动、删除、恢复与外部文件修改；持久任务与进度，暂停/继续/重试/重建/取消。图谱更新不依赖每次手动刷新，不受向量/分词组件就绪条件阻塞。
2. 笔记、概念、人物、组织、地点、事件与技术实体；显式引用、提及、共现、相似、模型语义关系及人工关系分别建模。
3. 关系证据绑定笔记 ID、来源版本/hash、原文摘录和行号；抽取的 quote 必须真实存在。模型候选可确认、忽略、修改；忽略记录不因重建复活。支持实体合并、别名与人工关系。
4. 搜索、目录/类型/置信度筛选、局部一至两跳、社区颜色与路径探索；低置信关系及相似边按需展开。保存视图，导出当前授权视图 JSON 与画布 PNG。
5. 图谱问答使用所选实体或搜索命中的有限证据，仅返回有效引用；没有配置模型时明确提示配置，不生成伪答案。
6. Ollama 原生 /api/chat 和 OpenAI 兼容 /chat/completions 两种模型适配，统一配置、测试连接和状态。密钥不回传、不进入 _data/Git/日志。远端发送正文需配置明确许可；基础本地分析不访问网络。

## 数据与一致性

自动结果与任务保存在运行数据库，来源稳定读取与 hash/revision 校验沿用核心原则。独立 graph_analysis_jobs 租约/epoch/重试，避免混入硬编码 text/vector 队列。任务发布须核对来源版本、路径、活动/冲突/写入状态和模型配置版本；发生变化撤回旧结果。独立服务启动即接入自动更新，退出 await 任务结束和模型取消。外部变化可复用 watcher/reconcile，缺少宿主 watcher 时提供受控补偿。

原文分块处理，不再沿用引用图 256KiB 限制作为语义索引整篇拒绝条件；保留平台文件上限、有界分块、模型输入/输出/耗时和并发预算，省略或失败必须可见。正文、代码和 frontmatter 的处理规则明确，证据定位始终对应原文。

人工审核、合并、别名和保存视图是不可重建资料，采用 `_data/apps/knowledge-graph/state.json` 的 knowledgeDataDomain、版本/CAS、幂等请求与冲突保护；模型配置和密钥仅留本机。自动结果可重建，人工决定随知识库迁移，二者分开。

权限先过滤来源，再聚合实体名称/描述/度数/社区/统计/证据；隐藏资料不得通过实体摘要或候选数量泄漏。所有 mutation 要求主人会话、CSRF、Origin 和期望版本。旧 GET /api/graph 保持兼容，新完整 API 位于 /api/graph/explore、status、settings、jobs、review、state、commands、ask。公开分享不开放完整图谱。

## 简洁界面

默认一条紧凑工具栏与一个画布；“笔记/知识”切换、搜索、筛选、一个状态胶囊。起始展示有限且有代表性的子图，按需展开，标签优先显示中心/选中/相邻节点。取消画布下方重复笔记卡片；列表与画布互斥，列表保留完整键盘操作入口。默认最多 80 节点/120 边，更多结果明确提示缩小范围或局部探索。

选中节点或边后才出现 inspector。桌面为可关闭侧栏，手机为 drawer。证据只放详情中。模型设置、任务、审核、视图管理/问答通过覆盖层按需打开，一次一个；高级参数折叠。画布更新尽量保留缩放、平移与位置。用共享 Ant 控件、SettingsOverlay、主题 token、低饱和类型颜色，图形不依赖颜色传达唯一含义，适配深浅主题与 reduced motion。

## 验证与交付

真实行为测试覆盖本地分析、两类模型协议与错误、密钥不泄漏、证据校验、自动索引/重启/重试/取消、源变化拒发、跨权限实体聚合、便携人工决定/CAS、相似与事实区分、合并/路径/视图/问答引用。桌面与手机验证完整功能与页面不溢出，不以 API mock UI 占位代替业务。模型集成用受控合成资料服务验证协议；没有用户真实模型配置时，明确记录实际模型质量尚未验证。最终 typecheck/build/相关回归、独立审查、截图与本地提交。
