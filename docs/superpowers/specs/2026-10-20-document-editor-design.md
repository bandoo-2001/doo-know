# 文档编辑与 Markdown 源码双模式设计

状态：用户已授权实施，开发实现与自动验收已通过，用户已确认电脑与手机两端中文输入正常；具体平台版本未记录，后续已获独立发布授权并完成 rc.26 正式验证。实际证据见[验收记录](../../验收记录/2026-10-20-document-editor.md)。日期：2026-10-20。

目标是让不熟悉 Markdown 的用户直接写文档，同时保留现有源码编辑能力。文件仍以 Markdown 保存，已有知识库、Git、MCP、搜索、历史、分享和备份继续使用相同原文。

## 使用体验

顶部提供三个清晰入口：

| 入口 | 行为 |
| --- | --- |
| 文档编辑 | 直接编辑排版后的正文；标题不显示井号，列表不显示语法标记，表格直接编辑单元格 |
| Markdown 源码 | 保留 CodeMirror、行号、语法高亮；“同时预览”作为此模式的附属选项 |
| 阅读 | 复用现有预览渲染，隐藏编辑工具；返回编辑时恢复上次使用的编辑方式 |

新用户默认文档编辑。已有明确保存的默认视图按迁移规则保留；提供可主动切换的文档编辑入口。文件不适合文档编辑时，保留可用的源码或大文件编辑方式，并在入口旁解释原因。

两种编辑方式共享一份未保存内容。切换不触发服务器保存，不新增历史版本；保存仍由按钮或 Ctrl/Cmd+S 明确触发。

## 首次完整交付的功能

| 能力 | 具体交互与边界 |
| --- | --- |
| 正文和标题 | 正文、标题 1–5；既有标题 6 可显示和保全，不强制降级；Enter 分段、Shift+Enter 换行 |
| 行内格式 | 粗体、斜体、删除线、行内代码；选中文字后操作，工具栏反映当前位置状态 |
| 列表 | 无序、有序、任务列表；回车续项，空项退出，Tab/Shift+Tab 缩进与提升；任务勾选属于未保存修改 |
| 引用和代码 | 引用、代码块、语言选择、分隔线；代码内容原样保留，代码块内不会执行格式转换 |
| 表格 | 插入标准 Markdown 表格，编辑单元格，增删行列，设置列对齐，Tab 导航；删除整表可撤销 |
| 链接 | 编辑文字、目标和标题；编辑态点击提供打开/编辑操作，阅读态沿用现有跳转规则 |
| 图片和附件 | 复用现有上传、授权及相对路径；图片替代文字可编辑，PDF 作为附件链接；异步完成只插入原笔记的有效位置 |
| 样式 | 对接现有文字颜色和段落对齐语法；只接受项目现有白名单，避免引入任意 HTML/CSS |
| 粘贴 | 纯文本保留换行；常用网页/办公软件格式按支持子集转换；明确无法表示的结构提供“按普通文本粘贴”或取消 |
| 写作辅助 | 撤销、重做、快捷键、章节目录、搜索命中定位；手机工具栏可访问，弹层不超出屏幕 |

首版不启用需要用户掌握 Markdown 的输入规则。后续可增补斜杠插入、块拖拽和更复杂排版；多人协同、分页排版、评论修订、DOCX 导入导出不列入本次完成标准。

表格限于 Markdown 可表达的单元格内容，不提供合并单元格、单元格内多个块或嵌套表格。复杂粘贴必须明确处理，不得悄悄丢失结构。

文档编辑、阅读、源码分屏和分享页对标题、表格、任务列表及项目样式保持相同含义。补齐当前缺少的任务列表阅读显示，阅读和分享中的勾选标记为非交互展示，不能绕过保存操作修改正文。

## 现有实现及接入边界

- `apps/web/components/MarkdownEditor.vue` 使用 CodeMirror，提供 `format`、`editHistory`、`goToLine`；同时服务普通笔记和大文件片段，不能直接全局替换。
- `apps/web/components/Workspace.vue` 持有 Markdown `draft`、保存版本、未决保存请求、冲突处理、预览、章节目录和导航守卫；它继续拥有服务器写入职责。
- `apps/web/markdown-format.ts` 定义现有格式动作及工具栏状态，可沿用动作名称，增加能力查询而不是让两个编辑器各自定义按钮。
- `apps/web/drafts.ts`、`apps/web/useNoteDraft.ts` 保存按账号和知识库隔离的 Markdown 本地草稿；其 `note`/`fragment` 类型及版本检查继续有效。
- `shared/markdown-styles.ts` 对有限的 `<div style="text-align:…">` 与 `<span style="color:…">` 开放解析，普通 HTML 仍被禁用。
- `packages/core/knowledge/limits.ts` 当前普通文件上限为 1 MiB，另有长行和大文件边界。文档编辑使用更保守的浏览器上限，不能通过提高服务端限制绕过大文件流程。

本轮不改服务器保存协议和笔记身份；如验证发现必须更改读写合同，先更新本文及计划，不把协议变更藏在 UI 任务内。

## 技术选择

优先验证 Tiptap 的 Vue 3 接入与 ProseMirror 扩展机制，保留 CodeMirror 作为源码编辑器。Tiptap JSON 仅作编辑中的投影，不作为数据库、磁盘或草稿的唯一正文。

已于 2026-10-20 核对官方资料：Tiptap 提供 Vue 3 接入，其 Markdown 模块仍标记为 Beta，文档说明了部分不支持的内容及表格限制。因此，不把默认的整篇解析再序列化视为原文保全方案。

参考：[Vue 3 接入](https://tiptap.dev/docs/editor/getting-started/install/vue3)、[Markdown 能力与限制](https://tiptap.dev/docs/editor/markdown)、[Markdown 使用及往返验证](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage)。

第一阶段验证后锁定依赖版本、许可证、体积及插件组合。只引入本地构建的必要依赖，不依赖付费转换、在线编辑器、CDN 或外部云服务。验证不通过时暂停该路线，提交差异证据，再评估原生 ProseMirror 或 Markdown 原生编辑器；不通过减少数据保护要求强行推进。

## 原文保全

### 保存原则

1. 没有实际内容编辑时，返回读入的同一 Markdown 字符串；打开、浏览、切换模式均不产生写请求。
2. 对已编辑的最小安全语法单元重新生成 Markdown；未编辑单元复用原文切片，保留标记风格、空行、引用定义及代码围栏。
3. 嵌套列表、引用、表格和跨块样式容器按完整依赖单元处理，不能只截取任意 DOM 段落。
4. 原文字符串中的 UTF-16 位置用于浏览器编辑映射；服务端字节位置仍使用既有 UTF-8 规则，不混用。
5. 不承诺修复读入之前已由既有接口归一化的内容；通过“不编辑就不写”确保浏览本身不改变磁盘文件。

### 内容分类

| 内容 | 处理方式 |
| --- | --- |
| 已验证的普通 Markdown | 可视化编辑；只重写实际受影响的安全单元 |
| 能确定边界但不能可视化编辑的内容 | 显示“此内容保留原文，可在源码中编辑”的原文保留块，原字符串随块保存 |
| 无法确定安全边界或跨单元依赖 | 整篇使用源码编辑，说明原因，保留全部内容 |

Frontmatter、HTML、注释、脚注、数学/指令语法、复杂引用链接、异常嵌套及自定义扩展必须进入兼容语料。支持与否以验证清单为准，不能因第三方解析器“没有报错”就认定内容安全。

保留块不能被普通输入、粘贴、跨块删除或拖动隐式破坏。首版保留块不拖动；整块删除需要明确操作并可撤销。涉及无法保持依赖关系的跨块操作，执行前拒绝并提供源码入口。跨块复制必须包含完整原文或明确提供文本复制方式。

原文切片、节点身份和版本映射必须保存在侧表或非 DOM 元数据中，不能相信粘贴 HTML 内伪造的节点 ID。

### 不可表示的操作

转换层对候选编辑事务先生成并验证补丁，再接纳为正式内容。无法安全表达时保留操作前的完整草稿，显示原因；不得先丢弃内容后提示成功。转换异常时仍可复制原草稿或切换源码。

组合输入期间若编辑器产生不能表示的结构，保留完整可见现场，拒绝保存/切换，继续显示未保存；提供包含原 Markdown、当前编辑器模型和保留块原文的恢复副本下载。该副本只用于异常恢复，不替代 Markdown 草稿。等待中的保存请求明确失败，不能错误地拿上一次快照当作本次输入已保存。

## 编辑会话与双模式切换

普通笔记增加共享会话控制层，负责内容版本、编辑器切换、选区映射、撤销重做和输入法状态；服务器保存仍由 Workspace 执行。

```text
                 文档编辑器投影 ── 可验证的文本补丁 ─┐
                                                   ↓
原文读取 → Markdown 会话与草稿 → Workspace 保存/冲突/历史
                                                   ↑
                 CodeMirror 源码 ── 文本补丁 ────────┘
```

- 每个补丁携带 `noteId`、会话代次、基础版本和来源；已切换笔记或过期投影产生的事件直接拒绝。
- 输入法组合输入期间不做来回解析，不切换编辑器；保存/切换意图等组合结束后执行，不能截断中文。
- 切换流程是提交当前编辑事务、检查兼容性、建立目标投影和选区、验证成功后展示目标编辑器；失败时继续留在当前编辑器。
- 光标优先映射到同一源文本位置；语法折叠或保留块只支持映射到最近可编辑块边界，并显式显示当前块，不假装逐字符定位精确。
- 源码变化后，原文单元索引按新版本重建；旧的节点映射不能继续复用。
- 单一撤销历史跨两种编辑方式生效。历史基于可逆 Markdown 补丁和选区书签，不把格式投影或模式切换记成内容修改。普通笔记的快捷键及工具栏接入同一历史；大文件片段继续使用原有历史。
- 历史最多 200 组且补丁/逆补丁文本合计不超过 4 MiB，超出时裁去最旧历史，不改变当前内容；历史不跨刷新持久化。

## 草稿与保存一致性

- 本地草稿继续存 Markdown、原文基准版本、账号/知识库身份；不以第三方编辑器 JSON 替代可恢复正文。
- 模式切换、保存、导航、退出前都经同一个提交入口；草稿存储错误沿用现有可见提示。
- 保存只提交按下保存时的不可变快照。等待响应期间继续输入、切换模式或导航，后续修改仍保持未保存状态。
- 沿用 `expectedModifiedAt`、请求幂等标识、未决请求查询、已提交但响应丢失的核对逻辑。
- 冲突、外部 Git/MCP 修改及服务恢复都保留当前草稿，不自动把服务器内容灌入正在编辑的投影。
- 图片上传的插入位置同时绑定笔记、代次和书签；目标消失或笔记已切换时不插入其他笔记，提供可复制的附件引用。孤立附件继续走现有生命周期。
- 书签可选携带当前文档投影的 ID 和原生选区；投影重建、跨模式或跨版本后失效。源码选区保留方向，实际替换区间使用最小/最大端点，插入后选区定位到新增内容末尾。
- 草稿恢复遇到不适合可视化的内容时，用源码恢复；基准已变化时仍按既有规则只允许复制。

## 资格、性能与异常降级

文档编辑的初始准入条件：服务端声明 `editorMode === 'full'`、Markdown UTF-8 长度不超过 262144 字节、语法单元不超过 5000、嵌套深度不超过 32，以及内容兼容性检查通过。数值是本方案的初始保护上限，性能验证可以降低；提高需要补足验收证据。

大文件、超长行及片段编辑保留现有通道，不把大文件整篇读入文档编辑器。用户已开始的普通笔记编辑因新增内容超过准入条件时，先保留完整草稿，再引导切换源码；不能把已输入内容截断。

文档编辑器与源码编辑器按需加载；阅读和登录不强制下载两套编辑引擎。日常输入只转换受影响单元，不在每个按键后重新解析整篇。

性能验收使用固定合成语料，在记录了设备、浏览器和运行方式的基准上比较：

- 10 KiB 普通笔记从切换到可输入，热加载 p95 不超过 300 ms。
- 200 KiB、包含 100 行 × 10 列标准表格的边界语料，热加载 p95 不超过 1500 ms；达不到时降低文档编辑上限或按结构拒绝。
- 10 KiB 普通笔记的常用输入 p95 处理耗时不超过 50 ms，不出现随输入次数持续增长的整篇转换工作。
- 每种加载场景预热 5 次、采样 30 次；连续输入样本至少 200 个。输入法验证另外进行，不把合成键盘事件当作真实输入法验收。
- 编辑器相关新增首载资源独立记录 gzip 大小；阅读入口不得请求文档编辑器 chunk。体积结果必须写入验收记录。

异常提供原文恢复/复制和源码入口；诊断不包含正文、私有路径或凭据。

## 偏好与兼容

保留 `EditorPreferences.mode: 'edit' | 'preview' | 'split'`，新增 `editorKind: 'document' | 'source'`。`preview` 代表阅读，`split` 只适用于源码。

- 没有历史偏好的账号：`editorKind='document'`、`mode='edit'`。
- 旧偏好存在但没有 `editorKind`：迁移为 `source`，旧 `mode` 原样保留。
- 新偏好中 `editorKind='document'` 且 `mode='split'`：规范化为 `edit`。
- 阅读模式保留上次的 `editorKind`；文档不能可视化时的临时回退不改用户默认偏好。
- 发布期间由 `VITE_DOCUMENT_EDITOR_ENABLED` 控制新能力；初始为 `0`。回退关闭后，`edit`/`split` 使用源码、`preview` 继续阅读，原文及草稿不迁移。

## 安全和可访问性

粘贴、保留块和阅读渲染沿用 HTML 禁用、DOM 清洗、URL 协议白名单和附件授权。Tiptap 能解析 HTML 不代表产品应接受任意 HTML。禁止脚本、事件属性、危险 URL 和会触发外部内容执行的嵌入。

工具栏支持键盘导航、状态播报和选区保留；弹层关闭后恢复焦点。桌面检查 1238×1315 和 1440×900，手机检查 390×844 与 320×568；同时覆盖浅色、深色、减少动态效果及软键盘出现后的可用性。

真实输入法必须记录至少一次 Linux/Windows 中文输入及一次 Android 或 iOS 中文输入验收；自动化只证明组合事件处理逻辑。

## 交付与发布

按技术验证、内容转换基础、完整编辑体验、兼容与可靠性、验收与渐进发布五个里程碑执行，顺序见配套计划。

第一阶段只使用隔离语料。开发预览通过开关启用，用户明确验收后再决定正式发布；计划编写和开发授权本身不等于启停或升级正式服务。

默认启用的必要条件：兼容语料的无编辑往返全部保持原文；局部修改没有影响其他单元；两种编辑方式的保存、草稿、冲突及撤销回归通过；大文件回退可用；真实输入法和性能验收有记录。

任何内容丢失、无操作产生改写、未知语法被吞掉、跨笔记写入或保存误报成功，都阻止默认启用。回退通过关闭功能开关并重新构建前端完成，不批量改写知识库文件。
