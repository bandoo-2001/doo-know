# DooKnow 编辑器整体改进方案

日期：2026-10-23。状态：待评审方案；本文件不表示功能已实现、组件已完整适配或兼容性验收已通过。

## 1. 目标与范围

把 DooKnow 改进为“以 Markdown 文件为中心，站内编辑更顺手，站外仍能阅读”的笔记编辑器。范围覆盖文档与源码编辑、代码块、图形附件、常用编辑操作、相关菜单及 Git 差异展示；保留现有 Vue、Tiptap/ProseMirror、CodeMirror、Mermaid 与 Excalidraw 基础。

用户已经明确的方向：代码块采用 CodeMirror 6；SVG 支持附件查看与源码/图形切换；普通 Markdown 阅读器兼容性是硬约束。其他增强、库选择和批次划分是本方案建议，不冒充用户已经逐项批准。

不包含重写后端、替换原生 Git、增加在线代码执行、多人实时协作或自动升级当前实例。实现、发布和本机安装测试是不同工作阶段。

## 2. 当前基础与真实缺口

- 源码模式已有 CodeMirror；文档模式使用 Tiptap，代码块仍为基础 `pre/code`。两种模式通过 EditorSession 共享 Markdown 与撤销。
- 常见格式、普通图片、链接、任务、基础表格、章节目录、保存恢复、Mermaid 和独立白板已经存在。
- SVG 受上传白名单、服务端附件识别、图片请求 MIME 限制和渲染入口共同限制，不是增加一个按钮即可完成。
- 文档模式缺文内查找替换；纯文本粘贴不会解释成 Markdown；文件粘贴仅取第一个文件，缺专门的外部文件拖放上传。
- H6 可以识别但不能从工具栏创建；缺清除格式、统计及快捷插入等入口。
- 表格已使用成熟引擎，自写部分主要是操作条；普通文档表格与后台数据表格不是同一种控件。
- 部分弹层重复手算位置，Git 差异当前主要作为原始 patch 文本展示。

详情与源码定位见[界面组件与开发预览](../../界面组件与开发预览.md)。既有审核记录和正在进行的主机维护工作不属于本轮修改范围。

## 3. 方案比较与建议

| 路线 | 收益 | 代价 | 本方案判断 |
| --- | --- | --- | --- |
| 在现有引擎上分批增强 | 复用原文保全、恢复和导航；各批可独立验证 | 需要认真处理嵌套编辑器及格式边界 | 推荐 |
| 整体替换为另一套 Markdown/富文本编辑器 | 可能快速获得较多现成功能 | 白板、分享、原文保全、撤销和大文件处理需要重接，回归范围大 | 当前不选 |
| 只补样式和高亮 | 改动小 | 无法解决 SVG、查找替换和粘贴等操作缺口 | 只能作为局部工作 |

依赖优先顺序：复用已有依赖 → 引入职责单一的库 → 确有缺口时才引入新的组件体系。避免同时替换引擎、组件库和保存机制。

## 4. 必须保持的约束

- Markdown 继续作为唯一正文存储格式。
- 通用正文以 CommonMark 为基础；表格、任务列表和删除线属于 GFM 扩展，不承诺所有基础阅读器同样渲染。
- 未编辑的段落、围栏、语言标记、换行与保留块不能因切换模式、主题或预览而改写。
- EditorSession 是正文与撤销的权威；嵌套控件不得产生第二套互不相通的正文或撤销历史。
- 展示增强不触发隐式保存；保存冲突、重试、笔记代次与草稿归属保护必须保留。
- 外部阅读不依赖登录态、站内 API、笔记 UUID 查询或 DooKnow 前端脚本。
- 现有附件上限 10 MiB、Git 差异上限 256 KiB、普通/大文件/元数据模式边界继续生效；不能为接入控件绕过它们。
- 不批量迁移既有笔记，不自动改写已有白板引用，不清理用户设计源文件或真实数据。

## 5. 格式与兼容策略

| 内容 | 保存形式 | DooKnow 内的增强 | 普通阅读器的底线 |
| --- | --- | --- | --- |
| 代码 | 普通围栏代码块及语言名 | CodeMirror 高亮、行号、折行、折叠 | 原码完整显示 |
| 普通图片 | Markdown 图片及相对路径 | 预览、替换、说明编辑 | 附件随文档携带后可显示 |
| SVG | SVG 原附件或 `svg` 围栏；关联 PNG 预览引用 | 代码/图形切换、矢量预览 | 不支持 SVG 渲染时仍可看 PNG，并取回源文 |
| Mermaid | `mermaid` 围栏；按需生成 PNG 预览引用 | 动态渲染、设计转换 | 无插件时图片可读、源文仍在 |
| 白板 | `.excalidraw` 原文件、相对路径源链接、PNG 预览引用 | 完整设计页 | 图片可读，源设计可下载 |
| 颜色、对齐、尺寸偏好 | 优先作为站内显示偏好 | 更好的布局 | 忽略样式后内容仍完整 |

兼容图形的基础写法仍是普通 Markdown，例如：

```markdown
![系统结构](./assets/system-preview.png)

[SVG 源文件](./assets/system.svg)
```

对 SVG/Mermaid 源码块，保留围栏原文；提供标准图片作为静态阅读回退。普通代码块不会因为语言名就被当成可执行页面。PNG 是预览产物，SVG/白板/围栏源码才是可编辑来源，不能只留下截图。

原文保全优先于兼容转换：已有笔记只在用户明确插入、保存该图块或选择生成兼容副本时增加预览引用，不在打开时自动插入图片。新建图形在首次保存前完成兼容预览准备；失败时保留草稿、提供源文下载和明确的“仅保存源码”选择，不伪装为已具备图片回退。

图形源与预览需绑定源内容摘要。保存前先准备预览附件，再按现有正文版本检查提交引用；旧请求不能覆盖新源文。保存冲突不覆盖外部版本，预览失败不覆盖旧预览。白板自身保存成功但父笔记兼容引用仍未保存时，明确区分两者状态，不偷偷保存父笔记。跨文件一致性与失败恢复须在批次 A 形成可验证契约，达标前不开放一键生成兼容图块。

## 6. 开源组件复用

| 范围 | 建议 | 需要保留的应用逻辑 |
| --- | --- | --- |
| 代码块 | CodeMirror 6，复用现有模块，语言按需加载 | 源码映射、中文输入、统一撤销、只读与笔记代次 |
| 浮动工具条 | Floating UI Vue；文字选区菜单可评估 Tiptap BubbleMenu | 选区与目标对象归属、显示时机、操作权限 |
| 基础界面 | 先统一复用 Ant Design Vue，稳定的 Naive 模态框逐项评估 | 未保存草稿、关闭确认、忙碌与任务状态 |
| Git 差异 | diff2html 做只读对照 | Git 执行、授权、读取上限、恢复确认和合并流程 |
| 大列表 | 测得性能瓶颈后再考虑 TanStack Virtual | 树展开状态、分页、键盘与选中笔记 |
| 高度定制交互 | Reka UI 作为备选 | 不为一个菜单新增整套第三组件体系 |

普通 Markdown 不能保存列宽、合并单元格、任意字体等完整页面布局，首批不提供会在保存后丢失的操作。现有表格引擎继续使用，先改善键盘操作、行列移动和可保存的基础能力。

## 7. 分批交付

| 批次 | 交付内容 | 完成标准 | 依赖 |
| --- | --- | --- | --- |
| A：兼容与保存契约 | 外部阅读样本、保全测试、图形源/预览/父笔记保存约定及失败演练 | 不运行 DooKnow 仍可读样本文档和回退图；设计源、预览与笔记状态不混淆 | 无 |
| B：代码块专业编辑 | CodeMirror 内嵌、搜索语言、行号、缩进、括号匹配、复制与折行；折叠按现有模块能力配置 | 中文输入、跨块光标、统一撤销和切换源码均正确；外部看普通围栏 | A |
| C：SVG 与图形兼容 | SVG 附件/围栏受限预览、PNG 回退、现有 Mermaid/白板的兼容引用生成 | 上传、编辑、阅读、分享、复制目录和导入导出均通过；无外链偷偷加载 | A、B |
| D：常用编辑补齐 | 文档查找替换、按 Markdown/纯文本粘贴、多图片队列与拖放、H6、清除格式、基础字数统计 | 不改错笔记、不丢输入、批量失败能逐项重试、撤销合理 | A、B；上传增强复用 C 的附件类型策略 |
| E：界面与差异展示 | 浮动定位统一、基础控件收敛、Git 只读差异高亮与左右对照 | 滚动和小窗口不遮挡操作；Git 原有安全边界与功能通过回归 | A，可在 B/C 之后独立交付 |
| F：知识笔记扩展 | 公式、脚注、提示块、双链、YAML 属性、快捷插入、阅读导出按需要逐项选 | 每项先给出常见语法和外部回退，再单独实现验收 | 主流程稳定后再选，不作为首轮承诺 |

建议先完成 A+B，再交付 C，再做 D；E 可以独立安排。各批形成独立提交和可回退版本，不把所有候选功能堆入一次发布。F 的需求和依赖尚未确认，不在首批实施中预装。

## 8. 关键交互

- 代码块头部收敛为语言选择、复制、折行和展开；更多操作放到菜单。代码区与整体主题一致，手机不强行固定宽度。
- SVG 等图形统一提供预览、源码和源文件入口；图形失败时保留源码与错误原因，不能显示空白并清除内容。
- 查找栏统一入口，范围写明“当前笔记”；文档替换不触碰原文保留块和隐藏源码，想改原文时切到源码模式。大文件只查当前片段时必须标注范围。
- 批量附件展示逐项进度、成功、失败与重试；上传过程中移动光标或切换笔记，不把附件插入后来选中的笔记。目标变化时保留明确的插入入口。
- 常用操作提供键盘入口、可读标签、焦点恢复和深浅主题表现；不重做已验证的侧栏拖拽及设置草稿守卫。

## 9. 验收与发布

1. 原文：LF/CRLF、反引号/波浪线围栏、代码内围栏字符、中文与 emoji、未知语法、引用与列表中的图块，未编辑单元保持原样。
2. 交互：真实中文输入法人工检查；自动化覆盖代码/正文光标、选区、撤销重做、读写模式、关闭与重新打开、快速切换笔记。
3. 附件：SVG 自包含内容、外部资源引用、恶意或损坏输入、超限文件、并发上传、分享撤销、移动重命名和导出重导入。
4. 兼容：独立 CommonMark 与 GFM 渲染器分别验证；另在 VS Code Markdown 预览、GitHub 和一种本地阅读器抽查，记录版本、插件、截图及差异。未实际具备的外部环境记录为未验收，不能用站内截图替代。
5. 资源：语言和图形引擎按需加载；普通笔记打开不创建全部代码块编辑器实例，不把大文件模式退化为一次加载全文。
6. 发布：每批跑受影响测试及必要的类型检查、构建；正式发行走现有制品验证、隔离安装和远端校验流程。发布不自动授权更新当前实例。

## 10. 主要决策与待核实事项

- 已确定：Markdown 正文、普通阅读器兼容、CodeMirror 6 代码块、SVG 两条入口、保留现有保存与草稿保护。
- 本方案建议：渐进增强、PNG 作为最广泛的图形回退、Floating UI 和 diff2html 优先、A–F 分批。
- 实施前核实：SVG 解析/净化方案与允许列表，图形源及预览的一致性恢复，当前附件路径和导入导出可否覆盖新文件组；以 A 批结果作为是否进入 C 的依据。
- 延后决策：需要随文档保存的图片尺寸/列宽格式，以及 F 批各扩展。没有兼容表达和验收依据的能力先不开放编辑按钮。
