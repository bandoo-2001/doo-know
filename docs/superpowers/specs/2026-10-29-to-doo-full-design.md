# To Doo 全量功能设计方案

日期：2026-10-29

状态：全量实现与本地验收已完成，具体结果及已知限制见[验收记录](../../验收记录/2026-10-29-to-doo-full.md)。原第一版讨论保留为历史，不作为当前实施范围。

## 1. 产品定位、授权与默认值

To Doo 是 DooKnow「应用」中的个人任务、时间与行动管理应用。通用任务能力服务学习、工作和生活；知识联动使用户可以带着资料行动，把成果留下，并在下一次任务中再次使用。

### 1.1 用户已经明确的方向

- 需要实现全量功能版本，不只是精简待办或仅交付第一版设计。
- 参考滴答清单的多种呈现方式与完整效率场景，同时体现 DooKnow 的笔记、白板、目标和成果联系。
- 长期用户内容保存于知识库根目录的 _data/apps/to-doo/，采用一实体一文件，随 Git 同步恢复；SQLite 是本机投影和运行状态。
- 用户本轮已明确要求实际实现全量功能，UI 设计图用于具体界面和操作讨论；不以只写设计文档替代产品交付。

### 1.2 本文补足的默认值

单主人、单知识库、自托管 Web、既有 Vue/Fastify/SQLite 技术栈是依据当前项目提出的实现默认。导航分组、默认时区、层级保护上限、重复预览窗口、通知策略、导入规模和统计口径是本方案建议，不伪称用户逐项决定；默认均在相应章节说明。

本方案将全量方向落实为任务、多层子任务、批量、搜索过滤、目标知识联动、成果记录、列表大纲、看板、月周日历、时间线、四象限、专注、习惯、纪念日、统计、可靠提醒、日历交换、数据迁移与 ChatGPT MCP 协作。农历、依赖联动、组合条件深度等是为完整使用场景补足的工程设计，并非用户逐项点名；仍纳入此实施依据，变更时明确记录。

「全量」指本方案所列功能完整可用，包括父子操作、批量、独立重复实例、后台提醒和交换能力。它不等于把其他平台每一个原生系统能力、协作体系、订阅服务或历史兼容格式全部复刻。多用户共享指派、原生 iOS/Android 小组件、付费第三方位置提醒、跨主机实时协同，不作为隐含承诺。

### 1.3 方案取舍

| 方案 | 价值与代价 | 决策依据 |
| --- | --- | --- |
| 继续只做任务、少量视图和在线提醒 | 实现量小，但不能满足本次全量要求 | 用户已明确要求扩大范围，不采用 |
| 知识联动与完整个人效率功能共用同一领域模型 | 保留熟悉操作，同时形成资料、行动、成果闭环；存储与跨实体操作需要平台能力 | 本文推荐，符合用户已明确方向；具体技术细节为设计建议 |
| 另建完整商业效率平台 | 需要账号协作、移动端分发、原生系统集成与运营服务 | 超出本机个人自托管目标，未获授权 |

完整范围可以按依赖顺序实现并分别验收，但下文的任何必备功能不能悄悄降级成「以后再做」。实现计划另行记录批次与进度。

## 3. 信息架构与 UI 行为

DooKnow 全局保留「应用 → To Doo」及账号、笔记、设置入口。To Doo 内侧栏分为：收集箱、今天、近期、日历、目标与清单、四象限、专注、习惯、纪念日、统计复盘；底部是提醒中心和数据/连接设置。侧栏顺序与隐藏项可以保存，用户不必同时显示全部模块。

桌面采用「侧栏 → 当前内容 → 可收起详情」；笔记资料可在详情的资料区打开预览或跳回知识库。月/周/日、看板和时间线可扩展为宽工作区。手机保留同一数据与操作，详情为独立页/底部面板，提供按钮替代拖拽和悬停。

任务详情分为内容、安排与重复、子任务、资料与来源、完成标准与成果、记录；常用字段优先显示，高级选项按需展开。普通任务允许一键勾选，成果不强制填写。

独立地址可以定位清单、保存视图、任务、重复实例、习惯、纪念日、复盘和当前日期区间；刷新、前进后退和从笔记返回均恢复定位。使用稳定 ID 与相对路由，不持久保存部署域名或本机绝对路径。

勾选、拖动与批量是明确提交；详情表单默认显式保存，可配置短延迟自动保存。自动保存须展示「输入中/保存中/已保存/待核对/冲突」，离线只保留本地草稿和明确的待提交操作，不能把本地缓存称为服务器已保存。恢复网络时按预期版本核对，不盲目重放过期拖动。专注计时跨刷新继续；安装成 Web App 不自动代表具备完整离线编辑能力。

本方案的配套 UI 图展示信息架构与主要状态，不是已实现界面。图中样例使用工作、学习、生活混合内容，避免产品视觉上变成考试专用应用。应至少覆盖任务大纲＋资料详情、章节看板、周/月日历、时间线/四象限、专注与习惯入口。

## 4. 任务、树、目标与批量

### 4.1 任务内容与状态

任务定义包含标题、Markdown 说明、优先级、重要程度、标签、预计分钟数、清单/章节/父项、排序、资料与完成标准。状态属于执行实例，为 todo、doing、blocked、done、cancelled、skipped；跳过一期、归档、删除与放弃分开。阻塞原因可填写文本，并可关联前置任务。

普通任务与重复任务统一使用「任务定义＋执行实例」：普通任务有一个实例，重复任务有多个。状态、完成时刻、实例日期和成果不能覆盖整个重复系列的历史。

优先级默认 none/low/normal/high，用于处理顺序；重要程度为 normal/important，用于四象限和目标价值判断，两者不强行等同。标签是独立实体，改名不重写所有任务。

快速创建支持本地规则识别常见中文日期、时间、重复词和标签，提交前突出显示识别结果并允许取消。无法可靠识别的文本保留在标题，不猜测后立即安排；此能力不依赖付费模型。

### 4.2 多层结构与父子操作

树不得成环，任务只能有一个结构父项；默认交互保护上限 8 层，设置可调整，工程硬保护建议 32 层。该上限为可审阅默认，导入更深结构时预览提示并允许用户选择保留为可折叠结构或明确变换，不静默扁平化。

同一结构子树属于同一清单，章节可不同。跨清单移动父项时，整棵子树与相关实例一次移动；移出重复树时提示是否保留为独立系列。复制产生新 ID，资料引用保留，默认不复制已完成实例、运行中的计时和已发提醒。

勾选有未完成子项的父任务时，弹出影响预览，可完成父项及所有未完成后代，或返回继续处理子项；不再禁止父任务完成。默认不自动替用户完成父项，可在清单设置开启「子项全完成后完成父项」。重开子项导致祖先已完成时，同一事务重开受影响祖先，界面说明影响。

子树删除、恢复、归档、取消、重排和跨清单移动均支持；删除写入墓碑，不物理删除。清单删除可以将任务整体转移或一同移入回收站，不能留下隐式悬空关系。用户可以恢复整棵树或选择明确的重挂位置。

### 4.3 批量与依赖

多选支持可见项、筛选结果和整棵子树。批量可改日期、状态、优先级、标签、清单、章节、资料、重复设置，或复制、归档、删除。预览显示选中与连带项数量、哪些字段会改变、重复操作的实例范围及冲突；确认后使用多实体事务，失败不留下半批已改的可见状态。

默认依赖为 finish-to-start，可设置延迟分钟/天；依赖图不得成环。依赖用于提示阻塞和时间冲突；拖动前置项不静默改动后续项。用户可预览「联动调整后续安排」并原子应用，也可保留冲突提示。完整版本不承诺资源平衡优化器或商业项目计划软件的全部依赖类型。

### 4.4 目标与掌握证据

目标清单具有目标日期、成功标准、相关笔记/白板、行动与阶段、进展和成果。目标日期不自动成为所有任务的截止日期。

「系统架构师」可按章节组织行动：看完教材可普通打勾；「独立解释方案取舍」「画出架构图」「完成练习并分析错因」是可选验收项。学习动作完成与掌握状态分开，后者标注为自评/练习验证/资料证据，保留日期与依据，不由完成比例自动推断。

同样机制用于工作项目的设计、代码/测试/交付链接，以及生活中的旅行预算、维修记录和采购对比。普通购物、缴费、预约无须填写验收或成果。

目标进度默认统计有效叶子实例，父项不重复计数；重复行动按所选观察期间内应做/完成实例统计，不能让无限未来周期进入分母。可显示里程碑与成果验收进度，但不合成未经解释的「能力分」。

## 5. 搜索、过滤与视图语义

搜索覆盖任务标题/备注、成果/记录、目标、习惯与纪念日；可限制领域。可视条件包括清单、章节、标签、状态、父子/叶子、重要性、优先级、计划/截止/创建/完成日期、预计/实际投入、重复、资料/成果有无、阻塞/依赖、归档/删除。支持 AND 条件组与有限嵌套 OR，保存为独立视图实体；默认嵌套深度 3、条件 30 项，可由实现基准调整。原查询字符串是显示层，不执行 SQL 或脚本。

内建今天、近期、逾期、未安排、已完成、阻塞、回收站。今天包括当天有计划或截止的未完成实例，同一实例去重；逾期以截止决定；未安排可以有截止但没有时间块。近期默认今天及之后六个日历日，可调整。时间区间与统计按用户选择的显示时区分日，全天日期不随设备时区漂移。

| 模式 | 展示与完整操作 | 不同字段的处理 |
| --- | --- | --- |
| 列表/大纲 | 层级折叠、章节、内联编辑、多选、键盘缩进/提升、排序 | 筛选命中的子项显示祖先上下文，不把未命中的祖先计成结果 |
| 看板 | 按状态、章节、清单、优先级或自定义标签分列；拖动、列内排序、折叠子卡 | 改列只改相应字段；跨清单列移动时采用子树事务；同列排序键独立于大纲排序 |
| 月历 | 全天安排、截止点、时间块摘要、习惯/纪念日及外部事件开关 | 拖动时间块改计划，截止单独拖动；不能混成一个日期 |
| 周/日历 | 小时时间轴、多时间块、未安排区、时区、拖动/拉伸、冲突叠放 | 时间块时长与任务估时独立；一天可给同一任务安排多段 |
| 时间线 | 按日/周/月缩放，按清单/阶段分泳道，任务区间、里程碑、依赖线 | 有多个时间块时展示区段及汇总跨度；无计划项在未安排区；截止是独立标记 |
| 四象限 | 重要/不重要 × 紧急/不紧急，多选和拖动，保留资料入口 | 紧急默认截止在未来 48 小时内或已逾期；阈值可配置，手动覆盖与截止时间分开 |
| 总览/记录 | 目标进展、当前行动、成果、复盘、完成/重开时间线 | 事实记录与当前状态分开；撤销不抹除历史 |

四象限拖动时设置重要性和明确的紧急覆盖，不偷偷改截止。看板/日历/时间线展示的未来重复项可以是预览实例；操作时先稳定物化该实例再提交。不同视图的日期、状态与资料均来自同一模型。

## 6. 日期、时间块、重复系列与例外

### 6.1 时间语义

计划用独立时间块实体保存；任务 estimateMinutes 是预计总投入，时间块 durationMinutes 是本次预留时间，实际专注是另外的事实。三者不互相覆盖。同一实例可跨天安排多段；截止是最晚交付瞬间或全天日期，单独保存。

持久字段区分全天日期、带 IANA 时区的当地日期时间、UTC 事实时刻。默认显示时区建议首次设置时读取设备后由用户确认；换设备不自动改整个数据集。对不存在的夏令时时刻交互要求确认；自动重复默认向缺口后的首个有效时刻顺延，回拨歧义取较早瞬间，并记录采用的策略。导入浮动时间先指定默认时区，不能默默按服务器 UTC 解释。

### 6.2 重复规则与实例

支持每日、每 N 日、每周指定星期、每月日期/第几个星期、每年、工作日（默认仅周一至周五）、完成后 N 天/周/月，以及开始/结束日期、次数上限、排除日期和额外日期。法定节假日必须使用明确的地区日历或用户导入来源；未配置时不把「周一至周五」标成法定工作日。

一个任务是系列定义；一次发生是独立 occurrence 实体，具有自己的状态、原始周期键、覆盖日期、资料、成果和提醒处理。历史与多个未来实例并存，允许完成其中任意一期、提前做、补做、跳过、重开及查询，不再只容许一个当前实例。

实例 ID 根据系列/规则分段 ID 与原始周期键确定，改期不改变原始周期键。并发预览、调度与导入生成同一期时得到同一 ID。规则修改保留已完成历史；本次、此次及以后、全部系列是明确选项，其中「全部」默认只改系列和未完成实例，改写历史需单独选中并预览。

「此次及以后」创建新规则分段，保留系列家族关联与旧分段截止边界；旧未来实例被明确替代/取消，已修改的例外先预览，不能靠清空实例目录处理。例外包含跳过、额外一期、改期、单期字段覆盖与实例取消，均有稳定身份。

固定日历重复默认保留错过实例，不因迟完成自动删除中间周期。用户可显式批量补做或跳过区间。完成后 N 天的规则只在上一期完成后确定下一期；界面不伪造尚无依据的未来精确日期。每月 31 日短月默认月末，下一月仍依原锚点；可改为跳过短月。

### 6.3 重复子树和生成窗口

重复父任务支持子任务模板。默认后代随父系列每期生成，实例保存 parentOccurrenceId，同一期子树可原子完成/重开/跳过。子任务可以有相对父期的安排偏移。给其中子项设置独立周期时，界面明确把它转为独立重复分支，并保留结构/资料关联；独立周期的实例不自动算进每一期父实例的完成条件，避免跨周期误完成。

未来重复由纯规则计算预览，默认查看过去 30 天至未来 90 天；用户操作或调度需要时物化。边界可配置且查询有上限和分页，不无限生成到永久。所有已完成、改动、提醒处理或有成果的实例均持久保留；窗口外未发生且无修改的预览不需要文件。历史错过的数量可按规则计算并分批展开，不静默丢失。

日历与任务列表标明「预览」和已保存实例。批量操作的日期区间明确；规则变更更新 future projection，不反复改写所有历史。

普通任务的单个实例使用稳定 once 周期键。重复系列的「完成」针对选定实例或明确日期区间；「结束系列」是独立动作，不能将无限未来全部记为已完成。删除一个实例、删除系列和跳过一期分别预览，不共用一个含糊的删除行为。

## 7. 笔记、白板、成果与经验复用

资料引用使用 noteId，角色包括 source/material/output/review；可附标题快照与来源选择区间。引用的路径仅作展示，笔记移动/改名后依稳定身份解析。来源保存 quote、sourceHash 和行号提示；现有编辑器没有稳定块 ID，匹配失败时打开整篇并展示原引用，不能跳到可能错误的位置。

从已保存笔记选区、任务列表项、白板或笔记操作菜单创建任务；也允许将未保存草稿文字作为捕获内容保存，但标明来源为草稿快照，保存笔记后再确认定位。初始任务标题、引用和用户后来改写的任务描述分别保留。自动全库扫描勾选框为可选导入入口：先预览哪些会成为任务并识别去重，不默认吞入模板和历史清单。

任务端与笔记中的关联任务卡可以显示实时状态；需要同步普通 Markdown 勾选框时，使用明确绑定 ID 和版本校验，只补丁目标区间。笔记有未保存草稿或基线变化时保留双方，提示待核对；未绑定的普通勾选框仍只是正文。用户可只关联不双向修改。

成果是独立实体，含总结、所对应实例/目标、完成标准检查、相关笔记/白板/附件、验证方式和后续行动。支持快速写一句、关联已有资料、创建成果笔记、从成果建后续任务和整理复盘。

「新建成果笔记并完成任务」允许一条用户流程：先经笔记核心保存与历史机制创建笔记，再经 To Doo 多实体事务完成、关联并记记录。跨笔记与任务存储使用可恢复操作记录，不假装文件系统具有跨子系统事务；中断时明确显示已保存笔记和待完成步骤，重试继续同一操作，不产生第二篇笔记或删除已经保存的用户资料。

任务模板/清单模板可保存结构、说明、完成标准和资料关联，排除实例完成状态、提醒处理和运行中专注。用户可从项目复盘形成下次发布清单，从家庭维修形成维护模板，从错题生成定向复习。模板是独立可迁移实体。

## 8. 专注：番茄与正计时

提供番茄、正计时及自定时长；可关联任务实例、目标或无任务专注。番茄默认 25/5 分钟，4 次后长休息 15 分钟，均可配置；默认到时等待用户开始下一段，可选择自动休息/继续。专注记录区分工作和休息，不把休息计入投入。

支持开始、暂停、继续、结束、放弃、补记、修正区间、备注与关联调整。同一服务默认每主人只能有一个运行专注；在另一设备继续前先接管，并使旧控制端失效。计时依据服务端确认的起止/暂停片段和当前时间，页面只负责显示，后台标签节流不决定时长。

已确认的起止片段、关联、手工修正和结果保存在 session 实体；心跳、控制租约、浏览器音频许可留本机，不每秒写 _data。关闭页面可以继续已开始的计时，但长时间无心跳后回到界面时提示核对，不根据时钟运行宣称用户一直工作。

新机器恢复运行中的 session 时标成「中断待核对」，不会自动恢复计时、播放声音或发送到时推送。原始起点和片段保留，用户决定结束时间或恢复。声音与 Web Push 分别配置，浏览器未授权播放时显示实际状态。

## 9. 习惯与纪念日

### 9.1 习惯

习惯定义保存名称、说明、颜色/图标、目标/资料关联、频率、数量或时长目标、开始/结束、提醒和暂停区间。支持每日、每周指定日、每周 N 次、每月 N 次、数值累计等；一日可多次记录，不以单个布尔值覆盖全部记录。

每次打卡/补记为独立 entry，保存当地日期、实际发生时间、数量/分钟、备注与资料；修改和撤销保留记录。允许补记过往日期，标为补记，不伪造原始录入时刻。提供日历、热力图、周期完成率、连续达标、最长连续和趋势。

跳过/请假/暂停与完成不同，是否打断连续记录由明确设置决定；默认暂停日不计计划分母，手动跳过单列，不充当完成。改规则只影响选定生效日后的计划，历史按当时规则快照计算。习惯打卡可与任务或专注关联，但不能未经选择自动双重计数。

### 9.2 倒数与纪念日

纪念日支持一次日期、每年周年、距离还有/已经天数、分类、封面或资料、提前多个时间点提醒和当天提醒。可选择是否包含当天，界面明确计数规则。

公历默认；农历使用明确的年月日与闰月规则，显示对应公历日期及转换支持范围。历法转换需使用可验证依赖和固定测试，超出支持年份时显示无法计算，不猜日期。2 月 29 日、农历无对应日或闰月缺失的下一次发生，提供明确策略，默认提前提示用户选择，不悄悄错移。

周年通知使用每次发生的稳定周期键，确认当年提醒不关闭以后各年。支持从纪念日生成准备任务或模板，例如续保、家人生日准备；生成记录进入事务与幂等回执，反复点击不重复建一批任务。

## 10. 统计与复盘

按日、周、月和自定义区间查看：任务/实例完成与逾期、目标有效叶子进度、计划时间块与实际专注、习惯达标、标签/清单投入分布、成果和待验证事项。提供数值说明、数据不足和时间区间，图表可以导出图片/CSV，复盘可保存为实体并关联普通笔记。

完成数量按有效实例完成事件计数；撤销与重开保留历史但排除被撤销的完成事实，不能无限勾选刷数量。父项与后代默认不重复计工作量；放弃、跳过和删除单独展示。实际投入优先专注 session，手工投入记录有来源类型，不与同一 session 再次相加。

重复任务按原周期/实际完成时间分别提供「计划达成」与「完成活动」口径；习惯按其本地目标周期计算。改变当前显示时区不篡改历史原日期。复盘保存当时统计口径、范围、数据截止点与用户总结；之后修正原始事实时提示该快照可能过时，可主动刷新。

默认不设惩罚性排行榜、能力评分或强制连续打卡。学习复盘可以展示学过/验证过/待复习；工作与生活显示交付、经验、下次行动，使用同一结构。

## 11. 可靠提醒、站内中心与 Web Push

### 11.1 规则与逻辑提醒

任务实例、习惯与纪念日均支持绝对时刻、相对计划开始/截止/发生日期的多个提醒。默认提供到时、提前 15/30/60 分钟和一天，支持自定义；默认每来源上限 10 条，避免失控请求，用户可调整至经过性能验证的范围。

服务端持久调度独立于页面，维护本地 outbox、领取租约、重试、退避与故障状态。逻辑 reminder event 使用 sourceType + sourceId + occurrenceKey + scheduleRevision + ruleId 产生稳定 ID；标题编辑不变更 scheduleRevision，改日期或提醒规则才使旧队列失效。

到期后先持久写站内提醒事件，再安排外发。站内事件、首次触发检查点、已读/确认/忽略/稍后与用户处理历史是便携内容；队列、设备投递尝试和网络响应留本机。完成、删除、跳过、改期或暂停后取消相应未发送项；发送前再次核对实例与规则。

站内中心支持未读、全部、错过、来源筛选、批量确认、稍后与打开具体实例。已读不等于完成任务，取消外发不删除历史。免打扰保存时区、时间段和紧急例外策略；默认推迟外发并保留站内事件，不把禁用通知解释成已确认。

### 11.2 Web Push 配置与真实状态

完整版本实现 Service Worker、Push 订阅、设备管理、服务端 Web Push 发送与通知点击定位，不仅在线页面弹窗。外发需要安全上下文、浏览器支持、用户主动授权、有效设备订阅、服务端签名配置和到推送服务的网络连接。生产部署用 HTTPS；可信 localhost 开发例外不能作为 HTTP 局域网已可推送的证明。

设置分别显示：未配置 HTTPS/不支持、未请求许可、被拒绝、已订阅、待服务配置、测试已提交推送服务、设备已确认接收（若有回执）、订阅失效、服务异常。不能把「Push 服务接受请求」显示为「用户已看到」。浏览器/操作系统对后台、锁屏、省电和安装条件存在差异，实际以能力探测、设备测试和官方平台要求为准。

默认通知内容只显示「To Doo 有一项提醒」，用户可选择展示标题/描述；设备订阅与端点、加密材料、VAPID 私钥、设备名称及外发主机开关只留本机。设备撤销、退出相关会话后的策略、权限收回与失效端点清理都可操作，不把秘密写进 Git 或诊断输出。

发送使用稳定 event ID 和通知 tag 去重/合并；多个设备可以按选择接收同一提醒，各设备本地去重。崩溃发生在外部接受与本地记账之间仍有重复可能，设计采用可恢复 outbox、稳定标识和短重试窗口降低重复，不承诺跨外部系统 exactly-once。

### 11.3 停机、迁移与接管

默认一个活动提醒主机。重启原实例恢复租约与未完成队列；新主机绑定同步来的数据、完整备份恢复和域名/签名身份变化时，先恢复站内中心，外发保持暂停并要求明确接管和重新配置设备。

接管时展示旧主机记录与最近便携触发检查点，提示关闭旧实例；Git 不是分布式锁，不自动证明旧主机已停。默认把错过提醒汇总为一条摘要，不对几天前的每条逐一补推；可配置仅补发最近 N 分钟未过期提醒或手动选择补发。后台停机期间不可能即时送达，状态需如实显示。

只有用户确认或可验证的处理检查点才能决定跨迁移已处理；本地缓存里缺少发送日志不应导致全量重发。新旧两台机器同时外发无法仅用文件同步保证不重复，此边界在接管界面明确提示。

## 12. 日历交换、导入与导出

### 12.1 ICS 导出与私有订阅

支持按清单、保存视图、选定实例和日期范围导出 ICS。兼容日历显示的默认模式将时间块导出为 VEVENT，截止可单独导出为标明截止的全天/定时项；另提供保留待办语义的 VTODO 导出，明确不同客户端的支持差异，防止一项同时被无说明地导出两次。

UID 稳定绑定数据集、实体与原周期键；处理 UTC/TZID/全天值、持续时间、文本转义、折行、重复与例外。只导出本应用可表达且经过互操作测试的语义；包含复杂例外时可选在明确区间内展开实例，附导出范围说明，不把无限系列展开成巨型文件。

私有订阅源保存用户选定范围、字段和是否带提醒，默认仅标题和安排，不公开备注、资料内容和成果。订阅 URL 使用独立高强度随机令牌，服务端只保存哈希，可撤销/轮换，不能复用登录、MCP 或恢复令牌。连接秘密留本机，换机后重新生成链接；客户端拉取频率由客户端决定，不能承诺秒级同步或双向写回。

### 12.2 ICS 文件导入与外部订阅

上传 ICS 文件可本地完成解析，不要求联网。先预览 VEVENT/VTODO、时区、重复、例外、未知字段、重复匹配和将创建的实体；用户选择导为任务、时间块或独立日历事件。以来源 ID + UID + RECURRENCE-ID 去重，单期改期不误识别成新系列。

外部 ICS 订阅是只读外部日历层，支持显示/隐藏、刷新状态、暂停、断开和将选中事件复制为自己的任务。已获取的用户日程快照为便携实体，断线/换机不会丢失；连接 URL、认证头、ETag 与抓取状态留本机，迁移后显示待重新配置。来源完整且校验成功后才处理远端删除；抓取失败、截断或限额不能清空旧事件。

远程订阅仅接受受控 HTTPS，请求初始及每次重定向都重新检查 scheme、DNS 解析及实际连接目标，阻止私网、环回、链路本地、元数据和其他不可路由地址，防止 DNS 重绑定；重定向不转发不相干站点的凭据。默认 10 MiB、15 秒、3 次重定向，有解压预算与并发上限。自托管私网来源如确有需要须另设明确的管理员白名单，不以普通输入框绕过保护。

不能表达的复杂 RRULE/时区或自定义属性须在预览显示，保留来源字段或原始文件供核对；用户可以选择有界展开为只读事件、人工映射或跳过，不能静默转换成一次任务。To Doo 不把 ICS 当成 CalDAV、会议邀请响应或第三方双向同步协议。

### 12.3 滴答 CSV 与 JSON 全量迁移

滴答 CSV 导入提供字段检测/映射、编码与时区确认、任务树/清单/标签/状态/日期/重复/备注预览、重复导入匹配和逐项警告。适配器使用真实脱敏样例验证，未知列保留在来源元数据，缺失字段不猜测；滴答导出的内容范围受导出格式影响，不承诺从 CSV 恢复原工具未提供的专注/习惯等数据。

导入支持创建新清单、合并到现有清单、跳过重复、保留副本或明确更新。更新已有实体要求列出差异与冲突，默认不覆盖。大批量通过可恢复导入作业执行，按经过验证的事务批次提交，预览说明批次边界和取消后保留哪些已完成批次；不是把百万条导入假称一个不可中断请求。

JSON 全量导出包含版本、数据集 ID、全部内容实体、删除标记、事务/幂等记录、附件清单和内容哈希，可下载为包。排除秘密、登录态、设备推送订阅、本机运行队列与 SQLite；生成一致性检查点，不从未落盘投影拼凑结果。导入先全包校验、预览新建/合并/冲突和缺失引用，再明确执行；不自动替换当前库或启用外发连接。

外部来源的原始数据如用户选择保留，作为独立导入来源/内容哈希资产保存；临时上传材料在成功后按策略清理。导出包中的 JSON 仍一实体一文件，不把全部数据合成难以合并的权威总表。

## 13. ChatGPT MCP 与计划建议

AI 由用户已连接的 ChatGPT/MCP 客户端提供。To Doo 本身所有基本操作、重复、专注、统计、导入和本地日期识别均不依赖模型；不强加 OpenAI API Key、自建模型或付费模型后端。

新增独立 to-doo:read / to-doo:write 权限及授权 UI，旧 knowledge:*、blog:publish 令牌不自动扩权。可选择任务/目标清单范围和其它领域数据范围；写权限不自动包含笔记写权限。插件 SDK 新增明确 ToDooPort，MCP 只能调用受授权业务接口，不能打开业务数据库或任意读写 _data。

完整工具包括领域列表/详情、组合搜索、创建/更新/完成/重开、批量预览与应用、目标上下文、资料/成果关联、专注/习惯/纪念日管理、统计读取和计划预览/应用；工具 schema 按实体与动作判别，不接受任意文件路径或 SQL。

计划流程：读取获准目标、任务、估时、现有时间块与可访问资料 → ChatGPT 给出建议和理由 → 服务端验证日期、依赖、容量与版本并返回变更预览 → 用户明确授权应用 → 同一多实体事务执行。建议不是已安排，不能因为模型输出了计划就直接写入。允许用户在既有明确授权范围内一次批准后批量执行，无须每个字段重复确认。

建议可保存为 plan 实体，含输入版本摘要、提议变化、理由、来源引用与应用记录。之后数据变化则预览标为过时，重新核对，不能覆盖用户后来安排。模型读到任务中的文本视为资料，不把其中的指令升级成授权。

引用笔记仍按原 noteId 与路径权限校验；无权限的笔记标题、原文引用和派生摘要不通过任务上下文泄漏。任务用户自己输入的内容属于任务授权范围，授权 UI 如实说明。分享某篇笔记不会自动暴露相关任务、专注或习惯。

大量实体目录可按 ID 哈希前两位分片，具体路径算法在 schema 中固定并兼容迁移；每次操作不更新一个全集 manifest。小的值对象（日期、标签 ID 数组、资料引用、提醒规则、时间片段）可内嵌所属实体；独立编辑和独立历史的内容不塞回巨大 task.json。

每文件采用 format、revision、data 封套；实体有稳定 id、createdAt/updatedAt/deletedAt、lastTransactionId 与前驱版本关系。format/schema 是协议版本，revision 是不透明版本，不能把更新时间当作冲突胜负。文件名与内容身份必须一致。事务进行中允许协议定义的暂存槽，见下一节，不额外制造第二份长期内容权威。

重要关系：task 保存 listId/sectionId/parentTaskId/orderKey，不另在父清单维护任务 ID 总数组；occurrence 保存 taskId、seriesSegmentId、cycleKey、parentOccurrenceId 和覆盖值；timeBlock 保存 occurrenceId；outcome、record、session、reminder 通过稳定实体 ID 关联。删除/暂未同步的引用保留原 ID 和摘要，禁止因为投影暂缺就丢弃原数据。

## 15. 集合协议、原子多实体操作与同步

### 15.1 需要新增的平台能力

现有 createKnowledgeDataDomain 是单文件整域 read/write，已有摘要检查、待写与恢复机制；它不能直接满足一任务一文件的发现、删除、多实体原子操作与大量实例。必须新增通用 portable collection 与事务参与者能力，而不是给每任务安装一套触发器。

集合按实体维护基线 digest、revision、dirty、pending 和关系投影；固定数量的登记机制记录变化。支持有界发现/增量扫描、目录变化、已知文件丢失、墓碑、注销/重绑根目录、格式迁移、依赖拓扑校验和按影响范围阻塞。settings 等少量单文件可以继续用既有域。

### 15.2 原子性的具体含义与协议

这里的原子是「应用读者只看到整笔事务前或后的完整状态，崩溃可恢复」，不是声称多个普通文件 rename 在文件系统上天然一起发生。Git/备份通过工作区闸门捕获一致性检查点；任意外部工具在任意微秒直接读取文件不在该保证内。

建议协议如下，实施前需用故障注入验证：

1. 在工作区写入许可内取得 To Doo 集合写租约，刷新受影响实体；验证所有 expectedRevision、授权、父子/依赖/日期不变量与请求指纹，分配 transactionId。
2. 本机持久操作意图保存成员与目标内容；逐实体安全写入「当前已提交版本＋本事务暂存目标」封套，含目标 hash、前驱版本和 transactionId。新增实体的旧版本为空；删除也是目标版本的墓碑。
3. 所有成员和相关资产写全并 fsync 后，原子写入并同步 transactions/<transactionId>.json 的提交标记。标记包含成员与版本/hash、requestId/指纹和可重建结果；它是逻辑提交点并随 _data 迁移。
4. 读者按提交标记同时选择成员目标版本；SQLite 在单一事务中切换投影。提交前暂存槽不可见，提交后成员缺失/错 hash 则认定集合不完整，不只应用找到的一半。
5. 幂等回执与活动事件可从提交标记/成员恢复。最后安全折叠实体暂存槽为当前版本，保留事务前后版本谱系；折叠是整理，不改变提交结果。后续版本必须能证明是该成员版本的后继，不能要求每个历史事务永远等于实体当前版本。

成员目标 hash 对规范化的逻辑版本内容计算，不包含会被整理的暂存包装；磁盘文件 digest 另用于并发写入的基线核对，二者不得混用。历史提交标记形成版本谱系，即使实体已更新，也能验证其为事务目标的后继；冲突解决创建带双方前驱的新事务。自动整理不得删除仍被提交闭包/幂等恢复需要的标记。

同一集合串行提交；读请求只读确定的提交代次。标记前中断按本机意图继续或回滚到旧版本，不能把混合状态投影给用户；标记后中断只完成投影与整理，不重放业务动作。新机器只有暂存槽却缺标记时保留材料并标为不完整，不猜测提交；已有提交标记但成员缺失则等待完整同步/人工核对。

请求幂等不是仅靠本机 SQL 队列：提交标记保存 actor 数据集范围、requestId、规范化请求指纹、实体 ID、结果与批量成员；相同请求返回已提交结果，不重复推进重复周期、打卡、计时结束或生成任务。同一 requestId 不同指纹拒绝；未知结果以事务查询确认。秘密和原认证 token 不写回执。

该协议是需要实现和审查的新基础能力，不是对当前代码的既有事实描述。若实施选用其它协议，必须达到同等便携、恢复与逻辑原子保证，并更新设计，不能退化成「循环写文件＋最后更新数据库」。

### 15.3 故障、删除与跨机器

SQLite 内容索引可重建，但删除本机数据库前必须排空或导出尚未提交操作意图；它并非在有待写时可随意删除的缓存。先恢复 library 身份，再恢复 To Doo 事务与实体，再重建关系和调度；新实例不绑定旧 owner 认证 ID。

应用删除为墓碑，支持批量/整树恢复；已知文件直接消失不是删除命令，不从旧 SQL 投影自动补回。永久清理提供影响预览和备份，默认建议墓碑至少保留 180 天；Git 离线副本没有自动全局确认机制，清理前需明确所有副本处理策略，不宣称可以无条件安全合并旧副本。

Git 同步负责文件运输，不提供多主机实时锁或同实体自动合并。不同实体独立改动可合并；同实体冲突保留双方，提供按字段/关系的核对界面与新解决事务，不能按 updatedAt 静默取胜。拉取后先验证事务闭包、版本谱系和树/依赖不变量，再启用受影响区域。

关系暂未同步时保留 ID、源文件和上次可靠快照，显示「关联待恢复」；只阻塞会破坏不变量的操作，不把任务自动移收集箱、不清空资料、不删除打卡。格式损坏或提交成员不完整时隔离受影响实体/事务闭包，其余健康数据可用，跨闭包批量写拒绝并说明。

接入现有 workspace gate，Git 提交/备份前保证无未决集合提交，拉取阻止未保存冲突，拉取后更新投影和提醒。外部原始复制非一致快照时检测不完整；JSON 全量导出应包含检查点完整实体清单与 hash，普通散文件扫描不能证明任意半拷贝完整。

完整备份含 _data 和一致的本机运行/恢复材料；用户 JSON 导出与知识库 Git 不包含设备秘密。恢复副本不自动开启外发推送、私有订阅公开入口或外部抓取，避免两个实例同时对外动作。

## 16. API、权限与接入职责

沿用 Vue 3、Ant Design Vue、Fastify、TypeScript、SQLite 与现有应用框架；扩展博客专属导航类型为支持 To Doo 的判别路由。领域服务挂在 platform runtime，关闭时停止调度/抓取与计时控制租约，不另起未经授权的常驻服务。

Web API 统一 /api/to-doo/，按 lists、sections、tasks、occurrences、time-blocks、outcomes、records、focus、habits、anniversaries、reminders、views、reviews、plans、calendars、imports、exports、transactions、health 分域。读接口分页和区间有界；变更要求 requestId 和所有受影响实体 expectedRevision。批量、计划和导入都有 preview/apply/status/cancel（仅提交前或批次间可取消）契约。

预览返回基准版本、连带实体和变更摘要；apply 重新验证，数据变化返回冲突并保留预览，不把过期预览当授权修改新数据。提交后取消不能假装回滚；撤销创建反向事务，先核对之后是否发生独立变化，不删除历史。

普通 API 继承主人会话、Origin、CSRF、维护模式、知识库 root 身份与路径边界；私有 ICS token 路由单独鉴权，只读选定 feed，无权访问任务 API。分享、普通笔记/附件、知识搜索不能直接读 _data；Markdown 备注安全渲染，无任意 HTML/脚本执行。

服务端 ToDooPort 和 Web/MCP 调用同一领域服务。所有写入使用集合事务与 workspace 协调，提醒和后台作业不绕过为 SQL 直接写。新增 scope 需贯穿授权选择、令牌允许列表、插件 capability、SDK、MCP schema 和运行时复核；请求不能自选 owner、权限或本机文件路径。

远程连接、Push 密钥、ICS bearer 令牌按既有受控本机秘密机制管理；日志和错误只显示可操作状态，不输出凭据、完整订阅 URL 或私有端点。运行位置、端口、数据、恢复和配置前置条件在实施文档记录。

## 17. 规模、可用性与错误体验

建议首个工程基准为 10,000 任务定义、100,000 持久实例/活动、20,000 专注或习惯记录；这是验证目标而非承诺无上限。列表虚拟化、游标分页、日历只查可见窗口、时间线按粒度聚合；常规单项保存与数据集总量无关，不全量扫描或重写历史。导入/重建为有进度的持久作业，重启可继续。

建议输入保护：标题 256 字符，普通备注/记录 64 KiB，单实体 4 MiB，附件 10 MiB；达到限制先提示与可选分拆，不静默截断。可配置导入作业预算，批量交互默认 500 个直接选择实体，连带后代单独展示；超出转后台作业，不能因保护上限取消批量功能。

明确区分空结果、数据仍在加载、离线草稿、连接未配置、权限不足、数据损坏、同步中、同步冲突、已提交但投影恢复中。保存失败保留输入，拖动回到已保存位置并可重试；已提交结果未知用 transactionId 核对，不能让用户猜是否重复点击。

键盘可创建、搜索、切换视图、操作树和多选；颜色之外提供状态文字，拖动提供按钮替代，计时和通知状态可被辅助技术识别。主题与笔记工作区一致，手机不会要求依赖桌面悬停。

实现顺序建议为：集合事务与领域契约 → 基础树/批量/重复/知识联动 → 全部任务视图 → 专注/习惯/纪念日/统计 → 站内与 Web Push → 交换迁移与 MCP → 全量交叉场景验收。可调整并行次序，但完整版本验收前不能删减后面的领域。

## 20. 实施前独立审阅的决策

以下决策细化前文协议，是实现与验收的约束；无需重新确认产品方向。

1. **幂等与版本顺序**：先重新验证当前身份和权限，再查询便携请求回执和规范化指纹；已提交请求返回仍在当前权限内的原结果，未提交请求才执行 expectedRevision 校验。不能用已经变化的版本拒绝成功请求的原样重试。
2. **完成后重复的后继**：周期身份依靠固定序号和前驱实例 ID，完成时刻仅决定安排日期。重开或修正前一期时，未修改的未完成后继可以在明确预览后重算；已经修改、完成或带成果的后继保留，冲突需要明确选择，不能自动删除或生成重复后继。
3. **恢复外发激活**：安装身份与外发激活材料属于本机受控状态。受支持的完整备份恢复流程明确生成新安装身份并清除 To Doo 外发激活、设备订阅可用性、订阅公开入口与抓取启用标记；普通重启保留本机身份。不能仅凭数据库存在推测是重启还是恢复。
4. **统一受控外连**：ICS 抓取和 Push 发送共用实际连接地址校验及固定已验证 DNS 的外连能力，默认只允许公网 HTTPS 443；底层 Push 库不能绕开该连接代理。每次重定向重新校验；ICS 解析器不主动下载 ATTACH、TZURL 或其它嵌入远程资源。
5. **稍后提醒身份**：逻辑 eventId 固定，每次用户稍后操作增加 deliveryGeneration。outbox 以 eventId + deliveryGeneration + deviceId 去重，网络重试沿用原代次，通知 tag 可以继续使用逻辑事件 ID。
6. **有界工作集接口**：面向 UI 的 snapshot/query 接受实体类型、视图、日期窗口、游标与数量限制，返回工作集及明确分页/计数元数据。完整历史分页读取；只有导出或重建作业允许收集完整快照，不能令每次页面刷新下载全部历史。
