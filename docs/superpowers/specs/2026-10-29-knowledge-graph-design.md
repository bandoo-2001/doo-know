# 知识图谱首版设计

## 意图与范围

用户在讨论子应用与隔离开发后，要求先实现知识图谱。本轮按已提出的第一期方向交付可用的笔记引用关系图：从应用页进入，查看 Markdown/Wiki 引用、目录和关键词筛选、孤立笔记、单篇一至两跳关系、节点详情及打开原文。采用独立 worktree 与 `codex/knowledge-graph` 分支，以当前已提交版本为基线，保留原工作区未提交工作。

## 方案选择

1. 每次扫描原文拼图：代码简单，但重复解析、加载成本高，不采用。
2. 宿主内置子应用与 SQLite 派生关系索引：复用现有笔记 ID、权限、链接解析与原文边界；本轮采用。
3. 独立图数据库与 AI 实体抽取：适合后续语义图谱，会增加运行与数据治理成本，本轮不包含。

用户已要求执行，以下细节为实现方的默认选择。无需新增独立服务。首版仅显示当前知识库中真实可读的 Markdown 笔记与显式引用；人工关系、实体提取和语义相似推荐留待后续。

## 数据与更新

新增 `packages/core/graph/`，自行管理幂等 schema，保存来源笔记 ID、路径、文件身份/版本、标题、目标相对路径与抽取状态。复用 `shared/note-links.ts` 的解析，排除代码、图片、外链等非笔记引用；目标路径在查询时解析到活动笔记 ID，使晚创建目标可被识别。路径变化必须触发重解析。缓存可从原文重建，不写入知识库 `_data`，不修改原文。

每次查询在有界的目录记录上增量检查文件身份，仅重新解析变化的文件；异步分批让出事件循环。设置候选、单篇字节、单轮读取和输出节点/边预算，返回跳过、待处理和截断状态；后续刷新继续处理。基础关系不依赖 tokenizer、Python 或向量组件。删除、符号链接、无效 UTF-8、冲突或未完成写入不得继续产生旧边；更新发布前检查来源身份和当前目录位置。

## 权限与接口

`GET /api/graph` 要求主人登录，采用已有知识库读权限；不暴露公开分享入口。本轮不增加 MCP 工具或授权域。核心服务接收 Principal，先过滤授权目录，再读取文件，并对边的两端、统计、未解析关系统一过滤。分享主体拒绝访问。根目录丢失、绑定变化和维护期间沿用宿主错误机制。

独立 `shared/graph-contracts.ts`：查询包括 `folder`、`q`、`focus`、`depth` (1/2)、`mode` (all/orphans)、`limit`；返回节点、边、过滤范围内的总量、截断状态和索引进度。未知/超长输入、越界 limit/depth 和未授权 focus 必须拒绝。图查询及 UI 输出均有界；展示的度数仅反映获准范围。

## 界面与集成

增加按需加载的知识图谱工作区与独立样式：顶部工具栏、可缩放拖动的关系画布、可搜索的笔记列表、节点详情。前端使用 Cytoscape.js，优先显示有限子图；支持适应画布、缩放、点选和局部展开；移动端列表和详情可完整操作，画布不是唯一操作入口。显示加载、空库、无匹配、无引用、解析不完整、失败及重试状态，提供清晰的新增引用指引。

共享应用路由增加 `graph`，支持页面刷新和浏览器前进/后退。首版不改造整个应用注册系统。图谱工作区通过现有 `open-note` 事件进入编辑器，沿用未保存草稿保护。服务通过平台运行时创建/关闭，路由注册保持薄层。

## 验证

核心测试覆盖真实链接解析、延迟目标解析、重复引用、增量修改、删除/恢复/路径变化、权限和统计过滤、符号链接/大文件/无效编码、边界与截断。接口测试覆盖登录、查询参数和错误。前端测试覆盖请求竞态、选择和筛选行为。浏览器测试在桌面与手机验证入口、可操作画布、筛选、详情、打开原文及返回；运行 typecheck、build 和受影响回归。保留隔离的开发数据，不启停正式服务。
