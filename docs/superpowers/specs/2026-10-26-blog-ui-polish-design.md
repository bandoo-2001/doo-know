# 博客页面细节优化

用户要求直接优化现有页面，本轮以刚完成的博客为范围，保留现有应用结构与视觉风格。此前已授权自主处理常规实现选择，无需再次等待设计确认。

选择沿用现有 Vue 工作台与 SSR 公开页，集中改进可读性、状态反馈、键盘及移动端操作。另行引入 UI 框架或重做布局会增加迁移范围，本轮不采用。

工作台：首次选择文章有明确加载／失败／重试状态，保留异步所有权及已核对正文身份；区分无文章和筛选无结果；减少手机端无效留白与小字，集中主要操作，完善危险操作确认的焦点与 Escape；统一中文文案。可以按实际布局折叠封面、置顶、固定链接等次要字段，但不改变字段语义、权限或手动发布流程。

公开页：让现有 system/light 主题设置实际生效；优化文章标题与正文层级、段落、目录、行内代码和表格；长文字不能撑宽手机页面，代码／表格可内部横向滚动；提供清楚的筛选选中、重置、空态出口及键盘焦点和跳过导航入口。不改写已发布快照，不删除正文标题，不扩大公开数据。

验证使用临时账号和隔离数据，覆盖实际桌面／手机与深色页面、首次详情失败重试、筛选重置、确认焦点、公开主题和长内容。纯 CSS 和文案不写镜像测试。新增行为先观察失败再修复；所有实现停稳后统一类型检查、构建、相关单元和编译页面回归，避免运行中修改源码导致缓存混用。

保护原验收记录及卸载功能的 8 个未提交路径；不改正式账号、知识库、运行服务，不发行安装包。

验证中确认一项原有竞态：集合文件监听把临时 EACCES 当成删除，将源笔记置为 inactive，从而触发博客误下架。追加最小修复：只有确认不存在的源才执行删除观察；权限等临时失败保留身份和发布状态。使用真实临时文件／SQLite／HTTP 回归覆盖恢复与实际删除，不通过关闭监听隐藏问题。
