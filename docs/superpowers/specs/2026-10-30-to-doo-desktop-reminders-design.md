# To Doo 桌面提醒与弹出卡片

状态：用户已确认并完成实现与隔离验证（2026-10-30）；尚未部署，真实设备授权与实际送达待使用端确认。

## 目的

用户参考滴答清单的提醒卡片，希望到点能看到事项并稍后提醒或完成，已明确要求关闭网页后仍能收到桌面提醒。

## 方案选择

- 仅在网页中计时弹窗：实现较少，但页面关闭后失效，不满足用户要求。
- 沿用现有 Web Push 与 Service Worker：服务端负责计时和投递，浏览器负责后台系统通知；网页打开时另显示可操作卡片。这是本次建议方案，复用已有设备订阅、通知中心、持久队列、去重与稍后投递代次。
- 单独开发常驻桌面客户端：可以控制独立窗口及退出浏览器后的常驻行为，但增加安装与维护成本，超出本次网页功能范围。

用户确定了后台桌面提醒的使用范围，并确认按本方案实施。Web Push 与以下交互是助手提出并获确认的实现方案。

## 用户体验

- 设置页明确显示当前浏览器的通知权限、当前设备订阅和服务端推送状态，提供启用与发送测试入口。权限只能由用户实际点击授予，不把其他设备已订阅误报为当前设备已就绪。
- 关闭网页后，通过系统通知提示事项；点击通知通过提醒事件 ID 解析对应任务实例、习惯日期或纪念日，相关内容失效时退回通知中心。已有工作区时通过消息触发受草稿离开检查保护的应用内导航，不直接重载正在编辑的页面；没有窗口时再打开网页。系统通知外观遵循操作系统，网页不承诺复刻滴答的独立桌面窗口。
- 网页打开时，在登录后的工作区显示小提醒卡片，切到笔记或其他应用仍有效。显示时间和事项；任务可完成、习惯可按实际目标打卡，纪念日可确认；都可选择稍后提醒。
- 多条提醒合并排队；按提醒 ID 和投递代次避免反复弹出。关闭卡片将本次提醒标为已读，刷新或其他标签页也不再次弹出，但事项仍未完成，并能在通知中心找回。已完成、已忽略或来源/计划已失效的提醒不会继续要求处理；较早但仍有效的漏看提醒保留在通知中心，集中提示而不逐条刷屏。
- 优先保证点击系统通知后可可靠处理；系统通知操作按钮按浏览器能力增强，不把按钮支持作为后台提醒的前提。

## 实现约束

沿用现有 Vue、Ant Design Vue、提醒实体及服务端调度。避免依赖页面定时器发送后台提醒，不新增桌面客户端或全局依赖。完成应调用真正的任务完成或习惯打卡命令，核对实例、日期与版本；有子任务、数量输入或冲突时打开对应界面处理。保护当前所有未提交工作，不启停或发布正式服务，不自动接管真实推送主机或变更用户设备授权。

Web Push 需要安全站点地址、通知授权、有效设备订阅及可访问的推送网络。网页关闭后可由 Service Worker 接收推送；浏览器被系统彻底终止、系统通知关闭或设备关机时不保证即时到达。设置说明应如实解释这些条件。

## 验证

运行现有提醒队列与稍后投递测试；对新增行为验证页面关闭后的 Service Worker 推送显示及点击路由、当前设备状态、前台卡片去重和真实完成/打卡语义。使用隔离测试数据，不修改真实待办。模拟测试与设备实际送达分开报告，真实浏览器授权和桌面送达由用户设备确认。
