# 平台可靠性与日常流程优化

用户已授权按审查优先级自主优化、测试、合并默认分支并发布。沿用当前已隔离的 linked worktree，不修改真实知识库或重启现网服务。

## 目标与约束

- 保留手动保存原文；浏览器自动保存仅作为本地草稿，恢复需明确选择，绝不静默覆盖服务器版本。
- 修复安装配置归属；旧账号仍可登录，新设/重置密码至少 8 字符。
- 提供保持 noteId、历史和分享关联的安全重命名/移动，遵守原有路径边界、版本检查、幂等与恢复机制。
- 对可证明归属的未决写入提供“接受当前磁盘版本并保全现场”的主人处置入口；未知材料、非法路径与 Git 整库冲突只报告，不盲目解除。
- 搜索支持文本/语义/混合模式和目录筛选；能力不足时明确回退/提示，保留命中行用于定位。
- 刷新恢复笔记、浏览器前进后退需经过未保存确认；普通笔记增加轻量章节导航。
- 首次记录按需创建 Inbox；日常可导入 Markdown、下载普通笔记。导入不覆盖、不放宽大小/编码/路径约束。
- 两套 UI 组件的过渡边界保持稳定，入口按页加载；浏览器库不重复安装进生产服务依赖。
- 发布验证绑定源码与制品；不把合成数据/协议测试称为真实用户库或 ChatGPT 客户端验收。

## 验证重点

- 崩溃恢复时服务器版本已变，或保存请求等待期间继续输入：不得覆盖新内容或删除后续草稿。
- 浏览器后退/刷新、搜索命中跳转、移动/导入切换期间的未保存提示与异步过期响应。
- 重命名碰撞、并发外部修改、分享/历史稳定身份、请求重试与进程中断。
- 未决操作处置时磁盘再次变化、非法链接、多文件恢复或无磁盘原件：保全证据并拒绝不确定操作。
- 自定义profile在安装环境消失后仍绑定正确实例；管理指令不能跨实例混用。
- 手机/短窗口与键盘操作，现有插件与MCP协议接口不回归。
- SQLite WAL 的读后写事务必须在开始时取得写入保留锁；新页、缓存页、快照完成和索引快照采用均通过真实双连接竞争回归，并纳入发布验证。
