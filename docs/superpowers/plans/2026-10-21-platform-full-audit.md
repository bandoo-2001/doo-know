# 全平台验收与持续回归计划

目标：按用户授权，保留现有个人资料，在真实卸载、重装和全新私有 Git 知识库上验证完整使用链路；发现问题逐项修复、复测并加入循环监测。有限测试不能证明任意条件下绝无缺陷，覆盖缺口必须保持公开，不能因部分测试通过而关闭整个目标。

## 执行约束

- 现有个人数据库、资料、账户、密钥、插件配置与未提交源码均须保留。只有全新的 QA 仓库和合成资料可作破坏性测试。
- 卸载前新建一致性加密备份并实际恢复到空目录，核对原文和数据库。保留当前及上一版程序制品及服务恢复入口。
- 正式服务保持固定发行版本；开发变更在隔离源码副本完成，经验证后才发布。
- GitHub HTTPS 使用用户名与 PAT；账户密码拒绝属于预期。SSH 使用仓库专用部署密钥及已核实的主机公钥，不关闭主机校验。
- 不输出、提交或写入普通日志任何真实令牌、私钥、账户密码及个人原文。监测不轮询登录接口，不在个人笔记上循环试写。
- 每项缺陷先复现并增加有效回归用例，再修复、复测、记录证据，启动或更新相应循环检查。外部环境异常与产品缺陷分别记录。

## 执行任务与验收

1. 建立覆盖矩阵、问题台账和证据目录；使用 Repo Bridge MCP 创建新的私有 GitHub 知识库并提交合成测试资料。
2. 新建正式资料基线和一致性加密备份；恢复到隔离空目录，验证归档摘要、全部原文字节、SQLite 完整性和业务不变量。失败不得卸载。
3. 在可恢复条件下实际卸载、重新安装正式服务，验证版本、启动方式、账户和既有资料不变；记录停机及恢复时间。
4. 建立独立全新 QA 安装、账户和数据目录，从首次配置开始验证 Git 克隆、HTTPS/SSH 认证、错误凭据、主机校验、提交推送、拉取、冲突、取消、重试、重启恢复、版本变更和回退。
5. 验证所有页面与功能：登录与权限、目录、笔记增删移改、各编辑模式和原文保全、撤销/草稿/保存并发与故障、附件/导入导出、收藏/最近/搜索、分享、回收站、设置、插件、MCP、更新备份恢复与大文件。
6. 在发行源码与实际制品上运行白盒单元/集成、黑盒 API/浏览器和性能/资源测试；覆盖离线、超时、磁盘约束、权限、损坏输入、并发、多端和中断恢复，记录未覆盖平台。
7. 对每个发现执行复现 → 回归用例先失败 → 修复 → 定向与关联全套通过 → 台账打标 → 周期回归。完成整批修复后进行独立整体审查；需发布的修复按既有发布流程验证。
8. 保留安静运行、异常才记录的非重叠周期监测；核对回归清单、运行方式和恢复方法，汇报证据、风险及仍未覆盖项目。

## 共享接口与门禁

- 备份恢复检查通过是实际卸载的硬前置；重装后的基线必须对应同一份合法个人数据。
- Git 合成语料清单是克隆、编辑、推拉和版本恢复检查的共同期望；每次变更须更新明确版本，不能重写个人资料。
- 问题台账是每次修复和周期监测的共同登记处；不得将未验证的问题标为已修复。
- 现有 rc.26 文档编辑发布证据可作为历史证据，不能替代本次完整验收。
