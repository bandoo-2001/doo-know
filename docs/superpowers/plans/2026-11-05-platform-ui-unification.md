# DooKnow 全平台 UI 统一长任务执行计划

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans with the task ledger. User already authorized continuous execution; no repeated phase approval questions. All images must use a verified GPT-Image2 path and pass functional/global review before product implementation.

**Goal:** 将现有非 ToDoo 平台页面和交互统一到已实现 ToDoo 风格，保留功能、权限及数据，完成验证、主分支整合和新版本本地制品。

**Architecture:** 现有源码/真实运行作为功能权威；先维护逐界面清单和模型核验，再完成全部图稿及功能映射/综合审查。之后使用现有技术栈提取共享布局、主题与交互组件并逐模块实施。

**Tech Stack:** 当前 Vue 3、TypeScript、Ant Design Vue、Naive UI、Markdown/文档/图形引擎；无无关升级。

**Spec:** 用户 2026-11-05 授权；`docs/design/platform-unification-2026-11-05/README.md`、各 coverage 清单、源码约束、最终图稿/审查记录。

## Global Constraints

- ToDoo 已完成内部范围保持；共享宿主改造后仍回归验证。
- 未核验精确图像模型不得生图或声称 GPT-Image2；禁止静默替换为未知/不同模型。
- 全部所需图稿完成并逐图、全局审查后才能修改平台产品 UI。
- 真实角色、接口、数据约束和业务行为优先于图稿；不得虚构功能或硬编码示例结果。
- 私有工作区、公开分享、公开博客、认证、打印的导航边界按实际权限区分；不向访客展示私有操作。
- 原用户及其他任务改动不覆盖/重置/清理；开发、测试、打包使用隔离工作区与数据。
- 图稿、提示词、覆盖映射、复核、进度和证据持久化；不向聊天输出大量内嵌图片/base64或日志。
- 最终快进/合并远端实际默认分支，不强推；新版本只打包与隔离验证，不外部正式部署/发布。

## Review Focus

- 所有者构建开关与访客准入不同，不能依据一个开关删去另一个角色的功能。
- 分享共用404、图形原件能力、只读/编辑作用域不能因统一样式而泄露或扩大。
- 草稿/冲突/CAS/长任务恢复、发布快照及手动保存语义保持。
- 外层 overflow=0 不代表窗口可用；要检查控件、窗口边界、焦点和主要动作。
- 固定页头和短/长页底部操作需同时满足，尤其手机表单、画布侧栏与导入预览。
