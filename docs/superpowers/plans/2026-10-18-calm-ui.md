# DooKnow 两栏视觉改版实施计划

> **For agentic workers:** Use parallel independent frontend tasks; preserve all existing business behavior. Steps use checkbox syntax for tracking.

**Goal:** 将用户确认的浅灰白与克制蓝色两栏设计落实到工作区及所有细节页面。

**Architecture:** 保留 Vue、Naive UI、CodeMirror 和原有 API。主工作区仍为目录树与内容区两栏，不增加常驻笔记列表。统一设计变量、Naive UI 主题、表单、弹窗及移动端规则；组件内部样式跟随同一变量。

**Tech Stack:** Vue 3, TypeScript, Naive UI, CodeMirror 6, Playwright。

**Spec:** 本聊天用户已确认的两栏图 [已确认两栏设计](../../design/two-column-ui.png)，以及“细节页面也都有相应美化”的明确执行授权。

## Global Constraints

- 仅改视觉、布局、必要的展示结构和中文提示；不修改服务端、数据库、权限、请求幂等、手动保存及分享语义。
- 1440×900 主界面：约 264px 目录侧栏，右侧编辑区；不加入第三栏。中性浅灰背景与白色正文，品牌色 #4566c6，圆角 6–10px、轻边框、无大面积渐变或厚阴影。
- 原有 Markdown 源码编辑、预览、分屏、大文件分段、历史、冲突、附件、分享、回收站及目录操作继续可用。
- MCP/Git 插件保持实际能力；配置的 JSON 输入与密钥字段语义不变，不自动下载模型或连接外部账号。
- 390px 手机页面可用，无横向溢出；按钮可点击、表单有标签、焦点清晰。保留原有自动化测试依赖的可访问名称。
- 沿用项目已有依赖，不全局安装；不改线上部署，不发布新版本。

## Review Focus

- 长标题、深层目录和中文大段内容不能挤压工具栏或横向撑开页面。
- 编辑未保存、冲突和失效会话必须保留草稿与可恢复路径。
- 窄屏菜单、编辑/预览/分屏和模态框不能遮住核心操作。
- 运行中插件配置、禁用和卸载仍应能找到；服务凭据始终隐藏。
- 首次设置各分支、目录浏览、导入及 OAuth 错误/授权页面均遵循同一视觉系统。
