# DooKnow《资源发布与数据库总体计划书》

2026 年 11 月 25 日 · 设计阶段

## 一、目标与应用边界

本计划设计两个独立的 DooKnow 原生应用。用户既可以把知识库目录发布为网站，也可以直接在知识库中建库管理数据。需要交互的网站可将两者结合，例如公开设备手册，让获授权的成员登记借用。

| 应用 | 用户从哪里开始 | 负责的事情 |
| --- | --- | --- |
| **资源发布** | 发布目录 | 选择知识库目录、自定义访问路径、预览公开范围、启停网站、管理资源检索开关，以及为有需要的网站绑定业务库。 |
| **数据库** | 新建业务库 | 独立建库、建表、管理字段和记录、定义关联、查询、执行事务，并管理调用权限与恢复。 |

业务库属于知识库，以稳定的库 ID 标识。静态网站可以直接发布，独立业务库可以通过管理页面、API 或获授权的 MCP 客户端使用。网站需要数据时，站主选择已有库，或一键创建并绑定专用库。解除绑定只撤销该站点的数据访问，库的归档和删除由「数据库」应用单独管理。

## 二、用户流程与界面

| 入口 | 核心页面和动作 | 用户应当能确认 |
| --- | --- | --- |
| 资源发布 → 发布目录 | 选目录、填路径、预览文件与实际 URL，确认启用 | 哪个目录会公开，后来放入的新文件如何对外可见 |
| 资源发布 → 站点详情 | 查看或停用映射，管理 MCP 检索，创建、选择或解除库绑定 | 网站发布状态、绑定的库，以及站点可以读写哪些数据 |
| 数据库 → 业务库列表 | 独立新建库、打开已有库，查看已绑定的站点 | 在没有网站的情况下也能完成建库和管理 |
| 数据库 → 指定业务库 | 表与记录、字段与关联、联表查询、业务事务及回执 | 当前库名、使用的身份，以及本次查询或写入涉及的表 |

数据操作页始终显示完整位置，例如「数据库 › 设备库 › 联表查询」。选表器仅显示当前库授权范围内的表。现有交互原型用设备和活动两个场景验证过建表、联表和事务回执。原型采用了早期的站点入口，下一轮界面验收要覆盖两个应用的独立入口，尤其是直接进入一个尚未绑定网站的业务库。

## 三、资源发布

- **实时映射。** 允许选择当前知识库的普通子目录。启用前预览公开范围。网站每次请求读取当前文件，浏览器可重新校验缓存。保存文件、Git 拉取或恢复文件后，稳定链接指向新的工作区内容。知识库换绑或源目录本身被替换时，暂停该映射，待站主核对新目标。
- **访问路径。** 使用独立的资源域名。以 `pub.example.com/manual` 为例，访问目录时跳转到 `/manual/` 并返回 `index.html`。保留子目录结构，`./config.js` 和 `./assets/logo.png` 按原相对路径加载。PDF、图片等文件可单独打开，缺失文件返回 404。
- **公开边界。** 资源入口只读取启用目录中的普通文件。隐藏文件、`.git`、`_doo-data`、越界路径及指向其他位置的链接排除在公开范围之外。管理登录使用独立入口。带登录态及私有数据的交互站点使用各自独立的浏览器来源和站点会话。
- **MCP 检索。** 每个映射默认关闭 MCP 检索，开启后仍按连接授权。通用 `search` / `fetch` 可搜索 HTML 正文、Markdown 和纯文本，JS、CSS、图片等静态资源可按文件名和路径查找。结果可定位到公开页面。索引随文件变更增量更新，检索及读取都核对映射状态、文件版本和权限。

## 四、数据库、API 与事务

**库与表。** 每个业务库拥有独立的数据目录和本机 SQLite 查询库。同名表可出现在不同库中。表定义包含稳定字段标识、显示名、类型、必填或默认值，以及关联目标。首版建议支持文本、数字、布尔、日期时间、枚举、JSON 和关联记录。显示名可直接修改，字段类型变化通过带版本的迁移校验已有记录。

**长期数据。** 建议使用以下知识库内布局。库名、表名和网站路径可以独立于持久 ID。

```text
_doo-data/apps/databases/<库ID>/
├── manifest.json
├── tables/<表ID>/
│   ├── schema.json
│   └── records/<记录ID>.json
└── transactions/<事务ID>.json
```

事务文件持久记录已提交的数据变更，记录文件保存当前状态。本机运行数据区为每个业务库建立单独的 SQLite 文件，可由便携数据重建。一个库内部可以共用记录表，用表 ID 区分用户创建的逻辑表。常用查询按实际的关联字段、过滤条件和排序建立索引。

| 调用能力 | 请求内容 | 服务端行为 |
| --- | --- | --- |
| 读取表定义 | 库、表 | 返回有权看到的字段、类型、关联和可用操作 |
| 查询记录 | 主表、返回字段、筛选、排序、分页、要展开的关联 | 按定义生成参数化查询，联接本库表，对参与的每张表和每行应用权限 |
| 提交变更 | 单条增删改，或一个业务动作的整组变更，附带请求 ID 和必要的预期版本 | 校验身份、数据类型、引用与业务前置条件，返回提交回执或明确的冲突 |

首版 API 建议用结构化 JSON 表达查询条件、关联和变更。平台处理权限、类型校验、事务与回执，具体应用定义借用条件、名额计算或评分规则。

例如，设备借用单通过稳定 ID 关联设备与成员。页面一次查询就能显示设备名、借用人和到期日。提交「借出设备」时，服务端在同一库的写入锁内检查设备仍可借、引用存在、操作者有权修改两张表。随后将设备状态变更和新增借用单一起原子写入一份事务文件，以此为持久提交点。全部变更在同一个 SQLite 事务中应用，业务 API 才对外显示新状态。

同一请求 ID 携带相同内容重试时复用原回执，携带不同内容时报告冲突。中断后按已提交事务恢复查询库及当前记录文件。Git 拉取或人工导入的数据须作为完整变更核对，遇到缺失前序版本、分叉或不完整事务，保留最后验证通过的状态和冲突材料。

## 五、绑定、权限和资料恢复

- **绑定是显式授权。** 首版建议每个站点同时最多绑定一个库。站主可一键创建专用库。复用已有库时，逐站限定表、读写动作及记录范围。发布文件、读取业务记录、写入业务记录分别授权。
- **各类调用者共用一套业务校验。** 站主可以独立管理库。交互网站默认个人使用，需要多人时由站主按站点邀请成员。网站访问使用本站会话，API 和 MCP 使用各自的授权身份。记录归属和服务器生成的字段由服务端确定。MCP 的库查询和写入使用独立授权，内容搜索只索引明确开放的资源。
- **Git 与备份。** 站点源文件和表结构可随知识库 Git 管理。含个人或成员信息的库，默认从 Git 排除记录与含相同内容的事务日志、附件，并纳入私有加密备份。需要随私有仓库迁移时按库选择，核对已有跟踪文件。密码验证材料、会话、邀请凭据保存在本机私有运行区。
- **恢复。** 备份取得同一写入边界下的数据与配置。新实例恢复后先重建并核对查询库，再由站主启用映射和外部绑定、重新授权连接。网站停用、成员撤销或连接权限变化后，旧链接与读取凭据按各自的新状态重新校验。

## 六、后续实施顺序

以下为未来开发里程碑。当前交付到总体计划书，正式开发、真实数据迁移和上线另行安排。

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| 1. 双入口与用户流程 | 资源发布、数据库两张应用卡，以及独立建库、发布及绑定界面 | 从任一入口都能独立完成核心任务。从网站一键建库后能清楚看到授权范围 |
| 2. 目录实时发布 | 安全目录读取、只读资源入口、公开路径与本地代理示例 | 用含相对引用的站点完成首次发布、直接修改文件、停用和异常路径验证 |
| 3. 独立业务库 | JSON 便携格式、每库查询文件、建表与记录管理、事务提交与重建 | 在空知识库独立建库。中断后重试不产生重复记录，重建后的查询结果一致 |
| 4. 联表与业务操作 | 关联字段、查询 API、跨表事务、并发控制与回执 | 设备借出、活动报名两个场景都能验证权限、并发冲突和完整提交 |
| 5. 网站绑定与 MCP | 绑定授权、个人及受邀成员、资源检索、结构化数据访问、学习站示例 | 三种使用方式均可运行。撤权立即作用于后续读取或写入，并完成备份恢复演练 |

## 七、整体验收

| 场景 | 通过标准 |
| --- | --- |
| 静态手册 | 只建映射即可访问首页、脚本、图片与 PDF。修改文件后刷新可见，停用后停止公开访问。 |
| 独立台账 | 没有网站也能创建库、建表、读写记录和联表查询。两个库使用相同表名时，字段、成员、索引和回执各自独立。 |
| 跨表并发与恢复 | 两人同时借一台设备只产生一笔有效借用。分别在事务文件落盘前后模拟中断，恢复后设备状态与借用单一致。 |
| 学习站 | 提供可放进知识库的示例网站。登录者可跨设备查看自己的答卷，受邀者各自查看个人记录。每份答卷关联当时的题目和评分版本，后续改题仍可解释历史成绩。 |
| 授权与检索 | 公开文件可按映射访问，私有记录须独立授权。关闭资源检索、解除库绑定或撤销成员后，旧结果和重复请求不能越过当前权限。 |
| 可迁移性 | 在新位置从便携数据重建，核对记录数、版本、典型联表结果及事务回执。Git 同步范围与加密备份范围可分别检查。 |

可复用项目中已有的便携数据、事务回放与授权机制。相关依据见 [To Doo 数据与 Git 约定](../../ToDoo使用与数据.md)、[事务落盘与回放实现](../../../packages/core/to-doo/store.ts) 和 [MCP 功能与权限](../../MCP完整功能与权限.md)。
