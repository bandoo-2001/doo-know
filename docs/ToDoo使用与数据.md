# To Doo 使用与数据

To Doo 位于「应用 → To Doo」。它将个人任务、日程、专注、习惯和重要日期放在同一个工作区，并与知识库中的笔记、白板和成果关联。

本页说明使用方式；本次实现、验证范围和部署状态见[全量功能验收记录](验收记录/2026-10-29-to-doo-full.md)。

## 从一个任务开始

- 可以直接在收集箱创建任务，也可以先建立工作、学习或生活清单。目标清单可以补充目标日期、成功标准和相关资料。
- 任务说明、日期、资料和完成标准在详情中编辑后保存。勾选、拖动和批量操作是单次提交；失败时保留输入，结果未知时先重试原操作核对。
- 计划时间表示准备什么时候做，截止时间表示最晚什么时候完成，两者分别保存。一项任务可以安排多段时间；预计投入与实际专注也分别统计。
- 子任务可以折叠、调整层级和整树操作。批量处理重复事项时选择当前一期、日期区间或明确实例范围，先核对连带项。
- 重复任务的定义与每一期执行记录分开，可以改某一期、从某期以后修改，或结束/取消重复。完成一项不会把未来所有周期视为已完成。

新建表单、未保存详情和未确认请求都有对应保护；内部切换模式保留草稿。跨应用、关闭详情或离开页面时，应按提示处理输入。浏览器草稿不等同于服务端已经保存的内容。

## 展示模式

| 模式 | 适合做什么 |
| --- | --- |
| 目标总览 | 查看目标进展、今天的行动、相关资料和成果 |
| 列表/大纲 | 分章节拆解、多层子任务、搜索、组合过滤和批量操作 |
| 看板 | 按状态、清单、章节、优先级或标签分列推进 |
| 日历 | 按周/月安排时间块，区分计划、截止和外部日历 |
| 时间线 | 查看任务区段、阶段节点和前后安排 |
| 四象限 | 按重要与紧急程度整理行动，保持截止日期独立 |
| 统计与记录 | 回顾完成、投入、习惯与成果，并保存复盘 |

各模式使用同一份数据。较多任务、实例或历史记录按各自集合分页；看到「继续载入」时可以读取后续内容，而不是把首批结果当作全集。

可以保存筛选视图，使用可视化 AND/OR 条件组组合日期、标签、状态、目标等条件。依赖中的延迟单独编辑；联动调整后续安排必须先预览，再明确应用。

## 让资料和行动相连

在笔记「更多操作 → 创建关联任务」中，可以将选中文字作为任务初稿；没有选区时创建整篇资料的跟进事项。未保存的笔记仍由使用者决定何时保存，任务保留来源引用和草稿标记。

关联使用稳定笔记 ID。应用内移动或改名后仍可找到来源；资料暂缺、被删除或没有访问权限时显示相应状态，不删除任务。

成果可以直接记录在任务中，也可以关联已有笔记。选择创建成果笔记时，可以同时完成任务；已有未完成子项需要先处理，或取消同时完成。流程保留可恢复的操作记录：

1. 保存待处理意图。
2. 使用知识库原有写入机制创建笔记。
3. 在同一任务事务中关联成果并按选择完成实例。

中断后保留已经保存的笔记。可在应用的待继续成果操作中核对原内容、目标版本和操作，再继续；重试原操作不会新建第二篇笔记。笔记后来发生变化时先核对，不覆盖后续编辑。

如果来源笔记还有未保存草稿，打开另一篇成果笔记时会出现原有的保存/放弃/取消选择。捕获任务不会代替这个数据保护步骤。

任务可以上传专属附件，默认上限 10 MiB，支持经过校验的图片、PDF 和纯文本。下载要求当前主人登录且附件属于该任务。解除关联不立即删除文件字节，以保全恢复和历史引用。

## 专注、习惯与纪念日

- 专注提供番茄与正计时，支持暂停、继续、结束、备注和时间修正。计时依据服务端确认的片段，页面刷新不会简单归零。迁移或恢复中的运行记录需要核对，不自动算作一直在工作。
- 习惯支持次数或数值、补记、跳过和暂停。目标或周期调整有生效日期，旧周期按当时规则计算；按周/月累计与每日打卡分别展示。旧数据缺少历史规则时明确标记估算。
- 纪念日支持公历、农历、周年和倒数/正数；闰日或闰月的处理策略可核对。超出历法支持范围时不猜测日期。

首次使用建议在设置中确认时区、周起始日、专注节奏和提醒偏好。

## 提醒与设备

服务端负责产生站内提醒，支持确认、忽略、稍后和错过汇总。稍后提醒使用新的投递代次，不会被第一次已投递记录吞掉。

Web Push 需要安全访问地址、浏览器支持、设备授权、有效订阅和服务端网络条件。设置页显示实际配置状态，设备测试区分「请求已提交推送服务」与设备是否真正显示。相关平台条件见 [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API) 和 [WebKit 的 iOS/iPadOS 说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。

默认由一个活动主机负责外发。恢复副本和新主机先恢复站内内容，外发连接保持未激活，之后在设备设置中接管。Git 同步本身不提供跨主机发送锁。

## 导入、导出和日历

- JSON 用于应用全量迁移，包含内容实体、版本、事务回执和附件校验，排除登录、设备密钥、订阅和本机队列。
- CSV/ICS 先预览字段、日期、重复与匹配结果。可以跳过、创建副本，或对稳定匹配的已有项目明确更新；更新会核对版本，不凭相似标题猜测覆盖。
- CSV 支持选择解码和列映射。某种原工具未导出的信息无法凭空恢复；未知字段和不能表达的规则在预览中说明。
- 较大导入使用有进度的批次作业，可以停止和继续。停止后已经提交的批次仍保留，不能把整个作业假装回滚。
- ICS 可导出为日历事件或待办，也可创建独立、可撤销的私有订阅。外部订阅是只读日历层，断线不会清空上次可靠快照。
- 私有订阅链接、认证头和远程连接留在本机；换机后重新配置。远程抓取仅允许经过校验的公网 HTTPS，默认不连接本机或私网服务。

当前导入预算为 JSON 64 MiB，CSV/ICS 10 MiB。外部重复展开使用有界日期窗口；非 IANA 自定义时区等不能可靠表达的内容会明确拒绝或提示，不静默转换成一次事项。

## `_data` 与 Git

以下是所绑定知识库中的位置，不是程序源码目录：

```text
知识库/
├── 原有笔记与附件/
└── _data/
    ├── manifest.json
    ├── library/state.json
    └── apps/to-doo/
        ├── manifest.json
        ├── settings.json
        ├── lists/<id>.json
        ├── tasks/<id>.json
        ├── occurrences/<id>.json
        ├── time-blocks/<id>.json
        ├── outcomes/<id>.json
        ├── focus-sessions/<id>.json
        ├── habits/<id>.json
        ├── habit-entries/<id>.json
        ├── anniversaries/<id>.json
        ├── reminder-events/<id>.json
        ├── operations/<id>.json
        ├── transactions/<id>.json
        └── assets/<sha256>
```

标签、章节、视图、模板、复盘、日历快照和进展也按实体分别保存。任务身份不随标题变化；SQLite 用于本机查询与运行，便携文件是长期内容的依据。

先完成保存并核对待写状态，再通过知识库原有 Git 流程提交、推送或拉取。仓库不要忽略 `_data`。程序不会因保存任务自动提交或推送 Git，也不需要提交运行中的 SQLite/WAL。

换机器时同步整个知识库、附件和 `_data`，再绑定目录，程序会恢复稳定身份与本机投影。JSON 完整导出与独立加密备份也可用于迁移；Git 历史不代替完整备份。

同实体冲突、损坏文件或不完整同步会要求核对，保留双方材料，不按时间戳自动覆盖。当前保守处理可能暂停整个 To Doo；原有笔记和博客与该错误隔离。不要删除 `_data` 或强制清空数据库来消除提示，目录内有不能仅凭笔记原文重建的数据。

## ChatGPT / MCP

使用更新后的 MCP 服务插件，显式开启 To Doo，并为客户端单独授予 `to-doo:read` / `to-doo:write`。旧知识库授权不会自动扩展。可在插件设置中选择清单和内容类别；资料原文仍受独立知识库读取权限限制。

查询与长文本都有有界读取和版本信息。较大批次返回精简回执和准确总数，可用原请求身份继续分页核对完整的获准变更，不能因返回摘要就重新创建。工具发现采用标准分页，客户端需要继续读取 `nextCursor`。计划建议先预览，再由使用者授权应用；过期计划必须重新核对，不能静默覆盖新安排。

基本功能不依赖模型 API Key。ChatGPT 通过工具读取获准上下文、提出安排和执行授权操作，To Doo 本身不伪造模型建议。
