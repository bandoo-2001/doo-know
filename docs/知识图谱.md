# 知识图谱

从工作区的“应用 → 知识图谱”进入。图谱展示当前知识库中 Markdown 笔记的显式引用，原文仍保存在原有目录，不会为生成图谱改写内容。

## 建立关系

同目录的两篇笔记可以这样关联：

```markdown
# 知识管理

定期整理资料，参见 [每周回顾](每周回顾.md)。
也可以使用 [[每周回顾]] 或 [[每周回顾|回顾方法]]。
```

Wiki 引用采用相对路径约定，不会仅凭标题在整个知识库中猜测目标。代码示例、图片链接、外部网址和自引用不构成笔记关系。多次引用同一笔记仅显示一条有向连线；箭头指向被引用的笔记。

## 浏览与筛选

- 搜索标题或相对路径，英文字母忽略大小写；选择目录及其子目录。
- 通过图谱节点或下方笔记列表选择笔记，查看引用、被引用和原文入口。列表支持键盘操作，手机也可直接使用。
- “查看 1 跳关系”显示与所选笔记直接相连的笔记；“查看 2 跳关系”再展开一层，连线仍保留引用方向。
- “仅显示孤立笔记”查找当前筛选范围内没有引用连接的笔记。目录或关键词筛选会改变这个范围。
- 使用放大、缩小和适应画布调整视野；“列表”视图适合逐项浏览。
- 打开原文沿用现有编辑器与草稿保护。浏览器返回、刷新可以重新进入图谱应用；首版筛选条件不写入页面地址。

## 更新与完整性

进入或刷新图谱时，服务增量检查文件，只重新解析变化的内容。外部新增文件先由知识库现有目录发现流程登记，再进入图谱；也可返回笔记刷新目录后重新进入。移动、改名、删除与恢复沿用现有笔记身份和引用维护规则。

首次处理大库会分批进行。每批最多处理 128 篇来源及 4 MiB 内容，界面一次刷新最多继续三批；提示仍有待处理笔记时，可继续刷新。单篇来源最多 256 KiB、最多 512 个不同笔记引用。超过上限、编码无效、正在写入或存在冲突的来源会跳过并显示不完整状态；修复后刷新可以重新纳入。

默认显示最多 300 个节点，可通过 API 将上限调整到 1000；画布最多返回 5000 条边。候选验证也有数量上限，截断时会提示缩小范围。图中的总量和度数仅反映当前获准且已验证的范围，不能用部分结果判断整个知识库没有关系。

首版支持 Markdown 笔记及其显式链接。白板内容、附件、人工关系、AI 实体提取和语义相似关系尚未纳入。

## 数据与访问

关系缓存保存在当前实例的 SQLite 派生表中，可由原文重建，不产生需要单独携带的知识库用户数据。用户无须安装插件或准备本地向量模型。

查询使用分批验证的有界快照。查询期间经应用保存的笔记若版本变化，会撤回旧结果并重新计算；查询完成后的外部文件修改在下一次刷新时反映。图谱不会尝试锁住任意外部编辑器。

`GET /api/graph` 需要主人登录，没有公开分享入口。核心查询还会按知识库读权限过滤节点、边和统计，隐藏内容不会通过关联数量暴露。接口支持 `folder`、`q`、`focus`、`depth=1|2`、`mode=all|orphans` 和 `limit=1..1000`。

## 隔离开发

本功能在独立 worktree 与 `codex/knowledge-graph` 分支实现。每个并行开发实例分别设置 `DOOKNOW_DEMO_ROOT`、`PORT`、`VITE_PORT`、`APP_ORIGIN`；已有显式原文、数据和密钥路径时也必须分别配置，避免沿用另一个实例的数据。需要同时登录多个同主机实例时使用独立浏览器配置。

开发入口仍为 `npm run dev`，依赖沿用项目锁文件。知识图谱不新增常驻服务，不改变正式部署的数据位置。浏览器验收可通过 `DOOKNOW_E2E_WEB_PORT` 和 `DOOKNOW_E2E_API_PORT` 指定独立端口，默认仍为 4179/4180；知识图谱用例会跟随测试来源地址。其他历史用例如果写死了来源地址，仍需串行运行或另行适配。
