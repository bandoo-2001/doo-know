# Git 远程知识库指南

Git 插件同时提供本地版本管理和手动远端同步，支持 GitHub、Gitee。知识库文件位于运行 DooKnow 的服务器上；浏览器所在电脑无需安装 Git。服务器需已有 Git ≥ 2.39，使用 SSH 时还需 OpenSSH 工具。

## 从云端开始

1. 在 GitHub 或 Gitee 准备已有知识库仓库，复制 HTTPS 克隆地址。
2. 初始设置选择“从 Git 远端导入”，填写地址、服务器保存位置和新的目录名称。分支留空时使用远端默认分支。
3. 公开仓库可先匿名读取；私有仓库填写对应主机的访问凭据。点击测试连接，再开始导入。
4. 平台下载并启用 Git 插件，将仓库克隆到新目录，绑定为知识库。插件下载与仓库访问是两套授权：下载官方插件不需要 GitHub 令牌。

导入不会覆盖已有目录，即使目录为空也需换一个新名称。当前导入暂存上限为 1 GiB、100,000 个目录项，并要求至少 512 MiB 可用空间；超出时可先在服务器手动克隆，再使用本地目录。新克隆拒绝符号链接和子模块。Git LFS 大文件的自动拉取不在本版范围内。

## 现有本地知识库连接云端

在“设置 → 知识库与存储”或 Git 插件设置中打开远端管理，填写仓库地址、分支和凭据，测试并关联。选择此流程会按需安装、启用 Git 插件；仅使用本地目录不会自动安装。

目录已有 Git 仓库时沿用提交历史，可选择识别到的远端。没有仓库时可以初始化。原有远端不会被静默覆盖；远端已有与本地无关的历史时，平台不会强推或自动合并。新建云端仓库用于上传现有资料时，选择空仓库，避免同时生成另一套 README 等初始提交。

## 凭据怎么填

优先使用 HTTPS，地址中只放仓库路径，不放账号密码或令牌。

- **GitHub：**在账号设置创建限定目标仓库的 fine-grained token。读取使用 Contents: read，推送需要 Contents: write；组织策略、分支保护仍可能限制操作。参见 [GitHub 官方令牌指南](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
- **Gitee：**在账号设置创建私人令牌，并给予目标仓库所需的读取或推送权限。账号密码与访问令牌应分开；启用双因素认证后，HTTP Git 操作使用私人令牌。参见 [Gitee 官方认证说明](https://help.gitee.com/account/two-factor-authentication)。
- **SSH 高级选项：**上传用于对应仓库的私钥，填写私钥口令（如有），读取服务器指纹后与 [GitHub 官方指纹](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints) 或 [Gitee 官方指纹](https://help.gitee.com/account/gitees-ssh-key-fingerprints) 核对，明确确认信任后保存。指纹变化会停止连接，需重新核实。

记住凭据时，平台在服务器端按账号、主机加密保存；不回显原始密钥，也不写入仓库配置、任务记录或浏览器存储。不勾选记住时只在本次服务进程中保留 30 分钟，重启或过期后需重新填写。删除凭据后，再次同步需要重新关联可用凭据。

测试连接只能证明能够读取仓库；实际推送成功后才显示已验证推送权限。云端已包含同一提交时不会为了测试权限重复推送。

## 日常同步

| 操作 | 作用 |
| --- | --- |
| 提交全部变更 | 预览并生成本地提交，不上传 |
| 检查云端 | 更新云端状态，查看两端领先、落后情况，不更改知识库文件 |
| 提交并推送 | 预览文件变化，确认生成本地提交，再将该提交推送到关联分支 |
| 仅推送 | 上传已经生成的本地提交，不再生成提交 |
| 拉取更新 | 将云端可直接前进的提交应用到知识库，并刷新索引 |
| 断开关联 | 停止平台管理这条同步连接；保留文件、本地历史和原有 Git 远端 |

平台保存笔记不会自动创建 Git 提交或推送。只有知识库中的文件变更进入 Git，数据库、登录账号、插件凭据和索引不属于知识库版本；请通过忽略规则排除依赖、缓存和私人文件。Git 同步不能替代完整加密备份。

有未保存草稿时先保存或处理草稿，再提交或拉取；有未提交文件时先提交，再拉取。两端分叉、分支保护或仓库规则导致失败时，页面保留本地提交并说明后续处理方向。平台不提供强推、整库重置或自动解冲突。

## 中断后如何继续

- 推送超时或断网后先核对同一任务；使用“仅推送”或任务重试继续已有提交，不要反复生成提交。
- 页面离开不会取消后台任务。服务重启后显示待核对状态；明确重试前先查看当前仓库状态。
- 更换知识库目录、远端、分支或凭据后，旧任务不能继续作用于新的目标，应重新检查连接。
- 克隆在发布或绑定时中断，可重试原任务；平台只恢复经过目录身份核对的同一份克隆，不覆盖已有目录。
- 历史恢复遇到大文件限制时，沿用页面中的大小及手动恢复提示；不会绕过既有保护。

本版不包含定时同步、自动推送、云端创建仓库、OAuth 登录代码托管平台、子模块或 Git LFS 管理。令牌需由用户在代码托管平台创建，平台内可保存、替换或删除。
