# 真实数据迁移与发布准备

本页说明源码验收后的操作边界。真实知识库迁移、生产部署及服务重启需要另行安排；本任务仅在临时知识库、测试资料和独立浏览器环境验证。

## 迁移前

1. 使用现有完整备份流程生成一致性备份，核对原文、assets、SQLite 状态、历史、回收站、迁移和文件操作材料。不要把复制正在写入的 SQLite 文件当作唯一备份。
2. 将备份恢复到独立目录和独立测试实例，核对稳定 UUID、附件、历史、ToDoo 关联、收藏及分享状态。原文与派生索引分别保留，索引可重建。
3. 在桌面端“知识库设置 → 旧白板迁移”逐项预检。处理同名目标、缺失资源、摘要冲突、未知场景版本和未完成写入；保留原件，不通过普通改名把 JSON 变成 Markdown。
4. 迁移窗口内先保存或关闭旧编辑会话。迁移后旧会话收到版本冲突时重新打开，不能继续提交旧 JSON。匹配迁移证据的本地旧场景草稿可在新白板中明确选择恢复，转换先写入新版本地草稿，随后生成预览并保存。

## 提交与核对

- 专用迁移界面会固定最终源，收集本篇及关联图形的 PNG，再切换同一 UUID 的主文件。出现“待准备预览”时继续原任务，不能修改摘要后复用旧 PNG。
- 迁移后检查正文和说明、原生节点链接、刷新重开、历史恢复、原 UUID/旧路径引用、ToDoo 关联及分享能力。抽样导出完整资源包，换目录并在不连接应用的普通 Markdown 环境中核对正文和图片，再整包回导到测试目录。
- 新文档已有编辑时，迁移回滚会保留两版并报告冲突。不要覆盖新文档来强制回滚。缺少原始路径、身份、固定摘要或可信日志的旧历史会明确拒绝推断，仍应保留原始备份供人工核对。
- 共享附件可能继续保留在原位置的资源目录中，供当前副本、历史或回收站使用。移动与撤销只接受已登记的固定资源；用户后来新增的文件会引起冲突。首版没有历史附件自动清理功能，不能把只剩 assets 的目录当成垃圾删除。
- 外部 PNG 中若携带可恢复的 Excalidraw 原场景元数据，不能当作公开预览。应从单独的图形源重新生成预览；所有者原始文件下载仍保留原字节。分享原件开关不赋予编辑权限。

## 完整资源包及调用方

当前预算为单媒体 128 MiB、便携包 256 MiB、最多 10,000 个文件，便携核心暂存 512 MiB。MCP 传输存储另有独立额度，不能将这两个存储域的总量描述成仅 512 MiB。

官方归档上传会在文件流之前提供目标目录及 requestId，直接流入受跟踪的输入快照；目录整体上传使用同一核心。自定义 HTTP 调用方应遵循该提前提供上下文的协议。旧式“先文件、后所有字段”小包兼容保留，但在没有提前上下文时需要有界暂存，不能据此承诺大包仍可在剩余额度不足时完成。

MCP 收到 `DIAGRAM_PREVIEW_REQUIRED` 后，先分页读取本人固定需求，再有界读取源、上传对应用途的 PNG、完成准备，以原 requestId 重试交付或继续原整理任务。不得借用其他主体、其他用途或其他版本的上传句柄。临时材料到期、授权失效及外部篡改均有明确失败状态；不要删除仍被合法重试引用的资源来绕过配额。

## 发布准备

- 固定源码、依赖锁文件与发布范围。原工作区存在用户已有未提交工作，任务兼容快照 `5cd82ce` 不能整体当作本功能提交发布。
- 源码单元测试、类型检查、构建和浏览器验证通过后，再按现有正式发布流程生成平台发行物、核对 notices、备份及回滚材料。缺少历史发行物导致的环境跳过项需要在发行构建环境补证，不能记作已通过。
- 按项目现有方式发布明确版本，分别记录源码版本、运行路径、数据位置及恢复方法。不要让开发目录的变动自动替换常驻服务，也不要在未安排真实迁移窗口时重启服务。
