# Local portable delivery protocol

The owner endpoint `POST /api/portable-deliveries` accepts a stable `requestId` and one selection:

```json
{"selection":{"kind":"single","noteId":"<uuid>"},"requestId":"<stable-id>"}
```

`multiple` accepts `noteIds`; `directory` accepts a knowledge-relative `path` (empty means the library). A single document with no file/document dependencies returns Markdown. Explicit multiple/directory selections always return an archive, including a one-document directory. Existing raw document download and legacy administrative/MCP bundle endpoints retain their contracts.

The result contains `id`, `kind` (`markdown` or `archive`), `fileName`, `mime`, `sizeBytes`, `sha256`, and `downloadUrl`; archives also contain `manifestVersion: 1`. Download the returned filename and MIME from `GET /api/portable-deliveries/:id/download`. Owner-session, Origin and CSRF protection apply. Receipts bind the calling principal/client; they expire after 24 hours. Reusing a request ID with a different selection fails.

Local Markdown navigation follows independently authorized document dependencies, with bounded cycle handling. Parsed links, reference definitions, images and wiki links are rewritten using original source ranges; code examples are preserved. Wiki navigation and legacy whiteboard embeds become standard Markdown. Documents retain their logical hierarchy; byte-identical attachments share a content-addressed package `assets/` path. Legacy `.excalidraw` documents become Markdown wrappers plus native source and a verified prepared PNG. Export never updates knowledge files.

Application-owned `/?note=<uuid>` navigation on the configured origin, including root/query-relative forms, resolves the current independently authorized note and becomes an ordinary relative document link with its fragment preserved. Other websites' `note` query parameters remain external hyperlinks. An own-origin autolink without a safe destination source range is rejected explicitly; it cannot become a false dependency-free Markdown delivery. Native scene links to application note URLs require the same relocation/preview plan as other native local navigation.

Primary diagrams require a ready semantic resource with matching source/render/PNG versions. Download creation and later chunks recheck the fixed document and asset closure. Missing local dependencies fail with `PORTABLE_DEPENDENCY_UNAVAILABLE` and authorized source/resource diagnostics; changed inputs fail with `PORTABLE_VERSION_CONFLICT`. Incomplete packages are not returned as successful Markdown downloads.

An archive contains `dooknow-portable.json`:

```json
{"format":"dooknow-portable","version":1,"files":[{"path":"00-Inbox/note.md","kind":"document","sizeBytes":8,"sha256":"<sha256>"}],"selected":["00-Inbox/note.md"]}
```

The owner can upload the **whole archive including this manifest** to `POST /api/portable-deliveries/import` as multipart fields `archive`, `folderPath`, and `requestId`. Results contain an import `id`, `notes` (`sourcePath`, new `relativePath`, new `noteId`) and asset count. The browser's complete-directory picker sends the extracted manifest and all files to `POST /api/portable-deliveries/import-directory`. Files stream into private staging using package-relative multipart field names, then enter the same `importDirectory` validation and mutation core; no HTTP endpoint accepts machine-local filesystem paths. Target collisions fail rather than overwriting existing notes. Completed/recovered requests retain their new identities. Each imported primary receives a genuine preparation for its validated copied immutable source/PNG paths, preserving the native source base, source bytes, unknown machine fields and ordinary prose.

For bounded owner archive uploads, send `folderPath` and `requestId` before the archive file, or provide both as URL query parameters (the browser does both). File-first multipart bodies are supported with this early validated context. If the same fields also occur in the body, they must match exactly. Legacy file-first requests without early context retain their spool-based compatibility path for small uploads; that path can require additional staging and is not the full-budget upload protocol. Complete-directory uploads likewise put target metadata before files. No client supplies a filesystem staging path.

Archive bytes stream directly into a private tracked input snapshot. Each entry stages in a hidden sibling directory on its actual target filesystem, including nested mount targets, and is invisible to normal note scans. After the entire manifest, source types, hashes and render bindings pass preflight, validated assets are exclusively promoted into their immutable destination without a second asset-sized copy. Staged-byte accounting decreases only after the private source entry is removed. Empty directories created only for rejected input are reclaimed, and location metadata lets expiry/restart cleanup find all private shards. Existing retained export receipts are neither evicted nor consumed.

Import verifies manifest version, exact file membership and SHA-256 before note creation; absolute/escaping paths, symlinks, hardlinks, duplicate entries and case/Unicode aliases are rejected. Export/import use shared limits: 256 MiB package, 10,000 files, 1,000 documents, existing per-file limits and 512 MiB tracked staging. Capture/validation are bounded local work; compression and download run outside the workspace lock. Archives/uploads are streamed and resources are staged individually; no archive-sized Buffer or Base64 result is returned. Import progress is durable and can resume using the same input/request ID; it is not a cross-filesystem atomic batch transaction.

Portable import accepts an ordinary Markdown file up to the export's 20 MiB document bound through an internal manifest-import mutation capability. The existing public ordinary-create API retains its 1 MiB bound. The internal capability still uses the normal path authorization, write intent, filesystem publication and recovery gates. Rewritten path segments escape Markdown-sensitive parentheses and preserve literal percent names, so inline/reference links and generated legacy document links survive offline parsing and reimport.

Media assets support structurally validated MP4/WebM video and MP3/WAV audio, with the shared 128 MiB media bound (existing picture/PDF/native limits stay in effect). Uploads and media snapshots/imports use bounded streams; owner and saved-reference public media downloads support single HTTP byte ranges and recheck the current session/share policy and file version per chunk. The internal asset API exposes `inspect`, `inspectById`, `publicInspect` and `open` descriptors; media never goes through the old bounded `file`/Buffer interface.

Parsed HTML `img`, `video`, `audio` and `source` resources include `src`, `srcset` and video `poster`; Markdown/code source ranges remain distinct. Audio/video originals get standard Markdown file links alongside embeds. App-owned asset URLs resolve through the asset registry. Remote embedded resources are localized outside the workspace lock, using a 30-second deadline, at most three redirects, public-address validation and DNS pinning on every hop, and fresh requests without forwarded credentials. Ordinary external hyperlinks remain external, including external HTTP(S) URLs whose path begins `/api`, `mailto:` and `tel:` navigation. The same passive navigation is preserved byte-for-byte inside native scenes and never fetched as a dependency. Only the application's own API and identity navigation uses private resource resolution; unsafe/unknown protocols remain rejected. Typed `data:` media is decoded in bounded chunks and validated as an ordinary asset. A `blob:` source returns `PORTABLE_REQUIRES_PERSISTENCE`; the owner export UI offers to persist browser-owned media, update and save the links, then retry. Expired browser URLs require selecting the file again.

Cancellation, unavailable resources and permission changes abort preparation and reclaim staging. Export callbacks can refresh the principal during acquisition, copies, compression and publication. Import callbacks refresh it for each asset stream/publication, each document publication and the completion receipt; already committed identities retain the existing retry journal.

The MCP tools `export_portable_documents`, `begin_portable_import_upload`, `import_portable_archive` and `get_portable_import_result` use the same core planner and whole-manifest import. MCP uploads/downloads retain bounded transfer chunks; large import identity maps are paged using a cursor, with request-ID recovery after interruption.

Unchanged native relative scene links preserve the package tree and keep their validated source/PNG pair. Changed UUID/API links, renamed legacy targets and relocated source bases use a fixed private portable plan and newly matching browser preview, surfaced through structured `DIAGRAM_PREVIEW_REQUIRED` needs. Native dependency discovery includes nested scene attachments and allocates stable per-document final paths before fixing any source. Shared live sources remain unchanged. Primary Markdown diagrams additionally require a retained version or live preparation proving the complete source/render/preview tuple and resource paths.

Bound inline SVG, Mermaid and Excalidraw v1 groups require a durable source/PNG preparation for strict export. Whole-package import validates their source type, fence/binding hashes, exact source reference and actual PNG digest before issuing a preparation for the imported immutable pair. Unchanged imported groups can be exported again without rendering. Bound Excalidraw snapshots use a package-relative source-file fence and matching code hash; live UUID references are checked against the current independently authorized board source before capture. Unbound legacy references retain their existing conversion behavior. Consumed preparation receipts resolve registered asset IDs and current note identities after moves/restores, so they do not replay stale physical paths or stale main-document content.

Owner jobs are persisted separately from legacy transfer tasks. `GET /api/portable-jobs` and `GET /api/portable-jobs/:id` expose running, completed, failed, cancelled and interrupted receipts, including committed partial import identities. `POST /api/portable-jobs/:id/cancel` cancels active work cooperatively; each imported document yields after releasing its mutation gate. Completed core import receipts recover a lost owner HTTP response. `POST /api/portable-jobs/:id/retry` retries an export using its real original request ID. Imports require reselecting the original whole archive/directory with the same request ID and destination; temporary upload bytes are reclaimed after success or failure, and the UI never advertises source-free resume. Retry verifies the whole manifest again and preserves already committed identities. A partial import remains unresolved until its core completion receipt is durable.
