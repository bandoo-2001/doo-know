# 应用导航组件

DooKnow 使用共享主菜单承载默认工作区与应用功能。菜单渲染与业务导航分开，应用可以注入自己的条目、当前选中项和底部设置入口。

## 手机与平板

手机和平板竖屏显示底部常驻 tabbar，平板横屏和桌面显示左侧 60px 竖栏。底栏显示前四个主入口与“更多”；更多面板提供完整主菜单、工具以及账户或返回入口。当当前页面位于更多面板时，第五项显示对应名称和选中状态。点击遮罩、关闭按钮或 Escape 收起面板，旋转屏幕切换布局时也会收起。

`WorkspaceFooter` 是工作区的直属组件，独立于笔记/设置目录的折叠侧栏。应用内不再显示外层主菜单折叠按钮；任务清单、日历视图等二级目录仍使用各自的目录入口。默认笔记工作区保留目录按钮。

底栏高度同时用于任务详情、功能目录和任务弹层的底部边界，保存操作保持在底栏上方。高度不超过 500px 的手机短窗口使用左右分屏，避免上下分屏的标题挤掉正文空间。

响应式规则覆盖宽度不超过 720px 的窗口、宽度不超过 960px 且高度不超过 500px 的手机横屏、宽度不超过 1100px 的竖屏，以及宽度不超过 1366px 的粗指针竖屏设备。规则分别位于 `WorkspaceMainMenu.vue` 与 `workspace-tabbar.css`，两处需保持一致。`--workspace-bottom-inset` 包含底栏和底部安全区高度，正文与浮动提醒据此预留空间。回归见 `tests/e2e/responsive-tabbar.spec.ts`。

## 接入方式

工作区根组件通过 `provideWorkspaceMainMenu()` 创建菜单宿主。应用组件在 setup 中使用 `useWorkspaceMainMenu()`，定义可由 computed 随当前路由更新：

```ts
import { computed, ref } from 'vue';
import { useWorkspaceMainMenu } from '../workspace-main-menu';

const section = ref('overview');
const hostedNavigation = useWorkspaceMainMenu(
  computed(() => ({
    id: 'my-app',
    label: '我的应用',
    icon: 'apps',
    activeId: section.value,
    items: [
      { id: 'overview', label: '概览', icon: 'apps' },
      { id: 'items', label: '内容', icon: 'file' },
    ],
    utilities: [{ id: 'settings', label: '应用设置', icon: 'settings' }],
    onSelect(id) {
      section.value = id;
    },
  })),
);
```

`hostedNavigation` 表示是否找到宿主。应用可据此隐藏自己的一级菜单；独立预览时继续保留完整导航。真实应用应在 `onSelect` 中使用自己的受保护导航回调，在离开未保存表单前确认；菜单组件自身不会直接修改路由、保存或丢弃数据。

菜单条目支持 `id/label/icon/title/badge/disabled/separated`。图标名称沿用 `Icon.vue`；单独使用 `WorkspaceMainMenu.vue` 时，还可通过 `identity` 与 `icon` slot 自定义展示。`identity` 接收 `compact` 和 `close`，返回入口先调用 `close()` 再请求受保护导航；组件的 `close` 事件用于同步收起账户等嵌套弹层。应用品牌应在始终可见的页头展示，不能仅放在会隐藏的目录中。

## 生命周期与作用域

- 注入随组件作用域释放，退出应用后恢复默认 DooKnow 菜单和账户入口。
- 嵌套应用面板可再次注入菜单，覆盖父级定义。父级更新不抢占子级；子级卸载恢复最新父级定义，不会清掉其他所有者的菜单。
- 返回入口由宿主处理，先核对应用草稿，再恢复进入应用前的笔记、收藏或其他 DooKnow 页面；账户入口在默认工作区恢复。
- 应用通过 `utilities` 声明自己的设置入口，避免指向 DooKnow 全局设置。菜单定义和应用位置记忆位于当前账号的工作区生命周期内，不写入知识库业务数据。
- 当前扩展点属于前端 Vue 应用。接入新应用仍需在现有应用注册与路由中接入，不改变服务端插件协议。

## To Doo 的目录规则

| 页面                                         | 二级目录                      |
| -------------------------------------------- | ----------------------------- |
| 任务、看板、目标总览                         | 智能范围、目标入口、个人清单  |
| 日历、时间线                                 | 日期、今天、周/月视图、时间线 |
| 四象限、专注、习惯、纪念日、复盘、通知、设置 | 隐藏目录，主体铺满            |

专注页自身的统计区、任务详情侧面板属于内容布局，不属于二级导航。`hostedNavigation=false` 时 To Doo 保留独立模式导航。

相关实现为 `workspace-main-menu.ts`、`components/WorkspaceMainMenu.vue`、`WorkspaceFooter.vue`、`AppsWorkspace.vue`。返回和位置记忆由 `Workspace.vue` 管理，菜单行为可通过 `workspace-main-menu.test.ts`、`app-main-menu.spec.ts` 及导航回归验证。

## 知识图谱与未保存表单

知识图谱通过同一宿主显示知识图谱、笔记图谱、关系审核、后台分析、图谱问答和视图与导出，底部工具为图谱自己的模型设置。独立预览保留原工具栏；在工作区内收起重复的审核和更多操作入口。选择移动端主菜单条目会关闭侧栏，不额外写入浏览器历史。

应用通过 `hasUnsavedChanges(): boolean` 和 `requestLeave(): Promise<boolean>` 接入 `AppsWorkspace` 的当前应用转发。模型设置修改或请求执行期间，图谱报告未保存状态；模型弹层的关闭确认同时用于外层导航，取消保留原 URL 和输入，确认放弃后才允许离开。已有待决确认期间的后续请求与忙碌状态均拒绝离开，卸载结清未完成的确认。工作区刷新或关闭时也检查当前应用的未保存状态，交给浏览器提醒。

图谱菜单与浏览器后退回归位于 `graph-hosted-navigation.spec.ts`；弹层取消、放弃、忙碌、重复请求与卸载行为位于 `graph-overlay.test.ts`。
