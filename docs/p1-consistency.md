# 第一批写入、删除与恢复一致性

本次仅涉及 W01、W02、W03。实现和验证记录见知识库 `10-Projects/DooKnow-MCP/审查修复验收记录.md`；后续批次及发布另行授权。

## 保存回执

Web 保存返回 `receipt`，其版本、哈希和大小来自持久化操作结果。成功提交后的可选全文读取不能把成功改写为 HTTP 失败。长行跨越 32 KiB 时返回对应元信息，页面切换到大文件工作区；缩短后切回普通编辑器时重新读取正文。

可选当前读取失败时响应保留成功回执，并带 `currentReadError`。此时附带的正文或模式来自该次提交内容；当前磁盘可能被其他编辑来源改变，应重新打开核对。回执与当前文档是两个概念。W04 的跨后续写入重试展示问题仍属于后续批次，不能据本批回执字段宣称已验收 W04。

## 删除请求

`DELETE /api/notes/:id` 必须携带页面读到的 `expectedModifiedAt` 和客户端 `requestId`。省略版本不再采用服务器最新版本。旧版本拒绝不会撤销分享；成功归档会撤销分享。

结果未知时保留原参数，用 `/api/operations?requestId=…` 核对；服务端未收到时可重发同一请求。再次点击确认不会接受尚未读取的更新版本。

## 回收站恢复

`POST /api/notes/:id/restore` 接收稳定的 `requestId` 与可选 `fileName`。页面在响应丢失后使用原参数重试；更改文件名属于新的请求。操作结果也可用通用 operations 接口核对。

恢复在文件变更前写入 `operations` / `write_intents`：原 noteId、源和目标、原版本、目标内容哈希与发布 inode 证据。正文哈希沿用 64 KiB I/O 块，校验读取期间的文件身份和版本，避免整文件缓冲。私有暂存副本独立于公开目标，fsync 后用排他发布文件创建目标，不覆盖已有目标。提交前检查数据库路径占用；在立即事务内移除回收站原件、更新原 noteId、保持历史和私有分享状态、登记索引任务与成功回执。只有提交后才清理私有副本。

启动时先重放未决意图，再进行扫描。普通扫描和索引 reconcile 都保留未决/冲突恢复路径，不分配第二个 noteId。部分复制可从原件重建；目标消失可从私有副本重放。目标外部变化时保留目标、原件或副本，操作进入 `needs_reconciliation`，不擅自覆盖外部修改；若回收站原件已移除，则尽量从私有副本补回，使列表仍指向原文。

出现 `needs_reconciliation` 时先保留所有文件、操作标识与数据库，不应手工删除意图或把冲突副本当缓存清理。当前没有新增管理员冲突处置或永久删除能力。

## 验证边界

故障用例只在临时目录、数据库与测试子进程中执行，覆盖登记、复制、发布、数据库更新、原件移除和提交后的进程退出，另有部分复制、占位、外部删除/修改、分享隔离与索引重启回归。这些是进程中断与竞争操作测试，不是真实断电、磁盘损坏或全规模并发压测。
